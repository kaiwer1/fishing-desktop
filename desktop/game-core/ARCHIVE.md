# 已关闭日志的只读检查与独立备份

2026-10-28。`FloatJournalArchive` 补充 P1 的有界检查/备份能力。它只读取明确指定的已关闭日志，并把验证过的同一份字节快照复制到明确的新路径；不恢复、修复、迁移、激活或自动选择存档，不搜索个人存档。

## 只读检查

`FloatJournalArchive.Inspect(sourcePath)` 返回不可变 `FloatJournalInspection`。公开元数据包括规范化来源路径、字节长度、整文件 SHA-256、末帧 SHA-256、事务序号、profile/branch 身份，以及是否存在活跃会话或满护 pending 结果。完整游戏状态仅供同程序集内部核对，不是页面协议；原始字节只保留在私有复制缓冲区。

检查以 `FileAccess.Read / FileShare.Read` 打开来源：支持文件本身带只读属性；拒绝已经存在的写者，并在读取、冻结副本和验证期间阻止新的写入及删除。最大来源仍为现有日志上限 16 MiB，超过上限在复制前拒绝。路径缺失、目录、空文件、不支持的格式、坏哈希、截断、尾部垃圾和语义不合法的事务都失败，不创建替代档案或裁剪坏尾。

`FloatGameStore.ReadValidatedJournal(Stream)` 是从原存储读取逻辑抽出的唯一重放检查器。正常 `OpenExisting` 和只读检查共用相同的帧、散列、序号、codec、reducer 和事务语义验证，没有第二份放宽规则的归档解析器。它只重建状态，不执行 owner 生命周期操作。

尤其不能用 `GameOwner.OpenExisting` 替代这项检查：owner 启动会明确收束普通未完竿，而归档检查必须原样保留普通活跃会话及已确认满护 pending 鱼。检查不增加恢复事件、不退饵、不加钱、不发鱼、不改变来源字节。

读取句柄关闭后，检查结果仍保存独立冻结副本。此后来源被合法继续写入、移动或删除，已经取得的检查结果不会跟着变化。

## 新路径备份

`FloatJournalArchive.Backup(inspection, destinationPath)` 只接受已验证的检查对象，备份该次捕获的快照。它**不重新打开来源取得“最新状态”**，也不把来源变化默默拼到原检查结果上。

执行顺序为：

1. 检查明确目的路径，拒绝与来源规范化路径相同的地址，Windows 大小写差异不会绕过此判断。
2. 以 `CreateNew / ReadWrite / FileShare.None / WriteThrough` 创建新文件。已有目的路径一律拒绝，包括完全相同的有效备份、空文件和坏文件；不使用“先判断存在再覆盖”的路径。
3. 写入冻结字节并执行 `Flush(true)`。全过程持有同一个独占句柄。
4. 在该句柄上回到开头，逐字节比较并计算整文件哈希，再调用同一个日志重放检查器。长度、整文件哈希、末帧哈希、序号和 profile/branch 都必须与检查对象一致。
5. 关闭句柄之后才返回 `FloatJournalBackup`，表示本次写入与核验已成功。返回元数据不构成恢复或激活该文件的命令。

服务不自动创建目录、不覆盖原档、不创建新的玩家身份、不重放出手动画，也不重新结算历史交易。既有来源数据和备份目录仍由调用者明确选择。

## 失败与保留

开始创建目的文件后的写入、flush 边界或核验失败抛出 `FloatJournalBackupUnconfirmedException`，携带目的路径。已经产生的零字节文件、部分文件或完整但未确认文件全部保留；不自动删除、覆盖、截断修复或作为当前存档使用。

失败后再次向相同路径备份仍会被 `CreateNew` 拒绝。可以明确检查留下的文件；即使检查发现它完整，也只说明该文件可验证，不会自动替换任何来源或活动分支。选择另一新路径需是明确的新备份动作。

源文件读取失败同样不做清理或修复；只关闭本次句柄。保存来源的 byte-for-byte 证据优先于把一个失败结果伪装成成功。

## 当前证据

命令行入口 `journal-tool.ps1` 只接受明确的来源，以及备份时明确的新目的文件；工具先在仓库外指定目录构建，不修改游戏配置或启动游戏。示例路径应替换为自己选定的已关闭候选日志和已存在的私有目录：

```powershell
./desktop/game-core/journal-tool.ps1 -Action inspect -SourcePath '<已关闭候选日志>' -OutputDirectory '<仓库外私有构建目录>'
./desktop/game-core/journal-tool.ps1 -Action backup -SourcePath '<已关闭候选日志>' -DestinationPath '<已存在目录中的新文件名>' -OutputDirectory '<仓库外私有构建目录>'
```

成功输出仅为长度、散列、身份/序号、是否有活动/pending会话等JSON元数据，不导出原始业务内容。备份输出的 `backupConfirmed=true` 仅在上述完整检查成功后出现；错误返回非零退出码和未确认说明，已创建目的文件仍保留。主代理另以本轮20笔事务的私有游戏测试档执行命令行检查/备份，原档散列不变、备份逐字节一致、重复目的路径拒绝；未读取个人存档。

`test-archive.ps1` 只在仓库外新建的私有夹具目录运行，不读取个人数据。系统 C# 编译器按警告视为错误编译，28 项通过，涵盖：

- 零资源、普通活跃竿及满护 pending 的原样检查，无 owner 自动恢复或初始化。
- 来源只读句柄、已有写者拒绝、捕获期间禁止新写者/删除、只读属性及句柄释放。
- 来源捕获后的变化不影响冻结副本，复制字节不能修改快照，来源移动后仍备份原捕获内容。
- 缺失、超长、截断、篡改、尾垃圾和“哈希合法但业务不合法”的日志拒绝，原字节保持。
- 新备份的字节/哈希/重放核验、同内容/坏目的路径拒绝、相同来源路径拒绝、全过程独占。
- 脚本注入的写入前、部分写入、完整写入、flush 边界、核验及丢失确认故障；不同有效日志也不能冒充原检查对象的备份。

由于抽取了共享读取函数，同时复跑原文件存储 21 项、owner 29 项、生命周期 15 项，全部通过。当前故障是内部测试回调注入，不是实际磁盘故障或断电。公开 API 没有回调或原始句柄入口；核验后的最终注入点只用于模拟确认丢失，不传出可修改句柄。

## 尚未完成的保存能力

本阶段没有 schema 1→2 升级、旧 0.3.1 导入、恢复选择、自动备份轮换、日志压缩或个人存档激活。检查/备份也不补齐独立高水位：如果整份来源被完整回退到较早合法帧边界，当前验证仍可能接受它。SHA-256 是损坏检查，不是身份认证或反作弊证明。

尚未验证真实断电、磁盘坏块、网络盘或存储设备缓存保证，不能据 `Flush(true)` 与脚本故障检查声称所有持久化故障均已恢复。后续升级仍须保留来源备份、独立候选、明确分支切换及逐项对账，不能把这项备份工具直接当成迁移工具。
