# 宿主持有的抛竿准备状态

这是按[抛竿链路](../../docs/CASTING_FLOW_SPEC.md)实现的独立动作切片。`CastFloat`仍表示已确认出手的资源事务；新的`FloatCastPreparation`在它前面保存按下、蓄力、松开及取消的瞬态状态。此切片尚未接页面鼠标、实际活动时钟、动画或真实水面，不能把固定测试靶称作已经能够落水钓鱼。

## 操作边界

| 阶段 | 行为 | 出手消耗 |
| --- | --- | --- |
| Begin → Charging | 核当前view/document/lease、模拟资格、无活跃会话、固定装配/线长、饵与体力、host目标；固定本次request/event/session及版本 | 零 |
| Advance | 只累计宿主明确提供的0..250毫秒活动步；按显式配置计算并限制力度，不读页面时间、帧率或系统墙钟 | 零 |
| Release → Prepared | 同一opaque手势令牌冻结目标与力度；本次松开不能开始另一手势 | 零 |
| CommitPrepared | 独立host出手事件再次校验资格、冻结版本和目标，使用同一命令保存；只有新写入确认才返回一次出手信号 | 同一笔扣一份饵及配置体力 |
| Cancel / 拒绝 | 未提交动作终结，旧令牌与迟到事件不能恢复；新的按下才能开始 | 零 |
| 保存不确定 | 进入Unknown，阻止重试/补偿，不先展示飞行 | 不猜测；关闭并核验原文件 |

已提交动作的取消不退款、不改变文件中的会话；后续必须走既有Recall/Recovery或收鱼链路。重播历史回执不能再次启动飞行。页面重建后应只投影当前动作，而非从回执重新播放动作。

目标由host内部不可变`FloatCastTarget`提供，坐标为整数毫米、规则版本与所需线长明确。注入的验证函数负责当下目标资格；本轮使用固定靶与失效开关。真实地形、水面、障碍和放线关系尚未接入，不能由页面自行声明“落点有效”或“所需线长”。蓄力上限和最低力度也由显式配置给出，不来自RF4原公式。

## 后续接线必须同时完成

- 控制器由唯一游戏owner所在宿主持有，不挂在每个页面或GameBinding上。
- opaque手势仅留在host；Release/Commit复核的是Begin保存的许可，不是新的消息来源。页面适配仍必须先核当前消息的窗口、文档、前台和许可，再将匹配手势交给控制器；不能把本内部API当作浏览器授权入口。
- 活动时间统一入口按顺序推进，页面只传动作意图，不传已蓄力时长、力度或消耗。菜单/宿主暂停、失焦、重载、隐藏及右键/Esc需取消未提交动作。
- 启用鼠标链路时关闭现有静态数据页直接`cast`事务的旁路；按钮也走同一准备/确认流程。
- 动画未就绪时可以明确使用临时host出手事件，不能在任意延时到期后无条件发射。真正飞行、落水、漂相、提竿和遛鱼另按P3/P4接入。

## 验证

2026-10-27：`test-cast-preparation.ps1`的21组检查及主代理独立复跑通过，warnings-as-errors；覆盖零成本准备、同活动时长不同步长得到同力度、取消/迟到事件、旧令牌/授权、菜单/暂停/重载、目标与线长/版本/资源复核、新写入确认仅一次出手、已出手撤销不退款，以及flush后不确定阻断。

审查补齐非I/O意外异常先终结为Rejected再原样抛出，避免准备状态留下可再次触发的旧事件。同一测试组补查验证回调改变菜单资格后的再次核验、重入Cancel拒绝，以及写前异常后重复回调不再尝试写入。最终21组全部通过。


文件测试使用专用新档与受控异常，活动步由测试明确传入；未执行真实页面鼠标、系统暂停计时、动画/水面物理、断电或个人存档。它与此前12项隐藏WebView数据接线独立，不能把两组结果合称鼠标蓄力已接通。
