# 整理已损失装备

背包最多保留128个当前装备实例，其中Lost记录原来也占用名额。现在空闲时可以明确整理这些记录，腾出购买名额；原日志与丢失事实全部保留，不退款、不赠物，也不恢复鱼线。

`ArchiveLostFloatEquipment`（schema3/type19）冻结1至128个当前Lost身份。目标必须全部存在、全部已损失且剩余线量为0，任意一项不符则整笔拒绝。库存修订加一，钓组修订和在用装备不变；活动竿和待放流会话禁止整理。

回执独立保存归档物件身份、损失归属身份及初始线量，不混入鱼获列表。状态从完整日志重建归档索引，后续请求、事件、会话、遇鱼和资产创建均不能复用它们。旧基底中没有损失回执的Lost归属也会保留。分批归档可引用同一损失事件，物件身份只能归档一次。

FEQP v1和旧基底格式不变。当前装备账本移除已归档条目后，生命周期初始量与损失量分别为当前账本值加 `ArchivedEquipmentLineMm`；可用剩余量保持当前账本值。只读检查工具已使用生命周期汇总。单独导出当前FEQP不能代替完整存档及历史。

页面只发送“整理损失记录”动作、输入序号和期望状态序号，宿主冻结当前全部Lost，创建请求/事件身份并复核权限。页面不能传物件列表、归档线量或退款。已知未写入可明确重试同一命令，未知结果冻结，重新加载只展示确认后的状态。三个菜单保持互斥，整理后可直接购买。

该功能不压缩日志，不解除10000笔/16MiB上限，也不自动归档；长期续档、经济恢复和物理断线仍有独立工作。测试中的装备损失仍由显式事实注入，不是已实现的物理断线。
