# 备件目录与购买

备件使用现有 schema3 装备账本及唯一日志写者。购买只扣款并增加一个背包实例；装配、整段移线仍是独立操作。商品范围为鱼钩、浮漂、沉子和鱼线，当前没有竿轮购买、拆卷、合并、出售旧装备或维修。

## 显式目录

`FloatEquipmentOffers` 绑定实际装备目录的完整内容摘要，最多16个唯一SKU。价格使用正整数最小货币单位，数量固定一件；鱼线另外声明整数毫米长度，其他品类长度为零。完整装备定义、兼容规则和损失规则共同参与目录绑定，不能只用版本号代替内容核对。摘要用于内容一致性，不是账号认证或反作弊签名。

FEOS v1 编码有长度、计数、键名、顺序、严格UTF-8及尾随数据限制。解码必须获得当前装备目录与钱包上限，不能安装未知装备定义或从损失记录补造物品。

`CreateNewWithEquipmentOffers` 只接受新的schema3基底，先写原有genesis，再确认一笔 `ConfigureFloatEquipmentOffers`。成功时序号为1。旧genesis及type1至15载荷不变，旧schema3档不会在打开时自动加入商品。配置失败保留新文件，不覆盖、删除或默默重试。配置不属于普通页面或host事实命令。

开发宿主新档显式采用目录1：单钩35、浮漂120、沉子25、50米尼龙线400最小单位。100最小单位为1银币。它们是原创开发数值，不是RF4价格或已完成的经济平衡。

## 报价与原子保存

`FloatEquipmentPurchaseQuote` 冻结玩家/分支、进度、装配/库存/规则修订、商品目录版本与摘要、SKU、装备定义、类别、价格和长度。购买时再次与实际目录及当前状态核对；页面只引用宿主保存的报价编号，不能提交价格、新实例身份或持久请求身份。

购买要求当前授权、菜单打开、无活动竿或待处理鱼，钱包足够且装备账本未达到128实例。上限包含丢失记录，现阶段不删除历史来腾出空间。成功只追加一笔交易，库存修订加一，装配修订不变。新线段的初始/剩余长度相等，原线段及已损失长度不变；买入不会补满旧线或自动装上线杯。

重复的完整请求返回原回执；同请求改内容、旧报价、伪造目录、复用资产或损失身份均拒绝。已知写入前失败只能明确重试原命令；未知写入冻结。关闭后核验完整帧可恢复同一件已购装备，部分帧拒绝打开，不自动修尾或重扣款。

## 页面与恢复范围

`game-spares-state` 是有界只读投影。金额、序号及目录版本使用规范Int64十进制字符串；旧格式无备件字段，未配置的schema3显示明确不可用原因。`game-spares`仅接受quote、buy、retry和cancel四种精确字段形状。报价绑定当前页面、许可与进度，重载/撤权/菜单关闭使未写入引用失效。

备件、补给和装备菜单共用操作互斥；其他菜单临时忙碌不应丢弃当前宿主投影。已知失败待重试时，其他菜单不能替代或绕过原操作。

`test-equipment-offers.ps1` 验证纯目录与编码，`test-equipment-commerce.ps1` 验证真实私有文件购买、缺件恢复、重开及注入故障。原生菜单闭环另用 `diagnostics/dual-window/test-webviews.ps1 -GameSpares` 检查。该入口受控提交一次末端损失，再通过真实页面购买、装配与重新抛竿；它不证明物理断线或真人输入已实现。

后续仍需显式旧档升级、余额耗尽的可恢复玩法、长期库存/日志容量策略，之后才开放真实装备损失。当前求解超限不会被当作断线处罚。
