# 单套浮漂装备归属与变更候选

2026-10-28。`FloatEquipmentLedger.cs` 是独立纯数据模块，补齐 [浮漂装配规格](../../docs/FLOAT_RIG_ASSEMBLY_SPEC.md) 的缺件、归属、换件和线量边界。它没有接入现有 `FloatGameState`、保存格式、商店、宿主或页面，也没有让当前游戏开始随机损坏装备。

算法、目录和测试参数由本项目独立定义，不是 RF4 装配公式。本模块没有默认装备、免费备件、默认耐久或恢复旧参数的逻辑。

## 不可变数据和显式目录

`FloatEquipmentLedger(rigId, rigRevision, inventoryRevision, catalog, instances)` 保存一套浮漂装配和至多 128 个装备/线段实例。已丢失实例也计入上限，不能删除其身份后重新补一件同 ID 的装备。传入集合会复制成只读集合；实例、位置、定义和规则本身均不可变。

首批支持竿、轮、主线、单钩、浮漂和一件沉子。装备直接位置只有四类：

- `Inventory`：背包中的一件装备或一整段线。
- `RigSlot`：当前钓组的竿、轮、钩、漂或沉子槽。一个槽位只能引用一件实例。
- `ReelSpool`：一条线段直接归属于一个真实存在且未丢失的渔轮。每个渔轮最多一条线段；钓组没有第二份“主线槽库存”。
- `Lost`：已经不可用的实例，记录明确的损失事件身份。它保留在集合中，不能装备、移动或作为新物品重复加入。

型号 ID 与实例 ID 分开。目录明确提供定义类别、质量、线径、竿的允许抛投质量范围、浮漂的允许沉子质量范围、竿轮连接、渔轮/线型号及线径的容量表、钩饵关系和允许的末端损失规则。缺定义/缺关系返回 `configuration-missing`；显式禁止的组合返回不兼容原因，不能把缺表等同于允许或自动套公式。

此切片固定一个鱼饵型号，仅检查钩饵关系和调用方提供的份数，不拥有、移动或扣除鱼饵堆叠。抛投质量近似明确为钩、漂、沉子三件质量之和；尚未加入鱼饵质量、前导线、多沉子或完整浮力模型。

目录有独立正整数版本，创建后内容冻结；账本直接保留该目录对象，不接受操作中悄悄替换另一个同版本目录。长度统一为整数毫米，线径整数微米，质量整数毫克；单线初始长度限制为 1 至 100,000,000 毫米，所有加总、修订递增和变更核对使用整数及溢出检查。

## 可编辑和可抛竿分别检查

`ValidateAssembly()` 检查已提供实例的类别、归属、兼容、线杯容量及具备足够部件时的配重。缺件允许作为可编辑状态存在。例如卸下鱼钩后仍是合法装配，不能因未计入钩质量而提前判定整套抛投质量不合格。

`EvaluateCastReadiness(gate, requiredLineMm, baitCount, stamina, castCost)` 再检查五个必需槽、实际装在当前渔轮的主线、所需出线量、鱼饵、体力和业务状态。背包里的备用线不能冒充已装主线。检查返回按槽位稳定排序的原因列表，本身不消耗资源、不提交出手。

`gate` 是唯一业务持有者提供的状态，不能让页面自行声称空闲：`Idle` 允许普通换件，`ActiveSession`、`PendingResult`、`PersistenceUnknown` 分别拒绝为忙碌、待结果和保存未知。纯模块不代替宿主授权，也不持有完整抛投状态机。

## 原子换槽与整段移线

`ReplaceSlot(gate, expectedRigRevision, expectedInventoryRevision, slot, itemId)` 只接受现有、未丢失、位于库存中的对应类别实例；`null` 明确表示卸下。它一次生成“旧件回库存、新件进槽、实例和库存/钓组修订递增”的完整候选。新装配不兼容、版本过期或发生溢出时返回原账本对象，不发布部分变更。

拆卸或更换渔轮时，原线段仍归原渔轮。新渔轮若已有自己的线，就使用它自己的线；不能把旧轮的线自动切给新轮，也不能再生成一段背包线。

`MoveLine(gate, expectedRigRevision, expectedInventoryRevision, lineId, reelId)` 移动现有整段线，`null` 表示移到库存。目标线杯必须为空，不能默默顶掉另一条线；目录中的容量必须覆盖这段剩余长度。移动经过的渔轮与线段修订递增，只有影响当前已装渔轮时才增加钓组修订，库存修订总会增加。

重复选择同一件装备或同一线段位置返回 `assembly-unchanged` / `line-unchanged`，不增加任何修订。此模块没有拆分库存线卷、绕新线、合并残线、购买、出售或修理入口。

## 明确的末端损失候选

`LockForSession(sessionId)` 对完整且兼容的装配创建不可变会话快照引用，绑定原账本、原目录、装配/库存修订，以及当前已装渔轮的确切线实例与修订。相同版本数字但来自另一份账本或目录的锁无效；手工构造的锁也不能指向背包渔轮的备用线，或使用空/与装备冲突的会话身份。

`PlanTerminalLoss(gate, sessionLock, lossEventId, ruleKey, outLineMm, cutDistanceFromReelMm)` 只在 `ActiveSession` 接受原上下文。调用方必须已经确定物理失败事实，提供已配置的连接损失规则与冻结的整数几何量。它不根据张力、时间或随机数自行决定断线。

断点从渔轮沿已出线计距，满足 `1 <= outLineMm <= segment.RemainingLineMm`、`0 <= cutDistanceFromReelMm <= outLineMm`：

```text
本次损失毫米数 = 已出线毫米数 − 断点距渔轮毫米数
保留毫米数 = 原剩余线长 − 本次损失毫米数
            = 原线杯余量 + 断点近轮端线长
```

配置的末端损失集合必须包含鱼钩，只能再声明浮漂和/或沉子；不能拿末端断线规则销毁竿或轮。未声明的部件保留原身份和位置。断点位于连接末端时允许零毫米线损失，但仍按规则丢失钩等末端件；没有配置的连接关系直接拒绝。

部分损失缩短同一条线段并递增其修订。余量变为零时，原线 ID 保留为零长度的 `Lost` 记录并释放线杯；它不能再次装回去。候选记录本次损失长度和完整丢失的实例 ID。对整个账本始终满足：

```text
初始线量 = 当前剩余线量 + 累计损失线量
```

初始线量是调用方明确提供的既有线段预算，不是程序赠送的商品线卷。纯模块没有旧档导入；未来适配现有 `FixedFloatRig` 时必须保留原 `LineId` 和线长，明确其为既有已上线段，不能补造库存线源或默认耐久。

旧会话锁不能作用到损失后的新候选。损失事件身份与装备身份不能混用；已记录的损失事件不能在补件后再次使用。对相同原始不可变输入重复规划仍可返回同样的候选，这不是持久去重回执：外部事务必须使用同一请求/终结身份原子确认，确认前不得发布候选为玩家资产。

## 当前验证与后续边界

`test-equipment.ps1` 只编译这个新模块和专用测试，在新的私有目录运行 32 项检查。覆盖输入集合冻结、目录缺失与禁止组合、缺件就绪、换钩、两套带线渔轮交换、整段线卸装、容量与配重、忙状态和旧修订、部分/全部/零毫米损失、保留丢失身份、线量守恒、旧锁与错误上下文、溢出，以及用已经持有的备用钩和线恢复就绪。

测试使用显式声明的目录和私有内存实例；没有读写个人存档或启动 WebView。当前生产 `FixedFloatRig`、schema1/2、原有交易、脱钩模型与宿主均未修改，真实断线尚未启用。

下一步仍需唯一事务持有者、保存编码和回放、真实备件购买及换装交互，再将物理失败接到这些已验证的候选边界。格式升级、旧档资产映射、库存线卷、耐久/磨损、维修、多沉子、前导线和跨会话物理续局不属于这一阶段。不能将本模块的候选检查当作这些功能已经完成。
