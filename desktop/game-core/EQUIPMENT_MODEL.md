# 单套浮漂装备归属与持久事务

2026-10-29。`FloatEquipmentLedger.cs` 已接入 schema3 的 `FloatGameState`、唯一 `FloatGameStore`、回放、owner 用户命令和抛竿准备，补齐 [浮漂装配规格](../../docs/FLOAT_RIG_ASSEMBLY_SPEC.md) 的缺件、归属、换件和线量边界。菜单已通过60项隐藏原生宿主/WebView联合检查，其中9项验证装备操作；真实鼠标桌面体验仍未验收，也没有让当前游戏开始随机损坏装备。下面同时保留独立模型和编码阶段的历史验证范围。

算法、目录和测试参数由本项目独立定义，不是 RF4 装配公式。本模块没有默认装备、免费备件、默认耐久或恢复旧参数的逻辑。

## schema3 的唯一装备来源

`FloatGameState` 按格式互斥保存装备：schema1/2 仅有内部 `LegacyRig: FixedFloatRig`，schema3 仅有内部 `Equipment: FloatEquipmentLedger`。不能同时保留两份钓组或背包。公开只读 `Rig: FloatRigDescriptor` 从实际装备来源派生；部件身份和线长允许为空，缺钩、卸轮或取出鱼线后不会补造一套完整钓组。抄网继续只由原 `OwnedNet` 字段拥有，不重复加入六类钓组账本。

schema3 仅通过内部 `CreateNewWithEquipment` 显式新建，测试和当前宿主开发夹具使用新私有路径；初始装备、钱包、鱼饵和体力均由调用方明确提供，不自动补件。genesis 在原装配位置嵌入有长度边界的 `FloatEquipmentCodec` 数据块；外层身份、规则和补给目录与装备数据合计仍受 64 KiB 帧预算约束。

schema1/2 的 genesis、旧命令字节及指纹保持兼容，旧日志继续按原规则回放。当前没有 schema2→3 的升级命令或旧档装备映射，也不把旧档直接标成 schema3；已有 schema1→2 的独立候选升级保持其原行为。每帧必须与当前格式一致，只有既有明确的 1→2 升级例外；正确重算帧哈希也不能使 2→3 跳转或 3→2 降级成为合法日志。

## 已接入的装备事务与菜单边界

`ReplaceFloatSlot` 和 `MoveFloatLine` 将下面纯账本的换槽、整段移线候选交给唯一 store 保存。命令绑定 profile/branch、request/event、状态序号、钓组修订、库存修订及装备目录版本；存储确认后才发布新装备。缺件可保存并跨重启保留，重复选择无变更时不新增事务；原请求重放不重复移动，修改同一请求的内容则拒绝。

schema3 出手使用 `CastFloatWithEquipment`，额外冻结所需线长、库存修订和装备目录版本。准备开始与最终出手分别核验就绪条件；旧 `CastFloat` 在 schema3 被明确拒绝，不能绕过缺件或线长检查。缺钩、未装主线、线长不足、缺饵或体力不足都不写出手记录、不扣资源。已确认会话保存装备版本和所需线长，满护待处理状态继续保留这些绑定。

owner 仍先检查当前 view/document/lease，再处理命令和旧回执。当前授权的菜单可编辑空闲装备；活动会话、满护待处理结果、旧授权和保存不确定状态均不能换件。菜单适配只允许选择已有实例和明确的目标位置，版本及持久请求身份由宿主生成；页面不能填写价格、制造资产或替换完整账本。

已知写前失败保留原操作供明确重试，新操作不能覆盖这个待处理意图；保存结果不确定时撤销控制、冻结写入并隐藏未确认状态。页面重载不会重建装备。真实WebView菜单已验证六笔事务：卸钩与装回、拆轮与装回、取出整段线与装回，使用实际DOM选择与按钮；缺件禁抛、重载、旧授权拒绝、写前故障及明确重试同时通过。

## 不可变数据和显式目录

`FloatEquipmentLedger(rigId, rigRevision, inventoryRevision, catalog, instances)` 保存一套浮漂装配和至多 128 个装备/线段实例。已丢失实例也计入上限，不能删除其身份后重新补一件同 ID 的装备。传入集合会复制成只读集合；实例、位置、定义和规则本身均不可变。

首批支持竿、轮、主线、单钩、浮漂和一件沉子。装备直接位置只有四类：

- `Inventory`：背包中的一件装备或一整段线。
- `RigSlot`：当前钓组的竿、轮、钩、漂或沉子槽。一个槽位只能引用一件实例。
- `ReelSpool`：一条线段直接归属于一个真实存在且未丢失的渔轮。每个渔轮最多一条线段；钓组没有第二份“主线槽库存”。
- `Lost`：已经不可用的实例，记录明确的损失事件身份。它保留在集合中，不能装备、移动或作为新物品重复加入。

型号 ID 与实例 ID 分开。目录明确提供定义类别、质量、线径、竿的允许抛投质量范围、浮漂的允许沉子质量范围、竿轮连接、渔轮/线型号及线径的容量表、钩饵关系和允许的末端损失规则。缺定义/缺关系返回 `configuration-missing`；显式禁止的组合返回不兼容原因，不能把缺表等同于允许或自动套公式。

此切片固定一个鱼饵型号，仅检查钩饵关系和调用方提供的份数，不拥有、移动或扣除鱼饵堆叠。抛投质量近似明确为钩、漂、沉子三件质量之和；尚未加入鱼饵质量、前导线、多沉子或完整浮力模型。

目录有独立正整数版本，创建后内容冻结；账本直接保留该目录对象，不接受操作中悄悄替换另一个同版本目录。长度统一为整数毫米，线径整数微米，质量整数毫克；单线初始长度限制为 1 至 100,000,000 毫米，所有加总、修订递增和变更核对使用整数及溢出检查。

## 可编辑和可抛竿分别检查

`ValidateAssembly()` 检查已提供实例的类别、归属、兼容、线杯容量及具备足够部件时的配重。缺件允许作为可编辑状态存在。例如卸下鱼钩后仍是合法装配，不能因未计入钩质量而提前判定整套抛投质量不合格。

`EvaluateCastReadiness(gate, requiredLineMm, baitCount, stamina, castCost)` 再检查五个必需槽、实际装在当前渔轮的主线、所需出线量、鱼饵、体力和业务状态。背包里的备用线不能冒充已装主线。检查返回按槽位稳定排序的原因列表，本身不消耗资源、不提交出手。

`gate` 是唯一业务持有者提供的状态，不能让页面自行声称空闲：`Idle` 允许普通换件，`ActiveSession`、`PendingResult`、`PersistenceUnknown` 分别拒绝为忙碌、待结果和保存未知。纯模块不代替宿主授权，也不持有完整抛投状态机。

## 原子换槽与整段移线

`ReplaceSlot(gate, expectedRigRevision, expectedInventoryRevision, slot, itemId)` 只接受现有、未丢失、位于库存中的对应类别实例；`null` 明确表示卸下。它一次生成“旧件回库存、新件进槽、实例和库存/钓组修订递增”的完整候选。新装配不兼容、版本过期或发生溢出时返回原账本对象，不发布部分变更。

拆卸或更换渔轮时，原线段仍归原渔轮。新渔轮若已有自己的线，就使用它自己的线；不能把旧轮的线自动切给新轮，也不能再生成一段背包线。

`MoveLine(gate, expectedRigRevision, expectedInventoryRevision, lineId, reelId)` 移动现有整段线，`null` 表示移到库存。目标线杯必须为空，不能默默顶掉另一条线；目录中的容量必须覆盖这段剩余长度。移动经过的渔轮与线段修订递增，只有影响当前已装渔轮时才增加钓组修订，库存修订总会增加。

重复选择同一件装备或同一线段位置返回 `assembly-unchanged` / `line-unchanged`，不增加任何修订。此模块没有拆分库存线卷、绕新线、合并残线、购买、出售或修理入口。

## 明确的末端损失候选

`LockForSession(sessionId)` 对完整且兼容的装配创建不可变会话快照引用，绑定原账本、原目录、装配/库存修订，以及当前已装渔轮的确切线实例与修订。相同版本数字但来自另一份账本或目录的锁无效；手工构造的锁也不能指向背包渔轮的备用线，或使用空/与装备冲突的会话身份。

`PlanTerminalLoss(gate, sessionLock, lossEventId, ruleKey, outLineMm, cutDistanceFromReelMm)` 只在 `ActiveSession` 接受原上下文。调用方必须已经确定物理失败事实，提供已配置的连接损失规则与冻结的整数几何量。它不根据张力、时间或随机数自行决定断线。

断点从渔轮沿已出线计距，满足 `1 <= outLineMm <= segment.RemainingLineMm`、`0 <= cutDistanceFromReelMm <= outLineMm`：

```text
本次损失毫米数 = 已出线毫米数 − 断点距渔轮毫米数
保留毫米数 = 原剩余线长 − 本次损失毫米数
            = 原线杯余量 + 断点近轮端线长
```

配置的末端损失集合必须包含鱼钩，只能再声明浮漂和/或沉子；不能拿末端断线规则销毁竿或轮。未声明的部件保留原身份和位置。断点位于连接末端时允许零毫米线损失，但仍按规则丢失钩等末端件；没有配置的连接关系直接拒绝。

部分损失缩短同一条线段并递增其修订。余量变为零时，原线 ID 保留为零长度的 `Lost` 记录并释放线杯；它不能再次装回去。候选记录本次损失长度和完整丢失的实例 ID。对整个账本始终满足：

```text
初始线量 = 当前剩余线量 + 累计损失线量
```

初始线量是调用方明确提供的既有线段预算，不是程序赠送的商品线卷。纯模块没有旧档导入；未来适配现有 `FixedFloatRig` 时必须保留原 `LineId` 和线长，明确其为既有已上线段，不能补造库存线源或默认耐久。

旧会话锁不能作用到损失后的新候选。损失事件身份与装备身份不能混用；已记录的损失事件不能在补件后再次使用。对相同原始不可变输入重复规划仍可返回同样的候选，这不是持久去重回执：外部事务必须使用同一请求/终结身份原子确认，确认前不得发布候选为玩家资产。

## 2026-10-29：严格有界装备数据编码

该编码阶段新增 `FloatEquipmentCodec.Encode(ledger)` / `Decode(byte[])`，在内存中转换完整装备账本。它不是第二个存档文件，也没有独立写者、提交确认或自动迁移入口；后续 schema3 genesis 使用这个数据块，仍由同一个日志写者负责确认。编码阶段本身没有修改 profile schema、日志、owner、页面和恢复收竿流程；当前也没有启用损失保护 Arm 状态或真实断线。

格式以四字节 `FEQP` 和小端 `UInt16` 版本 1 开头，依次记录完整目录、钓组身份与修订、全部实例。整数采用显式小端宽度，GUID 使用与现有日志一致的 .NET 16 字节表示。每个实例都保留型号、类别、修订、唯一直接位置、位置的拥有者/损失事件、初始和剩余线长；不会丢掉零余量线段、历史损失身份或背包渔轮中的线。

定义、竿轮关系、容量关系、钩饵关系、损失规则和实例分别最多 128 项；末端损失规则最多三种槽位。字符串先写两字节长度，再写严格 UTF-8，限 96 字节且符合现有小写 ASCII 标识符规则。非法 UTF-8、空字符串、非法布尔值、未知类型或位置、缺字段、重复或非法归属、负数及越界长度均拒绝，不替换乱码、不裁剪列表、不补默认值。

编码会按定义/关系键与实例 GUID 的明确顺序生成规范字节；解码要求同样的严格顺序，拒绝乱序、重复和尾随字节，而不是先排序后假装原数据合法。位置中的无关字段也必须是规范值：库存没有拥有者，只有钓组槽位能带槽号，其他位置的槽字节固定为 255。

编码前调用 `ValidateAssembly`，解码后先运行相同的数据构造约束，再调用同一个 `ValidateAssembly`。因此字节形状正确但容量或兼容关系不成立的数据也不能进入账本；合法缺件状态仍可往返，解码不会把缺钩补成完整钓组。解码得到新的不可变对象，输入字节数组后续变化不会改变它。

数据块总大小最多 65,536 字节，写入前逐字段检查预算。未来外层事务还需要身份、版本等字段，集成时必须从同一 64 KiB 总帧预算中扣除外层开销，不能把两个各自未超限的数据块直接相加。该编码没有校验和或防篡改能力：结构合法的数值修改仍可能解码成功，数据完整性与来源必须由唯一事务日志的帧哈希、上下文与回放规则负责。

`test-equipment-codec.ps1` 在新的私有目录以警告视为错误编译，30 项检查通过，包括完整/缺件/部分损失/零余量线段往返、所有 1,079 个严格截断前缀、目录与实例乱序/重复、每类计数和字段边界、严格 UTF-8、非法归属、共享兼容校验、大数据总预算和 1,000 次单比特修改。合法修改必须原字节重新编码一致，非法修改必须明确拒绝。原装备模块 32 项回归保持通过；没有读取或写入个人存档，也没有启动原生窗口。
