# 主线过载断线开发模型

2026-11-14。本切片把[遛鱼受力模型](FIGHT_MODEL.md)的实际主线负载接到现有 schema3 [末端损失事务](EQUIPMENT_MODEL.md)。算法、阈值和损失规则均为本项目原创开发配置；RF4 的材料强度、断线概率、磨损和服务器结算数据仍未知，没有复现其原版规则。

这不是持久化的鱼线强度目录，也没有耐久、维修或完整渔具平衡。普通 `--game-new` / `--game-open` 不启用物理断线；必须明确使用 `--game-line-break-new` 或每次使用 `--game-line-break-open`。构建和启动方式见[页面说明](../game-page/README.md)。

## 适用装备与显式配置

宿主要求 schema3、已有备件商品目录，并核对完整装备目录的规范签名与当前开发套装完全一致。检查覆盖定义和关系，不只比较目录版本或同名规则；不兼容的旧档拒绝进入此模式，不补造目录或升级原档。

每次创建遛鱼模型时，规则绑定当前实际装在渔轮上的 `nylon-018` 主线实例及修订，使用其真实剩余线长，不从初始 50 米或商品线卷长度补满。当前配置为：

| 项目 | 当前值 |
| --- | --- |
| 规则版本 | 1 |
| 负载阈值 | 5,000 毫牛顿，即 5 N |
| 连续过载门槛 | 5 个有效固定步，每步 50 毫秒 |
| 末端损失规则 | `mainline-terminal`：鱼钩、浮漂、沉子 |
| 断点距渔轮 | 0 毫米 |

阈值是这套开发配置的测试参数，不代表直径 0.18 毫米尼龙线的真实材料强度。型号相同也不能跳过完整目录、实际装线身份、修订和剩余长度的检查。

## 受力判定与冻结证据

只有已经通过求解、支持范围与线量守恒检查的物理固定步才参与判定。该步张力**严格大于** 5 N 时连续计数加一；小于或等于 5 N 时归零。达到 5 步即进入 `FailurePending`，停止持续收线，冻结当前失败票据及证据，并向宿主发出一次失败提交信号。

50 毫秒步来自有效活动时间，菜单、失焦和暂停期间不计时，也不补算后台时间。暂停本身不伪造一个低负载物理步，因此不清空已经累计的连续有效步；恢复后由后续实际求解继续判定。无效候选、负载或速度超出模型支持范围仍走故障暂停，不能伪装成一次断线损失。

证据保存同一会话、遇鱼、步号、实际张力、主线身份与修订、规则版本、阈值及门槛、总线量、整数出线量和断点。页面无权创建或修改它。宿主在首次构造损失命令前再次核对当前会话、钓组、装备目录、实际主线及冻结证据。

## 整数损失与保留线量

损失只在终结时量化一次，来自冻结的实际物理出线，不使用页面四舍五入后的显示值，也不以初始抛竿距离代替：

```text
出线毫米数 = floor(实际出线米数 × 1000)
本次损失毫米数 = 出线毫米数 − 断点距渔轮毫米数
当前断点 = 0，因此本次损失 = 出线毫米数
保留毫米数 = 当前主线剩余毫米数 − 本次损失毫米数
```

完全放尽主线时直接采用原始整数总线量，避免浮点换算少扣一毫米。出线量必须在 1 至当前实际主线剩余长度之间。不足一毫米的小数部分不会额外向上扣除。

确认后，鱼钩、浮漂、沉子按原目录转为丢失记录；鱼竿和渔轮保留。部分线损失缩短同一线段，余量留在原线杯；剩余量为零时保留原线身份的零长度丢失记录并释放线杯。账本继续满足“初始线量 = 当前剩余线量 + 累计损失线量”。不发鱼、不退款、不补件，也不重复扣除抛竿时已经使用的鱼饵和体力。

## 保存确认与恢复边界

宿主将同一冻结事实构造成 `HostFloatTerminalLoss`，交给唯一 `FloatGameOwner` / store 写者；沿用 schema3 的 type15，不改变其字段、编码、指纹和旧日志字节。不新增损失标记文件，不新增第二个写者。页面的 `retry-escape` 只表示重试原结果，不携带损失量、断点、阈值、部件身份或业务事务身份。

| 保存结果 | 行为 |
| --- | --- |
| 确认提交并取得 `TerminalLost` 收据 | 转为 `Escaped / line-overloaded`，结束本竿；页面才显示断线损失已确认 |
| 确认写入前失败 | 保持 `FailurePending`，冻结原票据、证据与命令；只能明确重试同一原命令，不自动重发，也不能用收回绕过 |
| 写入结果未知 | 模型和 owner 冻结，宿主故障退出；不允许重试、补偿或以普通退出再写一笔收束 |

完整帧已落盘但确认丢失时，重开核验得到原损失事务；精确重放原请求不会再扣一次。部分尾帧仍拒绝打开，不自动剪尾。

**未落盘的内存事实无法在进程崩溃后恢复。** 如果断线事实只留在内存、没有写成有效日志事务，进程退出后再打开，现有恢复逻辑只看见普通中断会话并执行原有收束，保留原装备。此版没有跨进程的断线待结算记录，不能声称能防止通过退出逃避未保存的损失。

## 页面与后续游玩

`game-fight-state` 额外提供 `breakEnabled`、`breakThresholdMilliN`、`overloadExposureSteps`、`overloadRequiredSteps`。四字段必须整套有效；兼容旧宿主完全省略时视为关闭，关闭时三个数必须全为零。页面只显示宿主阈值和计数，不用本地时钟预测断线，也不因为启用了断线配置就把松线脱钩误报为装备损失。

只有已确认 `Escaped / line-overloaded` 才显示断线及损失已保存；待保存、已知未写入和未知写入继续使用失败确认流程。已确认松线脱钩仍按[脱钩模型](UNHOOK_MODEL.md)处理，没有断线损失。

确认损失后可在任意钓点打开菜单，通过[备件购买](EQUIPMENT_COMMERCE.md)购买并明确装回缺件。剩余线仍满足抛竿需求时可继续使用；不足时自行购买和换线，不自动补满。实例名额不足可明确[整理损失记录](EQUIPMENT_ARCHIVE.md)，符合资格的缺钱玩家可使用[营地帮工](ECONOMIC_RECOVERY.md)。这些操作不退款或抹掉已确认损失。

重新启动必须再次显式选择 `--game-line-break-open` 才启用该物理开发配置。普通 `--game-open` 会保留已经写入的损失与缺件，但不自动延续断线判定。此切片不承诺跨重启续接同一场遛鱼、真人操作手感、最终画面或真实材料精度。
