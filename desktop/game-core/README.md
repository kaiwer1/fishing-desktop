# 单套浮漂的纯事务核心候选

这是单屏可玩链路所需的最小C#数据切片，独立于诊断counter、现有游戏和三份UI草稿。沿用[库存交易](../../docs/INVENTORY_TRANSACTION_SPEC.md)、[浮漂出手](../../docs/FLOAT_RIG_ASSEMBLY_SPEC.md)及[满鱼护收束](../../docs/FIGHTING_MODEL_SPEC.md)合同；已形成[文件存储](STORAGE.md)、[唯一GameOwner与会话收束](OWNER.md)和[页面/现有宿主接线](../game-page/README.md)。32/23/21/29/15项核心分层检查、16项页面命令、13项显示投影及12项隐藏WebView联合通过。真实游戏桌面输入、物理及完整正式存档仍未完成，不宣称P1整体通过。

- `FloatGameState.CreateNew(...)`必须显式提供profile/branch、固定完整装配、整数初始钱包/体力/鱼饵和配置；新分支从序号0开始，没有读取旧存档、清洗坏数据或默认发钱/装备的入口。
- `FixedFloatRig`只表示一套已经声明完整的竿、轮、线段、钩、漂和沉子；引用非空且唯一，线长为正整数毫米。它不替代完整装备目录的兼容、耐久、线杯容量、目标水面和出手动画验证，不能作为任意装配的通用授权。
- 钱包为整数最小单位（100=1银币），质量为整数毫克，体力/鱼饵份数为整数。状态/配置/命令/回执复制集合为只读，并校验范围、身份、容量、序号和会话归属；没有把异常输入回退到初始资源。
- `FloatGameReducer.Reduce(state, command, rules)`不修改输入，返回`FloatReduction`。`HasCandidate/RequiresConfirmation`为true表示有一份新的完整候选；调用方未来必须先持久化并取得确定确认，再把它发布为当前状态。`OperationSucceeded`只描述业务结果，不能代替确认判断。
- **满鱼护的`creel-capacity-exceeded`业务拒绝也有候选**：`OperationSucceeded=false`，但`HasCandidate/RequiresConfirmation=true`，含同一待处理鱼/会话和回执，必须确认后才能发布结果暂停。不能用“返回失败”跳过这份状态变化。
- 历史回执只从调用方传入的已确认输入state查找。同request同内容返回旧Receipt且`IsReplay=true/HasCandidate=false`；不会重算、重扣或把旧回执内余额覆盖到当前状态。刚返回但未确认的候选不自动进入历史。
- profile/branch先核对，再查request指纹；历史命中先于旧版本/缺配置检查。新业务再查event/session身份、整体Sequence、rig/rules版本及完整配置签名。相同版本下改配置内容也拒绝；身份集合规范排序，重排鱼ID清单不改变命令语义。
- 普通受理前拒绝没有候选或回执，不记录为已确认历史；本切片不承诺跨重启重放未受理错误。回执保留全历史以验证防重，尚无生产容量、裁剪/压缩或日志格式。

## 本切片支持的事务

| 入口 | 原子候选结果 |
| --- | --- |
| `CastFloat` | 当前无会话且饵/体力足够时，扣一份所选饵和配置体力一次，保存release event、session及固定rig/rules快照；同session换request也不能再扣 |
| `RecallFloat` | 只收回当前尚无待处理鱼的会话，不退已确认鱼饵/体力、不补线、不发鱼；历史请求重播不再次终结 |
| 内部`HostFloatFish` | 由程序集内部host事实提供鱼/encounter身份、物种和整数质量；配置查物种/质量边界并计算一次锁定售价。入护有空间则终结入护，无空间则保持同一待处理鱼 |
| `ReleaseCurrentFloatFish` | 只终结当前容量拒绝的待处理鱼一次，保留旧鱼护和出手成本；没有释放旧鱼/换容量的命令。本切片未接成长奖励，放流不发奖励 |
| `SellFloatFish` | 仅无活跃会话时出售冻结的具体鱼ID集合，使用已锁定整数值；任一缺鱼/重复ID/空集合/溢出使整笔无候选，不先移除部分鱼 |

`HostFloatFish`及鱼资产构造器均不是public用户入口。用户命令没有可填写的重量/价格，reducer也不随机抽鱼、接HTTP或接受JSON。该程序集内部边界用于区分host事实与用户意图，不是身份认证/反作弊系统；未来页面适配仍须由唯一owner校验授权与动作/物理资格，不把内部鱼终结直接暴露成页面路由。

固定事务切片将容量裁决放在实际host收鱼时，允许测试/host提供“出手后容量已满”的终端情形；它尚未实现抛竿前的完整就绪提示/容量预检、空间竞争或多竿。容量拒绝候选禁止Recall、再抛、替换当前鱼和卖旧鱼；只能明确放流当前鱼后结束，再按一般门槛管理旧鱼护。

配置只由host显式传入：支持的固定rig/bait键、正整数成本/上限、至少一种明确物种的质量边界及`MinorPerKg`；空物种配置直接拒绝，不能先扣出手成本再发现没有任何收鱼规则。计价使用checked整数乘法后除以1,000,000向下取整，没有未知价格默认值；测试用carp/crucian及所有数值均是夹具，不是正式中国鱼种目录、RF4公式或经济平衡数据。

## 纯核心与外部确认

保存层须把候选状态和该回执作为同一可恢复提交确认；保存结果不确定必须阻止新写入、查询原身份，不能拿旧state继续接新业务，也不能先退款再重放。这个纯reducer没有I/O结果，无法替调用方判定写入是否发生。新增FloatGameStore已实现该切片的文件确认/不确定阻断，明确限制见[存储说明](STORAGE.md)。

测试仅通过显式`AcceptForNextInput`把候选用作下一次输入，表示“假设外部已确认”的测试前提，不是磁盘/进程恢复证明。丢弃候选后从原输入重试只会重新产生同一逻辑候选，不会在原状态偷偷留下消费或历史。

已增加host-only Recovery和Lifecycle、owner启动/退出收束，并接可选宿主模式的正常退出；已确认满护结果跨重启保留，不自动放流。中途物理状态、旧档迁移/备份/压缩、真实断电、食品/制作/技能、完整装配编辑、世界鱼群和正式价格仍未接通；页面/宿主联合范围另记，不能把对象层恢复测试称作真实断电恢复验收。
