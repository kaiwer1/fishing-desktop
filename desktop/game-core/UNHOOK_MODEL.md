# 固定步松线脱钩与失败确认

2026-10-28。`FloatFightSimulation.ModelVersion = 2` 在已有位置、线长、受力和抄鱼模型上增加明确配置的松线脱钩。本文补充并取代 [FIGHT_MODEL.md](FIGHT_MODEL.md) 中“尚未启用脱钩”的旧阶段说明；其余矩形水域、固定深度、有界求解和无自由控竿限制仍保留。算法是本项目原创近似，不是 RF4 公式或实测钩口生理模型。

## 配置和步序

`FloatFightSetup` 末尾新增可选 `FloatUnhookRules unhook = null`。`null` 明确表示未启用，保留旧训练测试和旧调用方的行为；不会偷偷安装默认概率或时间。正式调用方必须显式传入配置，再接通失败持久化流程。

`FloatUnhookRules(minimumSlackM, exposureSteps, recoveryStepsPerTick)` 是不可变配置：

- 松线门槛为有限正数，支持 0.001 至 1000 米；零门槛不合法。
- 暴露上限、每步恢复量均为 1 至 12000 的整数步数，与界面投影合同一致。每步仍为 50 毫秒，最高连续暴露门槛为 10 分钟。
- 宿主候选值 `(.25, 60, 2)` 表示实际松线达到 0.25 米时每步暴露加一，累计 60 个风险步后脱钩；连续风险的最短时间为 3 秒。低于门槛的有效步减去 2，最低为零。这是可恢复暴露，不是只要中断就清零的连续计时器。

每个活动步先完成已有鱼运动、绞入/泄力和力学求解，并检查支持负载、速度和线量守恒。合法物理状态发布后，以 `max(0, OutLineM - anchorToFishDistance)` 得到实际松线长度。仅钩仍连接的活动阶段累计或衰减暴露。求解失败或越出支持包络仍进入 `Faulted`，优先于该步可能成熟的脱钩，不伪装成正常跑鱼。

暴露成熟时先进入 `FailurePending`，清除持续收线、丢弃剩余不足一步/本调用尚未推进的活动时间，然后才考虑其他资格。它不能在同一步同时抄鱼。此前已经明确请求抄鱼而处于 `LandingPending` 的运行时不再推进物理或累计暴露。

读取快照、`Advance(session, 0)`、`ClearInput` 和页面重载本身都不累计、衰减或重置暴露。宿主失权时清除输入并停止提供活动时间；恢复后需要新按下。模型不读取墙钟，也没有“松开左键若干秒必脱钩”的规则：鱼仍拉紧线时，松开收线不会直接增加风险。

## 单一失败身份和确认

快照新增 `UnhookExposureSteps` 和 `FailureAttempt`。首次成熟的 `Advance` 返回一次 `ShouldCommitFailure = true`，附带 `FloatFailureTicket` 和尝试序号 1；后续调用不会再次提交。票据绑定原 `SessionId`、原 `EncounterId`、`Reason = "slack-unhooked"`，以及从这两个身份和成熟步数计算出的确定性 `FailureId`。独立命名域的 SHA-256 派生不消耗鱼行为随机流；绘制时间分割不改变失败身份。

票据在运行时按对象引用验证，相同字段的新对象或另一个运行时的票据均无权确认。宿主负责将它绑定到同一条失败命令并保留请求/终结身份；仅凭 GUID 不是业务授权。模型保留同一条锁定目标，既不抽取新鱼，也不增加鱼护、退款、经验或丢失装备。

| 调用 | 结果 |
| --- | --- |
| `ConfirmFailure(ticket, attempt, Confirmed)` | 转入 `Escaped`，只发一次 `TerminalEvent` |
| `ConfirmFailure(ticket, attempt, KnownNotWritten)` | 保持 `FailurePending`，原因 `failure-not-written`，不自动重试 |
| `RetryFailure(ticket)` | 仅已知未写入后可调用；保留同一票据，增加尝试序号，再发一次提交信号 |
| `ConfirmFailure(ticket, attempt, Unknown)` | 保持 `FailurePending`，原因 `failure-save-unknown`；锁住重试、抄鱼和 `End`，等待宿主核查原始日志 |

确认只接受当前仍在等待结果的尝试序号；较早尝试的迟到成功、失败或未知结果都不能覆盖新的尝试。未知结果不能靠迟到的第二个确认解除。任何 `FailurePending` 都拒绝 `End`，包括已知未写入，避免绕过必须保存的终结。已确认脱钩后再 `End` 可以清理运行时，但不会再次发出终结通知。

此处的 `Confirmed` 必须表示宿主已确认失败事务，不能在收到模型信号时直接当作成功。纯模型没有磁盘、库存或授权层依赖；本文件也不声称失败交易或页面联动已经验证。

页面84项、真实隐藏WebView51项联合检查通过。后者含受控多放2米线、写前注入故障、菜单暂停、重载、旧许可拒绝、明确重试和完整资源对账；正常退出且残留0。当前章节以下所述29项测试仍为独立纯模型范围。窗口联调没有直接覆盖未知写入/未确认退出，也不替代真人鼠标、桌面兼容或真实断电验收。

`test-unhook.ps1` 在新的私有输出目录编译并运行 29 项检查，覆盖门槛和整数范围、未配置禁用、精确步边界、不同时间分割、暂停和余数、暴露衰减、清输入、实际张力与松线区别、物理故障优先、脱钩先于抄鱼、原目标/线量、单次信号、票据伪造和跨运行时拒绝、已知/未知写入、迟到尝试及创建线程保护。原 `test-fight.ps1` 的 34 项回归保持通过。

启用 `(.25, 60, 2)` 后，另以原候选参数检查 100 组种子、鲤鱼 0.3 至 1.8 千克、鲫鱼 0.1 至 0.65 千克、前向起点 6 至 42 米和有限横向偏移。持续手动收线的样本全部在 37 至 488 步进入抄鱼资格，最大松线暴露为零；每个样本仍需明确抄鱼动作，没有自动授鱼。种子 91 的两种样本在不收线 30 秒后再手动收线，也可到达抄鱼资格。这只证明这些明确参数的包络，不能推论所有鱼、地图或装备均已校准。

受控失败样本从同一 50 米线预算中，明确将初始已出线增加 2 米；鱼采用零驱动休息行为，其他物理过程照常运行，不每步改写松线数值。它在 2950 毫秒仍未脱钩，在第 60 步、3000 毫秒活动时间产生唯一失败信号。该样本验证边界，不代表自然游动鱼必然三秒脱钩。

本切片不实现断线、断竿、磨损、末端部件损失或维修经济。脱钩只断开鱼与钩的连接，不凭空损坏现有完整钓组，也不返还已经消耗的鱼饵；相关账本效果由宿主的明确失败事务处理。测试未运行 WebView、没有访问或修改个人存档，也未验证真实鼠标、RX 580 性能或正式美术。
