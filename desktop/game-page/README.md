# 单竿数据、抛竿、漂相与遛鱼接入页

这是窗口/页面/文件、抛竿准备、简化飞行、漂相与手动遛鱼的整合候选，使用独立`FloatGameOwner`。页面显示余额、体力、鱼饵、当前会话和分页鱼护，并提供蓄力出手、右键提竿、左键按住收线、调泄力/速度、抄鱼、收回、放流、选鱼出售及菜单开关。输入区域使用固定朝向与矩形平面水域，轨迹、浮漂近景和鱼的位置均投影宿主状态；尚无真实场景、挥竿动画或最终美术，不替换0.3.1网页和三份暂停中的UI草稿。

## 运行边界

复用`diagnostics/dual-window`现有宿主的导航、激活握手、暂停、只读桌面挂接和渲染挂起。游戏消息走独立typed命令入口，计数器仍作为旧诊断授权基础，但游戏模式不会提交计数器交易；唯一游戏存档写者是`FloatGameOwner`。

- `build.ps1 -Game`在指定仓库外私有目录构建，并复制本页。默认诊断入口仍使用旧页面。
- `DualWindowHost.exe --game-new`仅显式新建当前构建目录的`game.fltj`；已有文件时拒绝覆盖。
- `DualWindowHost.exe --game-open`只核验并打开原文件，缺失或损坏不会赠送新资金/饵/装备。
- 两个用户入口均尝试单屏只读桌面和独立交互窗口，启用原生环境查询及输入撤销；没有已有可用桌面层则拒绝启动。当前游戏页的实际可见桌面、原生鼠标和系统转换仍须独立验收。
- `--game-self-test`仅使用两个隐藏普通WebView、专用新文件与脚本消息；以受控种子实际运行问饵抽样、提竿、受力和收鱼保存，同时保留固定鱼事实用于业务边界检查。不操作系统鼠标、不挂桌面，不代表真人手感或完整生态已验收。它的前台测试旁路不会应用于上述用户入口。

测试初始配置为120银币、12饵、100体力、容量2的固定装配；鲤鱼/鲫鱼是本次简化运行的候选池，也用于业务测试夹具。它们不是36鱼产品数据库、已平衡规则或个人存档迁移。

## 消息与显示

精确来源、当前窗口/导航/文档、前台及当前wire许可先由宿主核验，再传递其保留的opaque游戏许可。页面不能提供profile/branch、鱼种/鱼重/售价、恢复命令或任意配置。收回、放流和出售保存固定request/event/session及版本，重试不能更换业务身份；页面目前单业务请求在途，没有超时自动重发或不确定补偿。原直接`game-intent/cast`入口返回`cast-preparation-required`，不能绕过准备阶段。

## 蓄力与出手

- `game-cast`只接受六个字段：`kind/documentId/lease/transportId/action/inputSequence`；动作仅`begin/release/cancel`。输入序号是正整数的规范十进制字符串，每次明确授权后单调递增。宿主消费每次新的开始序号，即使该次开始被业务条件拒绝，迟到的旧开始也不能在之后变成新的一竿。
- 页面仅发送按下、松开或取消。活动时长、力度、目标、请求与会话身份由宿主持有；蓄力使用统一活动时钟返回的时间步，保留小数毫秒，不补算暂停时间或卡顿丢弃时间。
- 松开先变为Prepared。临时宿主出手事件排队执行时，再核对原窗口、导航、文档和许可；仅新事务保存确认后发送一次`game-flight`。此事件目前表示确认出手，不表示已实现飞行动画或有效落水。
- `game-cast-state`按文档独立递增revision显示阶段、力度与输入序号。新页面只显示当前状态，不重播历史出手事件。右键、菜单、取消交互、失焦、重载、隐藏、竖屏和宿主暂停会终止未出手准备；恢复后需要重新操作。
- 鼠标快速按下后立即松开不等待网络应答，两个意图仍使用同一个输入序号和原许可。按钮替代操作也走开始/松开流程；页面没有控制蓄力的计时器。

页面只收到最小显示投影。序号、版本、金额和质量使用规范十进制字符串，避免JavaScript大整数精度损失；鱼护每页最多50条，只暴露选择所需鱼ID，不发完整资产身份、回执历史或保存路径。每个当前文档的显示包有递增revision，旧包不能覆盖新显示。

菜单暂停与宿主暂停分开：菜单暂停模拟资格，仍可按业务规则出售或放流；宿主暂停撤销输入，解除后需要重新开启交互。统一活动时钟驱动准备、飞行、问饵和遛鱼；只有显式抄鱼满足条件并保存确认后才入护。正常退出显式收束；异常退出只释放并等待下次核验，不把不确定事务再写一次。

## 固定平面飞行

[飞行模型](../game-core/FLIGHT_MODEL.md)仅在新出手保存确认后创建一次。宿主采用原点/竿尖`(0,1500,0)`毫米、水面Y=0、X范围±40米、Z范围3至80米，初速6.5至20米/秒、仰角40°、重力9.81米/秒²和5秒上限。固定目标只确定朝向，力度决定射程；不表示总能落在15米瞄准点。

同一活动钟推进轨迹，菜单/宿主暂停冻结时间；页面重载只重建显示，收竿、满护待处理或会话结束才终止对应运行状态。没有有效落水时，宿主测试鱼事实也不能入护；有效落水本身不产生鱼、奖励或第二次扣饵。落在水域外、线跨度到达上限或超时显示明确失败，玩家可按现有收竿流程结束，不退款。

页面接收`game-flight-state`，按当前文档revision接纳位置、活动毫秒、所需线长与最多32个近期轨迹点。所有坐标按毫米整数显示；侧面SVG只投影这些宿主值，没有物理、外推计时或渔获逻辑。直线跨度不是线杯实际出线量；正式鱼线、风浪和障碍尚未接入。新文档可从一份当前快照恢复位置，不重播出手。

## 漂相与右键提竿

`game-bite-state`只提供当前会话/遇鱼身份、阶段、原因、活动步和搜索轮次的规范整数串、钩饵是否仍附着，以及有界的浮漂上下/侧向位移。`BiteView`只复制显示字段；不保留鱼种、鱼重、随机阈值和未来提竿窗口，不自行计算鱼口或补帧。每份消息须属于当前文档并有更高revision；新页面可从当前快照恢复浮漂。当前SVG是近景示意，尚非写实漂模型或真实水面效果。

`game-strike`由页面捕获当前许可、会话和遇鱼身份，附上新的单调输入序号；不发送过去点击时间、鱼种、质量或奖励。准备阶段右键仍优先取消；有效落水后的右键按下才提竿，按钮作为替代操作。`mousedown`覆盖组合按键产生的右键新按下，按住、移动、迟到回复、换许可和目标变化均不会缓存一次未来提竿。失去授权时保留物理按住抑制，直到观察到松键，重新授权不能使旧按住自动中鱼。

提竿按钮在沉稳、等待和试探阶段也可操作，因此不是有效窗口内才出现的“必中”按钮。所有实际判定仍由宿主完成；提早/空提、错过鱼口、钩饵用尽有明确提示，成功中鱼转入手动遛鱼，不显示鱼种/体型，不直接入护或发奖励。鱼护和最终结果仍只读取原业务确认投影。

## 手动遛鱼与抄鱼

`game-fight-state`按当前文档递增revision提供位置、出线/线杯余量/松弛量、张力、泄力、竿弯、鱼体力、收线状态、调节档位和收鱼阶段。长度为毫米整数，力为毫牛顿整数，活动步使用规范Int64字符串。`FightView`只复制白名单字段，俯视图没有本地物理或插值计时，不接收目标鱼种和重量。坐标超出示意范围时明确标记，不把边缘显示当成真实位置。

`game-fight`基本字段为`kind/documentId/lease/transportId/sessionId/encounterId/inputSequence/action`；动作`reel-start/reel-stop/land/retry-land`不带额外参数，`drag/speed`附整数`value`，范围0至10。每个新动作单独递增输入序号。收线按下捕获原许可和会话/遇鱼身份，快速松开不用等待按下回复；失焦、菜单、暂停、捕获丢失和页面退出均清除按住并使用原身份发送停止，换许可后的旧松开不能替代新动作。宿主仍独立处理取消和所有合法性检查。

在抛竿操作区或遛鱼示意图按住左键收线；“按住收线”按钮也支持鼠标/触摸按住及聚焦后空格或回车按住。页面不把中鱼、重新授权或恢复窗口解释成开始收线。滚轮仅在操作区/遛鱼图调整泄力，按住R时调整速度；松开R或取消交互后恢复默认含义。空格仅接受新的按下，忽略输入框、编辑区和其他按钮上下文，宿主确认具备资格才抄鱼，不会因进入范围自动入护。

收鱼待保存、已入护、容量拒绝和未知故障分别显示。只有宿主明确给出`canRetryLanding`才提供“重试原收鱼结果”，不创建新鱼身份或以补偿流程重复入护。鱼护满沿用明确放流当前鱼的路径。当前使用声明的训练抄网能力和原创简化受力规则，尚未接入背包抄网实例、断线损耗、脱钩与写实抄网动作，不表示这些系统已经验收。
