# 单竿数据与鼠标抛竿接入页

这是窗口/页面/文件与抛竿准备的整合候选，使用独立`FloatGameOwner`。页面显示余额、体力、鱼饵、当前会话和分页鱼护，并提供蓄力出手、收回、放流、选鱼出售及菜单开关。输入区域使用宿主固定目标，尚无真实水面、飞行、咬钩、遛鱼、挥竿动画或最终美术，不替换0.3.1网页和三份暂停中的UI草稿。

## 运行边界

复用`diagnostics/dual-window`现有宿主的导航、激活握手、暂停、只读桌面挂接和渲染挂起。游戏消息走独立typed命令入口，计数器仍作为旧诊断授权基础，但游戏模式不会提交计数器交易；唯一游戏存档写者是`FloatGameOwner`。

- `build.ps1 -Game`在指定仓库外私有目录构建，并复制本页。默认诊断入口仍使用旧页面。
- `DualWindowHost.exe --game-new`仅显式新建当前构建目录的`game.fltj`；已有文件时拒绝覆盖。
- `DualWindowHost.exe --game-open`只核验并打开原文件，缺失或损坏不会赠送新资金/饵/装备。
- 两个用户入口均尝试单屏只读桌面和独立交互窗口，启用原生环境查询及输入撤销；没有已有可用桌面层则拒绝启动。当前游戏页的实际可见桌面、原生鼠标和系统转换仍须独立验收。
- `--game-self-test`仅使用两个隐藏普通WebView、专用新文件与脚本消息；不操作系统鼠标、不挂桌面、不生成真实鱼情。它的前台测试旁路不会应用于上述用户入口。

测试初始配置为120银币、12饵、100体力、容量2的固定装配，鲤鱼/鲫鱼仅为接线夹具；不是36鱼产品数据库、已平衡规则或个人存档迁移。

## 消息与显示

精确来源、当前窗口/导航/文档、前台及当前wire许可先由宿主核验，再传递其保留的opaque游戏许可。页面不能提供profile/branch、鱼种/鱼重/售价、恢复命令或任意配置。收回、放流和出售保存固定request/event/session及版本，重试不能更换业务身份；页面目前单业务请求在途，没有超时自动重发或不确定补偿。原直接`game-intent/cast`入口返回`cast-preparation-required`，不能绕过准备阶段。

## 蓄力与出手

- `game-cast`只接受六个字段：`kind/documentId/lease/transportId/action/inputSequence`；动作仅`begin/release/cancel`。输入序号是正整数的规范十进制字符串，每次明确授权后单调递增。宿主消费每次新的开始序号，即使该次开始被业务条件拒绝，迟到的旧开始也不能在之后变成新的一竿。
- 页面仅发送按下、松开或取消。活动时长、力度、目标、请求与会话身份由宿主持有；蓄力使用统一活动时钟返回的时间步，保留小数毫秒，不补算暂停时间或卡顿丢弃时间。
- 松开先变为Prepared。临时宿主出手事件排队执行时，再核对原窗口、导航、文档和许可；仅新事务保存确认后发送一次`game-flight`。此事件目前表示确认出手，不表示已实现飞行动画或有效落水。
- `game-cast-state`按文档独立递增revision显示阶段、力度与输入序号。新页面只显示当前状态，不重播历史出手事件。右键、菜单、取消交互、失焦、重载、隐藏、竖屏和宿主暂停会终止未出手准备；恢复后需要重新操作。
- 鼠标快速按下后立即松开不等待网络应答，两个意图仍使用同一个输入序号和原许可。按钮替代操作也走开始/松开流程；页面没有控制蓄力的计时器。

页面只收到最小显示投影。序号、版本、金额和质量使用规范十进制字符串，避免JavaScript大整数精度损失；鱼护每页最多50条，只暴露选择所需鱼ID，不发完整资产身份、回执历史或保存路径。每个当前文档的显示包有递增revision，旧包不能覆盖新显示。

菜单暂停与宿主暂停分开：菜单暂停模拟资格，仍可按业务规则出售或放流；宿主暂停撤销输入，解除后需要重新开启交互。当前活动时钟只驱动抛竿准备，不产生渔获。正常退出显式收束；异常退出只释放并等待下次核验，不把不确定事务再写一次。
