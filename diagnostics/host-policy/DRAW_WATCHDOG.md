# 运行时绘制进度与响应看门狗

2026-10-26 16:19，北京时间。独立三维诊断宿主，不是已接通的游戏或正式保存实现。

此前活动绘制进度只在soak里检查，页面固定故障通知也可能发送失败。现在三维策略模式的宿主定时监测当前只读页，不依赖页面主动报告错误。

## 门槛与时限

宿主的StartVisual明确登记绘制意图，StopVisual、导航开始/准备重载和视图退役清除意图。只有当前Ready三维页、owner允许运行且存在绘制意图时才监测；隐藏不直接停用监测，因为独立故障测试页也是隐藏的。Ready、SDK active和页面声称running均不能代替宿主意图。

每250ms检查一次，最多一个页面状态请求。结果绑定窗口引用、文档、导航代数、绘制代数和策略版本；不匹配的旧结果/异常只观察后丢弃。暂停不累计期限，恢复/新绑定重新给宽限。旧请求尚未完成时不堆叠新请求；新绑定等待自己的宽限后仍无新遥测则保守退出，不称旧回调破坏了新页面。

当前诊断宽限为3秒：真实running且帧数增加才续期；短停顿允许，帧回退立即失败，持续停循环/计数不变分别分类；没有状态响应使用宿主单调时钟单独超时。owner已恢复但渲染器长期Pending、非active或仍挂起也有独立3秒过渡期限，不能无限停用检测。实际触发时间还受定时器和线程调度影响，不作精确响应SLA。

故障沿[SceneFault暂停与退出](../three-scene/FAULT_POLICY.md)处理，要求明确重启、不自动授权。故障文件尽力写入；即使记录失败，finally仍执行保守关闭。另有尽力退出记录用于私有验收，两份记录都失败时也不以写日志成功作为关闭前提。

## 验证

```powershell
./diagnostics/host-policy/test-draw-watchdog.ps1 -OutputDirectory <已有仓库外目录>
./diagnostics/three-scene/test-fault-policy.ps1 -SdkDirectory <SDK目录> -OutputDirectory <已有仓库外目录> -WatchdogCase silent-stop
# 另可选择 stale-flag / no-response / transition-pending / record-failure
```

16项纯模型检查通过，涵盖边界宽限/进展续期/短停顿/停循环/帧回退、故障锁定、重置、暂停重基准和非法时间/计数。

五种真实宿主检查及原上下文故障回归均通过，每轮先验证3.5秒正常暂停（长于宽限）和重载后的新监测，再注入：

| 模式 | 实际做法与边界 | 检测结果 |
| --- | --- | --- |
| silent-stop | 只停止自身页面绘制，保留宿主意图，不发送故障通知 | draw-loop-stopped |
| stale-flag | 停止自身绘制，但测试替换状态接口仍声称running | draw-progress-stalled |
| no-response | 自身WebView脚本忙循环8秒，原生宿主线程保持运行 | draw-response-timeout |
| transition-pending | 真WebView先正常运行，再用明确的测试后端返回不完成挂起任务 | draw-renderer-transition-timeout |
| record-failure | 私有故障报告路径用同名目录阻塞，然后静默停画 | 正常关闭，recordWriteFailed=true |

过渡例不等于真实SDK损坏，记录例不等于实际磁盘满；无响应例不等于驱动或原生UI线程挂死。五轮各以预期故障码4结束，SceneFault阻止活动/旧命令；计数新进程确认1/7保持、旧lease拒绝和原请求去重，退出0。五轮及原画布通知轮均无强制清理/专用进程残留。新进程仍只是计数owner检查，不是完整游戏恢复。

正常三维210.93秒31项通过：103心跳、55个soak进度区间、运行时490样本/496请求/5个旧结果丢弃，一次重建、七次三维文档加载，最终重建页再次取得几何/像素证据；退出零残留、无强制清理。二维挂起/恢复21项另通过。该轮资源仅取到18.23秒/6样本即owner结束，不作为正式性能结论，长轮另补。

## 限制

检测的是预期活动状态下的绘制回调进展、页面响应和协调过渡，不证明物理显示呈现、场景内容确实变化或GPU/驱动没有冻结。加载中/未Ready的导航不属于本监测期，也不监测任意外部进程；原有导航错误和独立测试期限保留。最终游戏、全屏、多屏、锁屏/休眠及冷启动仍需对应实机验收。3秒是诊断配置，尚不是发行版调度预算。
