# P0 可用视图与活动时钟

这是双窗口诊断宿主的策略，只有显式宿主策略模式启用。当前并未接入钓鱼游戏，也不把此规则视为正式游戏所有视口/渲染器的最终调度方案。

| 当前宿主状态 | 可用性原因 |
| --- | --- |
| 没有窗口 | `NoViews` |
| 有窗口但没有当前已就绪页面 | `RendererUnavailable` |
| 至少一个当前页面就绪 | 不添加上述两个原因 |

由唯一 owner 的 UI 线程在窗口加入/退休、导航开始、显式重载准备和页面就绪时更新。两个原因原子替换，避免从无窗口变为未就绪窗口时短暂恢复。它们不清除启动、手动、会话、电源、显示等其他原因；启动阶段仍要等初始两页都就绪。

只读页重建而交互页仍就绪时，不额外撤销原本有效的交互 lease；现有恢复测试继续覆盖这个行为。没有任何当前就绪页时则停止 owner 的诊断活动时钟、拒绝修改，并保留同一个 owner、写锁、提交序号和去重记录。新页面就绪只恢复活动资格，不自动授权。

该策略不等于对所有加载中的 WebView 强行挂起。导航要继续执行才能变为就绪；活动时钟暂停、脚本绘制暂停和 SDK 挂起分别观察，不能由一个标志推断全部进程降载。
