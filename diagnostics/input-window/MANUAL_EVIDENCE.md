# 有时限的输入记录与启用确认

本诊断只运行普通输入窗口，不加载游戏、不嵌入桌面、不记录按键内容。输出、浏览器 profile 和原始事件全部留在仓库外。

```powershell
./diagnostics/input-window/run-manual.ps1 -SdkDirectory <SDK目录> -OutputDirectory <已有仓库外目录> -Seconds 300
node diagnostics/input-window/summarize-manual.mjs <本轮目录> --operator-confirmed
# 不显示/激活窗口，只验证到时退出；不会作为手动输入验收。
./diagnostics/input-window/run-manual.ps1 -SdkDirectory <SDK目录> -OutputDirectory <已有仓库外目录> -Seconds 60 -UnattendedTimeoutCheck
```

时间范围60至600秒，结束或收到本轮私有退出请求时正常关闭。程序只在自己的窗口内接收输入，不注入事件、不设置全局热键。首次显示不请求前台激活，实际测试须由操作者点进窗口，再按 F8 或点击启用按钮。

## 修复焦点交接竞态

旧流程在 `view.Focus()` 前生成启用命令，命令携带的取消代次可能落后于焦点交接触发的页面 blur。页面安全拒绝了该命令，表现为按 F8 后依旧不能操作。

新流程先把焦点交给自己的 WebView，再请求当前页面确认。确认绑定显式请求、当前窗口标识、文档和导航代次；页面回传当前取消代次及焦点状态，宿主再次核对真实前台后发放带请求标识的命令。确认前发生的焦点交接取消可被最新确认覆盖；确认后的取消、失焦、导航或关闭仍使请求失效。页面只接受自己当前准备过的请求，原有代次/版本检查没有放宽。

该流程复用双窗口组件的 `ActivationHandshake`。旧已发放请求的取消只处理对应请求，不误杀后来开始的新准备；不自动重试启用，也不在切回窗口时自动开放输入。

## 汇总边界

汇总要求正常退出、无强制清理、专用子进程残留0及操作者明确确认；还须逐项获得浏览器可信事件：左/右/中键在同一文档内配对、滚轮、普通键，以及左键按住后取消并返回时保持关闭/按住0。取消清空不当作真实抬键，累计计数不替代事件。缺项保持未完成，操作确认不能补齐缺失数据。

输入文件/祖先不得为链接，单文件上限16 MiB；核对本轮输出目录，拒绝逆序时间、文档内计数回退及不一致快照。输出只含固定标签、计数和结论，不含文档标识、坐标、按键内容或原始消息。DOM trusted 与人工确认仍不等于证明物理硬件来源，验收只限本普通窗口，不推断桌面图标、右键菜单、穿透、多屏或钓鱼操作。

运行脚本的 `nativeInputAccepted=false` 是默认不替用户做验收；离线整理另用 `ordinaryWindowInputAccepted` 表示完整证据是否满足。无人操作模式拒绝附带人工确认。
