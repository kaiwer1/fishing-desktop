# P0：单一状态持有者与双视图诊断

此目录验证一个独立计数器：C# 宿主持有唯一可修改状态，两个真实 WebView2 页面接收同一份已提交快照，其中壁纸视图只读，交互视图只有得到宿主当前授权后才能发出修改请求。诊断不加载游戏，不读取游戏或个人存档，也没有接入鱼获、货币、装备等业务。

目标是检查未来“壁纸负责展示、交互窗口负责操作”候选方案中的重复请求、旧页面消息、重新加载和进程重启问题。当前宿主仍是普通 WinForms 窗口；这个验证没有把窗口嵌入桌面、连接 Lively，或完成正式游戏存档方案。

## 状态与命令约定

- `ViewAuthority.cs` 在创建它的宿主线程上串行处理操作。两张页面持有快照，不各自运行模拟，也不自行保存计数器。
- 每次宿主启动产生新的 `OwnerId`；每个页面实例有自己的 `documentId`。重新加载后旧页面身份和旧授权失效。
- 交互授权使用 `lease`。显式启用会替换旧授权，撤销、失焦和重新加载使后续旧命令被拒绝。只读页面始终不能提交修改。
- 页面通过 `LeaseSession` 跟踪单调递增消息版本和本地取消代数。取消前排队的启用消息不能在返回页面后恢复交互；页面发出的撤销请求必须匹配宿主当前视图和授权，迟到的旧撤销不能取消新授权。
- 新请求需要匹配 `expectedSequence`。相同版本下排队的两个不同请求只接受第一个，第二个取得新快照后才能另行提交。
- `requestId` 为标准小写 Guid D 格式，`delta` 为 1 至 1000。相同 ID、相同内容重试返回原回执，不再累加；相同 ID、不同内容被拒绝。旧请求的去重查询先于版本冲突检查，但仍要求有效页面和当前授权，不能借重试绕过控制权验证。
- 写入结果不确定时停止接受修改，显式重启并读取日志后恢复。失败实例的内存值仅反映之前已确认状态，不能作为自动重试成功的依据。

## 持久化范围

`DurableCounterStore.cs` 以独占写入句柄持有一个 JSONL 文件，允许其他句柄只读，拒绝其他写者。每条记录包含版本、请求 ID、增量、连续序号、结果值、前条校验和及本条 SHA-256。规范编码、数字关系、重复 ID 和校验链在打开时全部检查。

追加记录之后调用 `FileStream.Flush(true)`，成功后才向调用方返回确认回执。Microsoft 文档将该重载用于刷新文件流及中间文件缓冲区；本项目实际验证的是调用顺序与受控进程恢复，没有据此推断真实断电可靠性。[FileStream.Flush(Boolean) 官方文档](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.flush?view=netframework-4.8.1#system-io-filestream-flush(system-boolean))。

尾部恢复采用以下规则：

| 发现的内容 | 处理 |
| --- | --- |
| 带换行的完整记录损坏 | 拒绝打开，保留原字节，不重置为空存档 |
| 完整且验证合法的最后一条记录缺少 LF | 保留记录和原去重回执，补 LF 并刷新 |
| 无 LF 的完整记录校验、链、数值或格式错误 | 拒绝打开，保留原字节 |
| 能由当前记录格式产生的未完成规范前缀 | 先将精确尾字节写到同目录的 `.incomplete-tail-<guid>.bin` 独立备份并刷新，再截断该片段 |
| 非规范片段、非法 UTF-8、超长尾部 | 拒绝自动修复，保留原字节 |

本格式由 ASCII 字段构成，因此半个 UTF-8 字符不会被当作本实现正常产生的未完成写入。完整记录缺 LF 的回归测试先成功提交两次，再移除最后一个换行，验证重开后累计值和旧请求回执都保留。

## 运行

要求 Windows x64、系统 .NET Framework 编译器、Node.js，以及已安装的 WebView2 Runtime。WebView2 编译引用使用解包后的 `Microsoft.Web.WebView2 1.0.3405.78` SDK。只运行存储及授权测试时不需要 WebView2 SDK。

在仓库根目录执行下列 PowerShell 命令。路径示例使用仓库旁的私有 `tools/` 目录；如本机位置不同，修改 `$taskOutput`、`$taskSdk`。所有输出目录必须在公开仓库之外，并在执行脚本前存在。

```powershell
$taskParent = Split-Path (Get-Location).Path -Parent
$taskOutput = Join-Path $taskParent 'tools/temp'
$taskSdk = Join-Path $taskParent 'tools/webview2-sdk-1.0.3405.78'
New-Item -ItemType Directory -Path $taskOutput -Force | Out-Null

& ./diagnostics/state-owner/test-store.ps1 -OutputDirectory $taskOutput
& ./diagnostics/state-owner/test-authority.ps1 -OutputDirectory $taskOutput
node --test ./diagnostics/state-owner/lease-session.test.mjs
& ./diagnostics/state-owner/test-webviews.ps1 -SdkDirectory $taskSdk -OutputDirectory $taskOutput
```

各脚本在私有输出目录下建立新的运行子目录，生成可执行文件、JSONL 计数日志、修复备份和测试报告。WebView 测试还产生独立浏览器配置目录；源码仓库不保存这些产物。

`test-webviews.ps1` 编译宿主，先运行一次双页面协议验证，再启动同一测试目录下的宿主检查重启去重。`--self-test` 模式的窗口不可见且不抢焦点；测试通过页面脚本与真实 WebView2 消息通道发送命令，并不模拟鼠标操作。脚本只清理自己启动的宿主进程，并等待该私有配置目录对应的 WebView2 子进程退出。

如需单独构建普通可见窗口，可为 `build.ps1` 指定新的私有输出目录，随后手动打开该目录中的 `StateOwnerProbeHost.exe`。窗口上方提供 `Enable interaction`、`Observe / cancel` 和 `Reload interaction`。测试宿主与此前输入候选宿主共用当前 Windows 会话的单实例门禁，同一时刻只能启动其中一个；这不是生产版跨会话或跨所有宿主的状态协调方案。

## 已执行验证

以下结果来自本机受控诊断，不代表桌面壁纸的完整验收。

| 层次 | 实际结果 | 主要覆盖 |
| --- | --- | --- |
| 文件与计数器测试 | 22 项通过 | 去重、内容冲突、重开、写者互斥、坏完整行拒绝、缺 LF 保留记录、先备份再截断、9 个字段边界的未完成前缀、受控写入失败、10000 条上限 |
| 真实独立进程 | 4 项通过 | 首进程持锁并提交、第二写者被拒绝、正常退出重开去重、强制终止后重开去重 |
| C# 状态授权 | 16 项通过 | 只读视图、授权交接、旧页面、条件撤销、迟到撤销、版本冲突、跨线程拒绝、重启去重、不确定写入停止接收 |
| 页面授权状态机 | 9 项通过 | 默认关闭、本地取消、迟到启用、消息版本、页面身份、错误输入与代数上限 |
| 真实双 WebView 协议 | 首轮 9 项、重启 4 项通过 | 同一状态持有者、无授权拒绝、只读拒绝、发布快照、请求去重、冲突拒绝、重新加载与撤销；迟到旧授权撤销不影响宿主及页面当前授权 |

存储异常测试包括固定边界回调抛错，以及关闭实际 `FileStream` 后触发写入或刷新时的 `ObjectDisposedException`。`after-flush` 回调失败检查“已写入但还没有返回确认”时重启重试不会重复累加。强制进程终止发生在已完成提交之后，不能当成写入过程中断电测试。

## 尚未覆盖的可靠性与产品要求

- **这不是游戏存档。** 尚未接入业务数据、真实模拟时钟、经济事务、版本迁移、备份轮换或保存位置选择。
- **没有真实断电或磁盘故障证据。** 未测试系统崩溃、设备断电、磁盘满、硬件 I/O 错误和控制器缓存故障；关闭文件句柄的测试不等于这些情况。
- **日志整体截短或文件丢失无法识别。** 删除整个末尾记录仍可能留下合法链；文件不存在时会新建空日志。若已确认记录被人为截成一个合法未完成前缀，仅凭该文件无法区分它与中断追加；修复会保留尾片段备份，但没有独立提交高水位来证明是否发生回退。
- **日志最多 10000 条。** 达到上限后新请求返回 `journal-full`，保持授权及正常读取，旧 ID 仍可去重；当前没有压缩或归档。容量拒绝发生在写入前，不按不确定持久化处理。上限测试读取预制的合法 10000 条日志，没有执行 10000 次逐条持久化刷新或长期性能测试。
- **校验链不提供认证。** SHA-256 用于发现意外变化，不能阻止有文件修改权限的人重写整条链。
- **写锁保护同一个文件。** 不同目录中的两个日志不会自动合并，也没有完成跨 Windows 会话、其他程序或真实游戏宿主的唯一写入协调。
- **不可见协议测试不代表原生输入验收。** 未据此验证真实左/右/中键、滚轮、拖动、按住后切窗、桌面图标或桌面右键菜单。真实桌面层、Lively 输入转发、多屏、DPI、显卡负载和长期资源占用仍需各自验证。

当前 P0 能据此继续比较宿主与共享状态方案；不能仅凭这些结果宣称正式存档、游戏流程或桌面输入已经完成。
