# 鱼类与渔具建模交接

2026-10-27，北京时间。用户明确：鱼类范围为**中国内陆淡水鱼和海洋鱼类**，要求向 ZCode 回复建模需求。写实风格、RX 580 8GB / 16GB 内存及横屏要求沿用项目约定。

本文件是资产准备与交接规格。下列具体鱼种、数量和资源预算由 Codex 提出，是首批建议；用户尚未逐种确认，也没有批准 Tripo 或其他生成服务的付费金额。当前仍按既有 P0→后续阶段推进，不恢复暂停的界面/钓鱼流程，不把建模准备当成海钓或模型接入已完成。

## 范围与建议批次

- 淡水覆盖中国内陆江河、湖泊、水库；海水先以中国近海岸钓/海钓为方向，后续可扩展远海。近海优先是本次实施建议，不把用户的海洋范围永久限制为近海。
- 不照搬旧原型的拟鲤、丁鱥、河鲈、白斑狗鱼、雅罗鱼清单。旧 `src/content.js` 是机制占位内容，不代表新的采购/建模清单；未来替换需另做 ID、图鉴、水域和存档迁移。
- 每种先做 **1 个基础模型**，不是一次生成多条鱼。场景里的个体数量、体长及有限外观差异由后续实例化处理；不能把同一基础网格换色当作不同鱼种。
- 第一批先检验 **鲤鱼 1 个、黑鲷 1 个**，检查形态、材质、尺度和浏览器导入。样本通过后再扩充，当前不要求立即发起任何计费生成。

## 导出与暂定资源预算

以下是用于控制第一轮样本规模的**建议上限/范围**，不是 RX 580 性能已经达标的结论。以导出后的三角形数计数，不能拿四边面数直接代替。导入样本与实际测量后可修订。

| 对象 | 近景 LOD0 | LOD1 / LOD2 | 贴图建议 |
| --- | --- | --- | --- |
| 单条鱼 | 8,000–20,000 三角形 | 3,000–6,000 / 500–1,500 | 一套最高 2K；低档可降 1K，通常 1–2 个材质 |
| 一套竿＋轮 | 合计 15,000–35,000 三角形 | 约 6,000–12,000 / 2,000–4,000 | 最多两套 2K；竿和轮可独立复用 |
| 双手＋前臂＋袖口 | 合计 15,000–25,000 三角形 | 按第一人称可见需求另定 | 一套 2K，袖口可独立材质 |
| 单件小配件 | 200–2,000 三角形 | 依屏幕占比裁减 | 共用 1K 图集优先 |

- 运行时首选 **glTF 2.0 的 `.glb`**，贴图打包，不引用失效外部路径。另保留可编辑源文件；有整理过的 Blender 工程交 `.blend`，FBX 可作中间交付，但不是唯一成品。
- PBR 材质至少整理 base color、roughness、normal；金属度仅用于适合的部件。鱼皮不设成整块镜面金属，鱼鳍透明尽量减少排序问题；是否压缩纹理由后续导入工具链决定。
- 单位为米、Y 向上。鱼头朝本地 +X、尾部朝 -X，根节点位于体躯中央；登记吻端到尾鳍末端的参考长度。竿沿本地 +Y（竿尾到竿尖），根位于主握持处。源文件中应用缩放/旋转，导出后尺寸可复核；最终适配器负责装入游戏坐标系。
- 鱼至少划分可调整的尾部、主要鳍与口部；需要游动时另做骨架和蒙皮。AI 生成几何不自动视为已完成重拓扑、UV、骨骼或动画。可先交静态模型，但必须明确标记状态。
- 渔具拆出可动线杯、摇臂和手臂骨架；竿身支持后续分布式弯曲。握持、竿尖、导环、出线和挂钩节点要有明确命名；不能把渔轮、手、竿全部焊死。
- 动作接口与质量以 [模型与动作质量门槛](VISUAL_MOTION_TARGET.md) 为准。这里不承诺生成 API 能直接产出合格抛竿动作。

## 交付、来源和验收

1. 每项附资产 ID、准确物种/装备类别、参考长度、三角数、材质/贴图数量和尺寸、LOD、是否已绑定/动画、文件清单和导出版本。
2. 原创建模或有明确使用范围的素材；不提取、转发或上传 RF4 模型/贴图作为生成输入。生成服务的产物使用条件、参考图许可和费用另记，不以“AI 生成”替代来源登记。
3. 先在 ZCode 自己的交付目录准备文件和清单，并告知实际路径；不要覆盖本仓库 `src`、`public`、暂停中的 UI 草稿或其他代理正在编辑的文件。由本项目后续单独审查并导入。
4. 静态样本先检查准确物种形态、真实比例、UV/材质、GLB 导入与资源数量；动作样本另检查握持、关节/鳍变形、出线同步及真实帧时间。漂亮缩略图不替代模型验收。
5. **付费预算未定**：先提交当前报价、计费单位、预计模型/重试/绑定/导出等费用及总上限，等待实际付费授权。未给出价格不填 0，也不把这份清单当作付费批量生成授权。
