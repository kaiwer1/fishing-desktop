# R1：浮漂咬钩、提竿与鱼饵状态

2026-10-28 实施补充：[最小固定步模型](../desktop/game-core/BITE_MODEL.md)及宿主/页面接线已实现，29项纯模型、41项页面、28项隐藏WebView和17项暂停回归通过。当前只接鲤/鲫、蚯蚓、静止平面水域，统一50毫秒活动步、有限漂相曲线、一次遇鱼/提竿、失饵后收竿；没有完整生态、水深/装配平衡、风浪或自然收鱼。下文仍是整体合同与历史基线，不能将全部验收视作已完成。

2026-10-26。待实现的原创规格，接续[抛投](CASTING_FLOW_SPEC.md)、[装配消耗](FLOAT_RIG_ASSEMBLY_SPEC.md)和[遛鱼](FIGHTING_MODEL_SPEC.md)。首版只规定一套带轮浮漂，不借此开放底钓、路亚或三竿。

## 已知范围与当前差异

[模块调查](RF4_MODULE_RESEARCH.md)确认接近鱼饵、下拉和咬钩检测相关类型存在，尚未恢复其启用路径、转换条件、鱼口时长、客户端/服务端职责或概率。用户截图和录屏可用于核对漂相与操作节奏，不能提供原版数值。以下状态、概率积分和提竿判定均是本项目设计，参数须另作自研配表和试玩调参。

0.3.1在等待阶段累加`exposure`，达到一次随机阈值后选择鱼种/体型，直接进入`bite`，用提示与倒计时接受提竿；65秒未咬自动结束，首鱼有辅助规则。未来增加接近、试探和有效吞饵阶段，使用实际漂相反馈。无鱼口不默认65秒自动收竿；首鱼辅助须成为明确、持久化且可关闭的辅助配置，不能通过刷新或切图重复触发。这里没有修改现有代码。

## 数据与状态合同

每一竿延续出手会话`sessionId`及锁定装配/鱼饵版本；每轮搜索有`searchEpoch`、独立种子流和危险率阈值，实际问饵有唯一`encounterId`。遇鱼后锁定鱼种、体型、行为配置及来源条件，提竿、菜单或窗口重建不得重新抽取。鱼种名称和准确重量不在漂相阶段提前公开给玩家；诊断信息与公开视图分开。

| 状态 | 进入与推进 | 输入和退出 |
| --- | --- | --- |
| `settling` | 已确认有效落水，钓组按自身配重/漂深进入稳定工作状态 | 可主动收竿；尚无有效鱼口，提竿只执行规定的空提/收束，不生成鱼 |
| `searching` | 有可用钩饵、有效水深和目标池，按活动固定步累计搜索暴露 | 可调允许的漂深/控线或收竿；改变条件更新后续搜索率，不重抽当前阈值 |
| `approaching` | 一次搜索触发后锁定遇鱼，鱼接近已落水钩饵 | 接近可被水域约束或配置的惊扰打断；不授予鱼，不反复重抽体型 |
| `nibbling` | 试探动作改变浮漂/线组状态，可短暂顶漂、下压或侧移 | 尚未进入有效提竿区间，空提按该钓组规则收束；不把所有轻动都当有效咬钩 |
| `strikeable` | 已配置的吞饵/连接条件成立，记录有效模拟步区间 | 当前有效右键在窗口内提交一次中鱼，转入遛鱼；过期进入`missed` |
| `missed / interrupted` | 有效鱼口错过、空提或惊扰结束该遇鱼 | 依据钩饵状态返回搜索或进入必须收竿；旧遇鱼的迟到命令无效 |
| `retrieve-required` | 鱼饵已脱落/钓组失效，不能再问饵 | 给出原因并允许收竿；不自动补饵、不继续隐形累计咬钩 |

所有时长、漂相强弱与状态转换条件按钓组/鱼种配置，不能把类型名直接当成固定顺序的原版脚本。首版采用上述有限状态链；若配置允许跳过试探，必须明确声明，不能漏状态后误进入无限等待。

## 搜索、目标与概率边界

使用owner的活动固定步时钟，独立于绘制帧率。搜索率由本项目水域/鱼种池、落点深度、饵适配、模拟时段及压力等已配置条件计算。参数缺失与明确的零鱼口率分开处理；负值/非有限值拒绝，明确零率保持等待，不编造保底鱼。

每轮搜索从种子流取一次`u`，严格限制到开区间(0,1)，目标累计危险量为`-ln(1-u)`；每个固定步累加`rate × stepSeconds`，超过目标时仅触发一次接近。该公式是本项目原创搜索抽样，不是RF4概率恢复。新环境条件只改变后续增量；打开菜单、改分辨率、重新加载只读页不重置累计量或阈值。种子/阈值与活动会话由owner持有，视图不参与抽样。

触发时只在当前合法鱼种池按自研权重选择目标并锁定体型，空池不创建遇鱼。环境在接近过程中失效时按明确中断规则结束该遇鱼，而不是偷偷换成另一个鱼种；搜索是否重新开始及其新epoch记录在状态中。此为轻量遇鱼模拟，不声称存在完整逐条游鱼或RF4服务器鱼群。

## 漂相与提竿

浮漂基础平衡来自漂/沉子/钩饵装配、水深与出线，风浪扰动只作为已声明的环境分量；问饵动作叠加本项目有界位移/速度曲线。曲线以模拟步推进，渲染插值；不能用每帧随机摆动决定咬钩。风浪本身不打开提竿窗口，动画丢帧也不能缩短或延长窗口。

提竿有效区间采用`[openStep, closeStep)`；owner接纳动作的模拟步为准，忽略页面声称的过去时间。边界与当步终结顺序写入模型版本。同一有效右键只消费一次，重复/旧会话/旧授权动作不创建第二份搏斗。空提、过早、过晚分别返回可理解原因；不能把窗口外点击缓存成下一轮自动提竿。

有效提竿验证装配仍可用、钩饵状态、遇鱼未结束以及连接条件。成功沿用原`encounterId`进入唯一搏斗会话，不再抽鱼，不自动开始收线。提竿时长、抬竿动画、竿尖与线的同步属于P3/P4/P10接口；动画表现不能回写已确认的中鱼时点。

默认以漂相为主要信息，辅助提示可由明确设置开启；辅助只改变提示，不改变有效窗口、目标鱼或奖励。首版辅助功能未实现前，不能用常驻“必中”按钮替代鼠标提竿验收。

## 鱼饵、暂停与恢复

出手已从库存扣除一份饵，钩上的饵是这份已提交消耗的在用状态，不是库存里另一份可用物品。记录`attached / depleted`；鱼试探、错过或空提后是否失饵由原创配置决定，并使用遇鱼事件ID只处理一次。失饵不再从库存额外扣一份，也不把已扣鱼饵退回库存；重新挂饵走结束当前会话及新出手的规则。保留钩饵的错过可返回搜索，新epoch可追踪，不能保留旧有效提竿窗口。

菜单、宿主暂停、失焦等依据统一输入/暂停合同冻结搜索、试探、窗口与鱼动作，清除按住/缓存提竿；恢复后重新操作，不计算墙钟间隔、不补发鱼口。切图与换件仍按活跃会话限制。若以后某菜单允许会话继续计时，须另行修改统一合同，不能由某一个页面擅自继续。

首版重启仍按`recovery-retrieve`结束未完成的已提交垂钓，保留确认消耗、不授予鱼或奖励；不在重启时保存一个过期鱼口并自动中鱼。已确认搏斗/终结回执优先，迟到的咬钩动画不能把它改回等待。正式P1持久化尚未实现，本规格不宣称已通过断电或存档故障验收。
