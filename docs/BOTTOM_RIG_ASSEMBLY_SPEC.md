# R1：简单底钓与饵笼装配合同

2026-10-26。面向P5的待实现原创规格，依赖P1正式保存、P3抛投与P4遛鱼；本文件没有恢复暂停的游戏/UI开发。继承[装配归属](FLOAT_RIG_ASSEMBLY_SPEC.md)、[抛投](CASTING_FLOW_SPEC.md)、[输入](INPUT_RIG_SPEC.md)、[库存交易](INVENTORY_TRANSACTION_SPEC.md)、[遛鱼](FIGHTING_MODEL_SPEC.md)、[咬钩](BITE_PRESENTATION_SPEC.md)及[三竿/竿架](MULTIROD_STAND_SPEC.md)合同；下文只为底钓补专用规则，不把浮漂专属配重或漂相套到底钓。

## 依据与首版范围

[RF4模块调查](RF4_MODULE_RESEARCH.md)确认`RigBottomSimple`、`RigBottomPaternoster`、`RigBottomInline`等类型及饵笼资源分类，局部底钓初始化关联基类/鱼线辅助方法，竿架槽位关联报警器和锚点。类型与字段关联不证明连接顺序、装配兼容、沉底/自刺鱼、消耗、信号阈值或公式已经恢复；原版真实参数仍未知，不再解码或复制原文件。

已核对[src/content.js](../src/content.js)、[src/game.js](../src/game.js)及[src/ecosystem.js](../src/ecosystem.js)：0.3.1只有型号级竿/线、单份钩饵、单会话和原创落点深度/鱼群权重，没有独立渔轮、沉子、饵笼、笼料、底质/触底或竿架。旧鱼种/鱼饵适配不能当作已支持底钓，现`depthAt`也不是可碰撞河床。

首版只开放同一简单单钩底钓结构的两种明确模式：`bottom_simple`使用一件普通铅坠，`bottom_cage`将该末端配重换为一件饵笼。均手动提竿，不支持自动自刺鱼；饵笼空投、Paternoster/Inline/Method/鲤钓、浮动饵、多钩、防缠绕复杂连接、走水漂移、绕障和架上搏斗延后。未支持组合明确不可用，不以改名称共用浮漂等待冒充完成。

## 实例、单位与装配兼容

| 槽位/数据 | 首版要求与不变量 |
| --- | --- |
| 竿与渔轮 | 各一件独立实例；目录明确支持相应底钓模式、连接类别和承载状态，不能按“更贵/更强”推断兼容 |
| 主线 | 当前渔轮中同一`LineSegment`，线径/类别/容量与允许放线规则完整；不另生成顶层主线副本 |
| 前导线与鱼钩 | 一件有效前导线及一件兼容单钩；长度、连接类别和钩饵允许表明确，不从RF4名称猜钩号或距离 |
| 末端配重 | 普通模式恰好一件铅坠；饵笼模式恰好一件饵笼，两者互斥，不再额外挂一件隐形沉子 |
| 钩饵选择 | 一个具体鱼饵堆叠引用，真正出手至少一份；钩上在用饵属于已确认消耗，不是库存副本 |
| 笼料选择 | 仅饵笼模式必需：具体配方/批次堆叠、正整数份数、每份整数质量；选择不提前装填或扣料 |
| 饵笼参数 | 空笼质量、允许料类、容量/装填范围、释放规则、连接/阻力及损失规则；每项都显式配表 |
| 报警附件 | 可选独立实例，首版只接一种配置完整的铃铛/报警器；明确装于竿或槽位的唯一归属与锚点，不同时出现在两个位置，未接通的设备不可启用 |
| 会话扩展 | 同一`sessionId/rigRevision`、模式、笼料来源/提交质量、当前剩余/释放/损失量、触底状态、遇鱼和信号序号；不另造“饵笼会话” |

装备实例、位置、版本和容量沿用库存合同：实例在库存/槽位/容器中只归属一次，整套竿在收纳/手持/竿架槽位间也只有一个位置。型号不代表拥有，饵笼装上后不能再作为另一件库存可售物品。

资产长度用整数毫米、线径用整数微米、质量用整数毫克，笼料以整数份数和固定每份质量入账；余量/沉积质量同样为毫克，不能每帧浮点扣一份。运行时几何/速度/拉力沿用P4米、米/秒、牛顿，保留量化余数，确认事件才按统一规则转回资产。体力仍是固定整数刻度，不以质量替代力。

`ValidateAssembly`允许缺件装配保存，但拒绝已有部件类别/连接冲突、重复归属或非法数值；`EvaluateCastReadiness`另检查全套完整、可用耐久、钩饵/笼料、体力、技能资格、线量、目标域及规则。总抛投质量明确包含末端配重、当前装料与其余目录规定部件，按竿的允许范围校验，不复用浮漂沉子配重区间。

线杯容量、前导线长度、饵笼容量、料量、沉底速度/稳定条件、底质承载、信号/提竿和失败损失均须有本项目版本化规则。缺参数返回`configuration-missing`，区别于已配置但不兼容、缺件或明确零鱼口；不能填零质量、无限线长、免费笼料、必触底或必中。

## 出手、钩饵和笼料消耗

蓄力→松键→准备出手沿用原抛投身份；开始时记录装配/选择版本，松键冻结力度与目标。底钓出手仅由当前手持竿接受，架上不能遥控蓄力。修改装配/笼料选择须无该竿活跃会话；准备阶段先确认取消，已出手后按收竿/终结处理，不凭切竿、开菜单或换件退资源。

`CommitCastRelease`再次校验会话、装配、钩饵与笼料具体批次/数量、规则、体力及可写性；同一事务扣一份钩饵、规定体力，饵笼模式另扣所选整数份笼料，记录提交装料质量、会话已出手及回执。普通模式没有笼料成本/效果。两类消耗必须一起成功，最后一份料或饵被其他竿先用时整笔拒绝，不能只扣钩饵或偷偷换批次。

同请求同内容返回原结果，同ID改内容拒绝；新请求ID不能重用已提交`sessionId/releaseEventId`。确认前不飞行，动画回调只提供一次合法触发。出手前取消/校验失败零消耗；已提交后落点失效、受阻、空提或主动收竿保留已扣饵、料和体力，不自动返还“没来得及撒”的装料。

笼料在出手时一次扣库存，之后`loadedMass = remainingMass + releasedMass + lostMass`守恒；释放不再扣库存。首版只有有效触底稳定后按固定步释放，剩余料在正常收竿/失败时按规则计为弃置，不回包、不跨新一竿免费续用；报废饵笼的未释放料也仅记录一次损失。取放竿和切手持不重新装填。

钩饵仍记录`attached/depleted`；试探/错过是否失饵按底钓规则和遇鱼事件确认一次，失饵不额外扣库存。钩饵耗尽进入`retrieve-required`，笼料有余也不能继续生成有效咬钩。笼料耗尽不等于钩饵耗尽：保留合法钩饵时可继续以无新增饵笼效果搜索，不自动补料。

## 飞行、沉底与局部饵料作用

| 底钓状态 | 进入/推进条件与退出 |
| --- | --- |
| `casting`飞行 | 已确认出手；轨迹/碰撞/放线属于同一钓组。无效水域或路径明确失败，不转成等待 |
| `settling`沉底 | 有效落水后按配置向本落点河床下降；检查水深、剩余线、底面和稳定性，无遇鱼/释放有效窗口 |
| `searching`至`strikeable` | 实际触底且稳定、钩饵可用才接入本钓法搜索/问饵；不是固定延时后无条件到位 |
| `retrieve-required` | 钩饵耗尽、底面/工作域失效等原因不能继续问饵；允许明确收竿，不能悄悄重投 |
| `hooked`以后 | 有效手动提竿后接P4同一搏斗/收鱼链；未完成终结前不创建第二次出手 |

P5首版只在有明确底面高度、底质、坡度/承载、深度与障碍标签的少量平缓静水钓区开放。水深来自实际水面/河床采样，钩饵高度由末端接触点和前导线规则求得；不能仅以地图名、屏幕落点或既有鱼种偏好深度当触底证明。沉降/稳定最大活动步数明确配置，超限报告具体原因并收束，不留无限下沉。

底质类别通过显式适配/可达表影响能否稳定、钩饵可见性和后续搜索条件；泥底埋陷、草底遮挡等首版不模拟的区域排除或明确不可用，不编造真实陷深。线量必须足以覆盖实际有效路径及允许松弛，放线/收线守恒；环境未知或几何求解非有限则故障暂停，无免费鱼或伪装断线。

饵笼释放生成有限质量、版本化位置/范围/有效期的局部沉积，归属当前水域和来源会话；仅修改已经配置的合法鱼种搜索率/权重，不生鱼、不保证鱼口，也不替代钩饵适配。每源累计释放、沉积和衰减可对账；重入触底不能重复投放。具体半径、释放率、衰减与叠加上限是原创参数，不能照抄未知RF4数值。

三竿共享沉积按三竿合同先取共同环境快照、各竿算候选、统一归并，下一固定步才对附近各竿生效；相同来源不能各自复制三份，重叠按明确上限组合。释放与世界沉积保存为同一确认检查点，不能只恢复源料余量或只恢复沉积；重启不重播未确认释放，不从旧出手重复生成整笼效果。P7更完整打窝/水流扩散另立规则。

## 咬钩报警、手持与竿架

底钓专用`approaching/nibbling/strikeable/missed`使用咬钩合同的身份、危险量搜索、独立随机流及`[openStep, closeStep)`动作边界；状态条件/曲线由底钓配表，不显示浮漂或照搬浮漂幅度。搜索阈值不因切竿、看菜单或信号动画重抽；遇鱼时锁定同一鱼种/体型，提竿和取竿不重抽。

竿尖/线的可见变化来自owner本竿确认状态，风浪/沉降/松线只产生各自环境分量，不自动打开有效提竿窗口。铃铛或报警器读取绑定槽位/本竿的线/竿尖变化及阈值，生成带`rigId/sessionId/signalSeq`的信号；音频/灯/界面提示不决定中鱼，不给页面泄露准确鱼种/重量。未装报警器仍可看竿尖，但不能享受虚构已购功能。设备安装/拆卸沿用活跃引用限制，取竿造成的绑定更新随位置提交一次完成，空槽不能继续发旧竿信号。

提竿必须当前竿已合法手持、控制代数有效、遇鱼仍在窗口且装配/钩饵可用；一份新右键只提交一次中鱼，不自动开始收线。架上报警只提示稳定槽号，不抢镜头、不自动提竿；按E或1/2/3取回仍需另一次有效右键，取用时间不冻结该竿窗口。过早/过晚/旧竿命令不能缓存成下次必中。首版空提按明确底钓规则结束本次遇鱼并要求收竿；未提竿错过则按钩饵保留/耗尽返回新搜索epoch或必须收竿，不能遗留旧窗口。

取放和位置提交严格复用三竿合同，不新增第二套竿ID或支架库存。首版底钓仅在已稳定等待/问饵时允许按配置放架，飞行/沉底及`hooked`以后拒绝放架；已在架上问饵的竿没有自动自刺鱼，取回后才可手动中鱼，因此不借此启用架上搏斗。收线输入只给手持竿，取放清除旧持续输入，不借放架重置钩饵、笼料或搜索。

菜单、失焦、观赏和宿主暂停统一冻结全部竿的沉底、释放、沉积衰减、搜索/鱼口/报警时钟，清除按住/缓存动作；恢复无墙钟补算、自动取竿或铃声重放。多个报警可合并表现但身份独立，不吞掉其他会话。出线后收纳、拆架、切水域及交易仍按各合同门槛，买卖/装配从任意钓点菜单查看，不引入建筑距离。

## 终结、保存和冲突处理

有效中鱼后继续同一`encounterId/sessionId`，线、竿轮、末端配重的质量/阻力与损失使用冻结配置接P4，不另用底钓“收鱼进度”。首版配重不因中鱼自动脱落；若断线丢末端，终结回执列具体部件、线长及剩余料处置，不能笼统销毁整竿。配置未完成的破坏/主动放弃方式不可启用。

`sessionId + terminalEventId`只终结一次，终结原因、钩饵/料状态、磨损/损失、鱼护与奖励和回执原子确认；空提/未中鱼收竿不发鱼。鱼护满仍保留同一待处理鱼，按P4明确整理/放流，不自动出售、复制或跨竿争同一空格。保存结果不确定停止新写入并查原回执，不换ID重扣/退款/发货。

首版不承诺重启续跑沉底或三份搏斗：未提交准备作废；每份已提交未终结会话执行一次`recovery-retrieve`，保留已确认钩饵/笼料/体力消耗与损失，无鱼/奖励。只恢复同一已确认世界检查点，不补离线释放/衰减，不补记未确认损耗。已确认终结优先，场景竿/架归属按三竿恢复规则核对，迟到落水/报警/取放回调均不能重开会话。

错误区分`rig-incomplete`、`rig-incompatible`、`hookbait-empty`、`feeder-mix-insufficient`、`bottom-unsupported`、`settling-failed`、`rig-busy`、`not-held`、版本冲突与`persistence-uncertain`；同名普通模式不能自动替代失败的饵笼模式。0.3.1无这些实例/资产，迁移沿用库存合同，不能由旧型号/等级补造一套底钓或免费笼料；新增入门权益须单独一次政策。

## 待实现验收

| 场景 | 必须成立 |
| --- | --- |
| 铅坠/饵笼同时装、缺前导线、超载/缺参数 | 装配冲突与不就绪分开，说明具体部件，不用浮漂配重或默认零继续 |
| 最后钩饵/笼料被两竿竞争、出手回执重试 | 至多一笔成功，两种消耗与体力同提交，原身份不重复发射/扣料 |
| 出手前取消与出手后受阻/收竿 | 前者零消费，后者保留已确认消耗；无退料或复制装备 |
| 不同水深/底质、线量不足、无底面/超时 | 真正触底才工作，非法/未支持区域明确失败，不无限沉降或保底咬钩 |
| 释放至耗尽、收竿有余料、钩饵先失效 | 质量守恒，不二次扣料；空笼可合法低效搜索，失钩饵必须收竿 |
| 同种子/输入30与60绘制、三竿共享沉积 | 触底/释放/窗口一致，共同效果下步生效，遍历不制造额外物质/抽样 |
| 环境摆动、三槽同时报警、页面重建 | 不自动中鱼，信号绑定正确竿/序号，未装装备无虚构报警功能 |
| 架上咬钩取回、窗口边界右键、旧控制命令 | 取竿不提竿，只有手持新动作可中鱼，过期/旧竿不产生第二搏斗 |
| 飞行/沉底/遛鱼要求放架，按住收线切竿 | 受门槛拒绝或合法取消；新竿无继承输入，其他竿时钟不重置 |
| 断线/失口/满鱼护与重复终结 | 损失、鱼和奖励各一次，无整竿任意删除或自动卖鱼 |
| 释放检查点/出手/终结丢确认后重启 | 查原回执，已确认沉积与源料一致，无重播整笼、离线收益或重复恢复 |

以上为P5及前置层的未来验收，未执行游戏或原生测试。当前限制与浮漂/三竿/P4合同相容：共用会话/消耗/终结边界，只增加底钓工作状态与笼料来源；多模式、架上搏斗和更完整水域物理仍延后。
