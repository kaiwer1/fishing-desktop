## 已取得的静态证据

| 环节 | 已核对关系 | 仍未知 |
| --- | --- | --- |
| 就绪与开始 | 就绪状态读取“主要操作”的按下瞬间，经过输入阻挡检查后调用角色的开始入口 | 当前机器的改键覆盖、全部阻挡条件的具体名称 |
| 手持物与钓具检查 | 开始入口区分钓具与其他手持物、物品类别及接口允许条件；检查不通过可返回或显示提示 | 不能把混淆的布尔检查直接命名成缺饵、饥饿、疲劳或缺少某件装备 |
| 开始蓄力 | 独立角色状态将计时、力度与模式标志初始化；持续状态读取主要操作 | 力度上限涉及其他对象与钓具条件，其完整含义未恢复 |
| 持续蓄力 | 活动更新中累计时间并更新角色力度；有加速动作与修饰键分支 | 不直接采用原函数数值、技能条件和公式；并非此前的调漂累积 |
| 松开 | 主要操作不再按住时，请求进入独立抛出状态 | 在所有输入后端、菜单和设备切换下的完整时序 |
| 动画交接 | 蓄力与抛投动画有不同标识和进入/退出通知；抛出状态还设置动画相关参数 | 动画速度到竿型/竿长的全部映射 |
| 提交抛投 | 抛投动画进入回调检查当前角色状态，将力度与布尔模式传给对应钓具/手持物接口，并读取返回值 | 飞行轨迹、碰撞、水面落点、放线、资源扣除和失败恢复全集 |
| 取消与清理 | 已见状态退出清理和输入阻挡；原版取消动作的完整路径仍未确认 | 不能宣称本项目的右键/Esc 取消就是已还原的 RF4 行为 |

这里的“提交”是调用钓具接口，不能当作已经确认钓组落水或原游戏服务器结算成功。

关键定位包括角色开始入口 `0x180755580`、蓄力更新 `0x18076d4b0`、抛出状态入口 `0x18076d040` 与动画提交回调 `0x18075dcb0`。方法记录、字段类型、构造状态编号、调用关系和动画标识交叉核对；原文件哈希一致。26 个选定入口的结果核对通过，但仍有未恢复跳转表、间接接口调用和推断类型限制。

研究中排除了剪线输入、渔获展示状态和调漂累积；没有因类型相邻、构造编号相似或存在动画名称就将其当作抛竿实现。

## 本项目的实现合同

后续恢复玩法开发时独立实现以下阶段，不复制原配置、原代码或原公式：

1. **就绪检查**：校验当前物品实例、装配兼容、鱼饵、体力与有效水面；失败给出具体原因。按下左键只创建一次抛投会话，不扣资源。
2. **蓄力**：保留瞄准点、力度、所用钓组实例和会话 ID；按活动模拟时间增长。暂停或隐藏不增长。调漂、调速与泄力使用各自动作，不修改本次蓄力。
3. **松开与准备出手**：松开左键冻结本次力度和落点；请求播放抛投动作。此时尚不能称为飞行/落水成功，也不重复接受另一竿。
4. **出手提交**：由独立的出手事件再次验证装备实例及资源，最多提交一次。被取消、失败或已提交的会话忽略迟到的动画回调。鱼饵与体力消耗作为同一笔自研结算提交，不声称原版也在同一时点扣除。
5. **飞行与落水**：仅已提交会话创建钓组轨迹；到达有效落点才进入等待。无效落点、被阻挡或装备失效有明确收束方式，不能留在无限蓄力或等待状态。
6. **取消**：右键/Esc、打开菜单、失焦、隐藏与宿主暂停，在出手前取消会话并清理按住状态；恢复后必须重新按下才能再抛。右键/Esc 是本项目已确认的操作决定，原版完整对应仍待核对。出手后按收竿/失败流程结束，不把已飞行的一竿再次当作取消前的会话。

动作阶段与视觉事件分开，但共享会话 ID。动画事件丢失时设有明确的恢复路径；不得为了避免卡住而在任意延迟后无条件发射或重复扣资源。没有可用动画时可使用标明为临时的出手事件，不能声称已完成写实抛竿动画。

## 实现前验收清单

- 完成一次左键按住、松开、出手、落水，检查消耗和会话只提交一次。
- 蓄力/松开后尚未出手时取消，再投递迟到或重复的出手回调，不产生飞行或扣资源。
- 关闭菜单、切回窗口、恢复宿主时仍按着鼠标，不自动抛竿；重新按下后才响应。
- 出手前更换装备、资源不足或落点失效会失败并提示，不提交旧钓组。
- 不同帧率与暂停时长下，同样的活动时间和输入顺序得到同样的力度与提交次数。
- 正在飞行、已经落水、断线/脱钩和完成入护后，再来一次旧回调不复制钓组、鱼或奖励。

此清单为待实现验收，不是已经通过的游戏测试。2026-10-26已补[装配](FLOAT_RIG_ASSEMBLY_SPEC.md)、[库存交易](INVENTORY_TRANSACTION_SPEC.md)、[遛鱼](FIGHTING_MODEL_SPEC.md)、[咬钩](BITE_PRESENTATION_SPEC.md)和[三竿](MULTIROD_STAND_SPEC.md)原创合同；原版完整取消、物理/概率及玩家覆盖仍未知，R1整体未完成。P0继续独立验证壁纸宿主，不恢复暂停中的玩法，也无需无边界地扫描原客户端。
