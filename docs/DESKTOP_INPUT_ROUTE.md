# P0：桌面输入路线与缺口

2026-10-19 18:53，北京时间。依据为本机 Lively 2.2.1.0 配置、对应版本官方源码和真实宿主暂停试验。不是 RF4 反编译结论，也不是已完成的输入实现。

## 已确认的边界

| 项目 | 证据与结论 | 验收限制 |
| --- | --- | --- |
| 主鼠标键 | 官方 `WinDesktopCore` 的按下/松开处理将主键转发为左键消息；系统交换左右键时采用交换后的主键 | 未做真实桌面按住/松开、图标点击与拖动实测 |
| 普通右键 | 同一转发分支没有普通右键消息，仅在系统交换鼠标键时把右键当主键使用 | 属于源码确认的适配缺口；没有用真实桌面右键操作作最终验证，也没有修改系统鼠标设置 |
| 键盘 | `InputForwardMode` 为 off=0、mouse=1、mousekeyboard=2；本次配置为 1。键盘转发要求模式 2 且桌面处于前台 | 默认配置下不能把网页中 I/C/M/Esc 可用直接当成桌面快捷键通过；未改成模式 2 验收 |
| 输入前台条件 | 官方 `IsDesktop()` 比较前台窗口是否为宿主保存的 WorkerW 或 Progman。鼠标按下/松开及键盘均有该条件 | 从桌面按住后切到其他应用时，松开转发存在缺失风险。当前网页虽有取消处理，仍需验证实际是否收到失焦/隐藏事件 |
| 自动暂停 | 本机 grid=3、AppFullscreenPause=pause(0)、AppFocusPause=ignore(1) 下，真实无边框全屏测试触发暂停，恢复小窗口触发继续 | 已测试诊断页和准备状态的游戏观察副本；非独占全屏游戏、锁屏及多屏均未验收 |
| 自动化能力 | Windows 工具可枚举与读取专用程序的可访问性状态，键盘可操作其按钮；截图返回 `FrameArrived timed out`，坐标点击没有可用几何信息，桌面层未作为可操作窗口返回 | 不编造桌面输入结果，不改用脚本派发页面事件当成真实桌面输入 |

这些条件使“现有网页直接交给 Lively”尚不能满足用户熟悉的右键提竿及完整快捷键要求。桌面画面和自动暂停已有证据，完整交互路线仍是 P0 的前置门槛；不能靠在网页里拦截右键菜单解决宿主未转发右键的问题。

## 下一项独立验证

计划验证一个由本项目控制的 Windows 交互窗口/覆盖层候选，直接接收左右键、滚轮、按住/松开及普通键盘事件。它只用于输入路线验证，不恢复钓鱼界面和玩法开发，不宣称已经选定最终产品形态。

1. 明确区分观赏与用户主动开启的交互。观赏时普通桌面图标、拖动和系统右键菜单可用；交互开启后才让测试窗口接收游戏输入，不注册全局热键，不在其他应用前台截获输入。
2. 对焦点、最小化、宿主暂停和退出统一发送取消信号；验证“按下后切窗口，再松开”不会残留蓄力/收线。触摸与鼠标应使用同一会话取消规则。
3. 如观赏和交互涉及两个渲染视图，必须先解决唯一模拟与唯一存档写入者，禁止各运行一套独立进度。连接失败、重复命令和重开窗口不能复制状态或多次结算。
4. 先用独立测试页完成左右键、滚轮、拖动、键盘、失焦、返回桌面与图标验收，再决定继续 Lively 配合交互窗口，还是实现独立宿主。尚未实施该候选，不把它写成已支持功能。

若自动化仍无法直接验证桌面层，整理短的人工验收步骤并由用户实际操作补证；在取得证据前保持相关条目未通过。当前没有要求用户持续配合，也没有后台测试继续运行。
