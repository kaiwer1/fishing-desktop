# R1：单竿遛鱼模型与收鱼合同

2026-10-26。状态：待实现规格，属于 R1；没有恢复界面或钓鱼流程开发，也没有通过 P4 验收。先服务于一套带轮浮漂钓组，底钓、多竿和路亚另按计划接入。

## 依据与未知项

用户要求接近熟悉的 RF4 操作，并允许鱼群等未知规则采用独立实现。[模块调查](RF4_MODULE_RESEARCH.md)记录了鱼的拉冲、横移、疲劳及渔轮线杯/泄力相关类型的存在；类型名不能证明当前版本启用路径、转换条件、鱼力、泄力、疲劳、断线或脱钩公式。本文的状态、算法与参数合同均为本项目原创设计，不称作 RF4 反编译公式。

输入沿用[输入规格](INPUT_RIG_SPEC.md)：中鱼后左键按住手动收线、松开停止主动收线，滚轮调整泄力，R 配合滚轮调整收线速度；右键在咬钩上下文提竿。实际原版自动收线和组合键冲突仍待核对，首版不借双击默认开启自动收线。松开左键不等于打开线杯，也不保证张力下降。

以下对应已发布 `src/game.js` 的 0.3.1 基线，只读核对，未修改：

| 当前简化行为 | 后续目标 |
| --- | --- |
| 提竿立即设置 `reeling=true` | 提竿只提交中鱼；手动收线须由当前有效输入决定，不能继承旧按住状态 |
| 单个0至100张力值，正弦鱼力，松开固定减张力 | 分别记录鱼位置、线长、张力、泄力出线、竿弯和鱼体力；鱼持续外冲时松开仍可维持拉力 |
| 收线增加 `progress`，到1立即入护 | 收线改变线长和鱼的位置；进入可抄范围后仍须满足收鱼条件并原子结算 |
| 张力到100统一称鱼挣脱，低于阈值累计4秒脱钩 | 区分断线、连接失效、脱钩、线杯放空等原因，按已配置规则处理对应部件 |
| 只有型号层面的竿/线强度 | 用已锁定装配实例、线段和版本，消耗与损失可对账 |

## 唯一模拟与数据

宿主唯一状态持有者推进模型；只读壁纸页与交互页均不能自行抽取鱼动作、修改装备或授予鱼。渲染仅插值已确认的前后状态。P0 计数 owner 是机制诊断，尚不是正式游戏实现。

| 数据 | 单位或约束 |
| --- | --- |
| `sessionId / rigVersion / fishEncounterId` | 延续同一已提交垂钓会话；鱼在咬钩阶段确定，中鱼不重新抽体型或奖励 |
| `stepIndex / modelVersion / configHash / randomState` | 固定步长、参数版本及可复查的随机序列；不同版本不承诺轨迹相同 |
| 鱼位置、速度、水深、岸边与抄网区域 | 米、米/秒；统一世界坐标，不能用屏幕像素当物理距离 |
| 竿根、竿尖、控竿目标与弯曲量 | 输入目标有角速度边界；竿尖由模型给出，动画追随，不由动画反写拉力 |
| 已出线长度、线杯剩余长度、松弛量 | 米且非负；出线与线杯余量之和受该线段总长度约束；长度损失另记账 |
| 鱼线拉力、泄力阈值、部件有效强度 | 牛顿；内部不混用质量与力，鱼重不能直接等同鱼的拉力 |
| 鱼体力、动作剩余步数、松线暴露、超载暴露 | 有界状态；体力比例0至1，暴露时间以模拟秒计 |
| 终结原因、物品损失、结算回执 | 只由会话终结事务产生；界面提示不是授予奖励的依据 |

参数分为钓组配置、鱼行为配置、水域约束和辅助难度配置。必须验证有限数值、量纲、合法范围及相互关系。缺少必需配置时禁止开始相应会话，不能用零强度、无限线长或隐式免费补线继续。所有初始数值均须标注为自研调参值；本文不预填未经实测的俄钓数值或真实材料常数。

装备/库存的持久化仍沿用装配合同的整数毫米、微米和毫克；上表米/牛顿属于运行时物理计算单位，不改变资产表示。线量转换保留小于毫米的运行时余数，只有声明的损失/终结事务按统一规则量化一次；不得每个模拟步各自舍入而生成或损失可售线材。质量由整数毫克换算，物品回执继续记录整数数量；量化和总长度守恒纳入P1/P4验收。

## 状态与输入

`hooked → fighting → landing-eligible → landing-pending → landed` 为成功路径；`landing-eligible` 条件失效可回到 `fighting`。断线、脱钩、线杯耗尽导致的规定失败、主动放弃和恢复收竿均进入终结路径。`landing-pending` 是等待持久化结果，不能先显示已入护再尝试保存。

每个命令包含会话 ID、输入代数与动作序号。旧页面、旧交互授权、旧装配或已结束会话的命令拒绝；重复命令返回原结果。一次更新内先处理宿主/菜单暂停与输入取消，再处理有效控制，最后推进模拟和检查终结。终结优先级固定并记入模型版本，不能因帧率或消息顺序随机变化。

收线为持续意图；松开只停止绞入，泄力仍可出线。调泄力与调速为独立有界设定，达到上下限不循环跳转；R 松开/取消后滚轮恢复泄力上下文。提竿不会兼作收线；菜单关闭、失焦返回或宿主恢复必须重新按下才能开始收线。打开线杯、抬竿与放弃的可用性按当前钓组明确列出，不能把同一次右键同时当提竿、取消和放弃。

## 每个固定步的求解顺序

使用有上限的固定步长累积器，步长与单次最多子步数属于版本化配置。模拟输入按步序消费；高频页面绘制不会增加模拟步数。超出预算的时间记录为丢弃的活动时间，暂停时间不进累积器；恢复不追赶后台墙钟时间。固定步与种子提供同版本复查条件，不承诺不同 JS 引擎的浮点结果逐位一致。

1. **控制与鱼意图。** 消费该步命令，更新有界竿角、泄力和收线设定。鱼用种子序列在明确的决策步选择外冲、横移或低体力动作；动作持续若干模拟步，不能每个渲染帧重抽。水域边界、深度和障碍约束对所有动作生效。
2. **预测运动。** 根据鱼行为驱动、阻力和上一状态预测鱼位置/速度；鱼的质量只参与已声明的运动近似，鱼种行为强弱单独配置。体力影响可用驱动和动作持续时间，不凭体重推导固定拉力。
3. **绞入与泄力。** 主动绞入只在该轮的负载/速度包络允许时减少已出线；受阻时可停转，不能强行拉短穿过鱼或地形。绞入速度不受页面帧率影响。拉力达到配置泄力阈值时，在线杯尚有余量的前提下允许出线；出线速率有限，余量同步减少。泄力不是“无条件将拉力钳到安全值”，急冲或余量不足仍可超载。
4. **线与竿耦合。** 首版使用单条有效线段和柔性竿尖近似，不承诺完整绳链。以鱼到竿尖的有效路径长度、已出线长度、相对分离速度及配置的柔顺/阻尼求非负拉力；松线不产生推力。以有界迭代求竿尖、拉力和出线，限制迭代次数并检查残差。超过容差或非有限状态进入诊断故障暂停，不瞬移鱼、不奖励鱼、不伪装断线。首版不支持的绕障路径须在钓点范围中明确排除，不能让直线穿岸后仍算合法。
5. **约束与暴露。** 应用水深/岸边合法域，复核线量守恒、位置和拉力边界。用每个承载部件的有效强度计算负载比，累计配置的超载暴露；明确瞬时破坏上限与持续超载规则，不能只看一根总张力条。松线暴露只在实际松弛且钩仍连接时累计；恢复绷紧后按配置衰减。脱钩规则首版采用可重复阈值/暴露合同；若以后加入概率，须版本化且只在固定决策步取随机数。
6. **体力与终结。** 鱼做功/持续外冲降低有界体力，低负载时可有限恢复；不能只用战斗经过时间强制疲劳，也不能松线无限恢复。按固定优先级检查故障、部件破坏、脱钩、主动放弃和收鱼条件，输出一次状态与事件。损耗累积交给版本化装备规则，未接通前不声称有真实维修经济。

渔轮阈值降低时应更早出线，但不保证任意瞬间张力严格单调下降；鱼能改变动作。固定鱼意图、初始状态和其他控制的受控比较中，低阈值不能产生更晚开启的泄力。类似地，低速绞入不能无解释地在相同静态负载下比高速收得更快。这类局部单调约束比宣称整场必然更轻松更可验。

## 抄鱼、失败与保存

抄鱼资格同时检查：同一活跃会话、鱼仍连接、鱼在有效水域且进入当前抄网距离/深度/可达扇区、速度和体力满足配置、抄网实例可用、当前状态允许收鱼。只有资格满足且新的空格动作被消费才提交收鱼；不会因进度条满、相机靠近或开菜单自动入护。资格失效则回到遛鱼。具体抄网动作与写实表现留 P3/P4/P10 对照，不从截图猜距离。

鱼护容量在收鱼事务中复核，不能仅在抛竿前检查。**首版采用本项目的简化选择，并非RF4行为复现：容量不足是已确定的入护拒绝，不是保存结果未知。**不改旧鱼护、不授予入护经验，保留原`sessionId/encounterId`对应的同一待处理鱼；它尚未成为入护资产。owner进入受控结果暂停，冻结全部会话与世界时钟并清除持续输入，只提供查看和明确放流当前鱼的收束路径，不提供“整理旧鱼后重试入护”。

`ReleaseCurrentFish`属于该暂停结果的明确业务命令，不是恢复模拟或普通库存交易。结果暂停只冻结模拟，不自行把仍有合法交互资格的结果界面变成只读；独立宿主/授权门槛仍须满足。只接受当前有效交互授权、当前存档分支、匹配会话/遇鱼和预期版本，且该鱼确在容量拒绝待处理状态；观赏页、失效授权、宿主不允许交互或保存恢复中不得发起。放流确认沿用唯一终结身份，当前鱼的终结、已配置奖励/损失与回执同一事务确认；同请求重试查原结果，改请求ID也不能对同鱼再次放流、入护或授奖。放流奖励继续按经济/成长配表，缺配置不发奖励，但不阻止无奖励收束。

容量拒绝期间不得出售/放流旧鱼、换鱼护或改容量，也不得借另一菜单绕过活跃会话门槛。放流当前鱼不腾旧鱼护位置；应先按各自规则解决/收束其余会话，再按库存一般门槛管理旧鱼护，重新检查容量和就绪后再抛，不自动结束其他竿。未来“保留当前鱼并替换旧鱼”须另立原子交换合同，不属首版。

若放流写入结果不确定，维持暂停并停新业务写入，先查原放流回执，不能当成容量拒绝再次放流或先恢复收竿。已确认放流终结优先；确认未提交的放流或仅容量拒绝的未完会话，重启仍按既定`recovery-retrieve`一次收束，无鱼或奖励，保留已确认消耗/损失。页面重载只重建同一待处理结果，不复制鱼；全部结果暂停条件解除后，收线仍须新的有效按下。

断线与脱钩给出不同回执。失败只消耗已配置且实际断开的线段/末端部件；未配置损失规则的钓组不能启用该失败模型。不任意销毁整根竿或整个渔轮。线杯到末端先按末端约束求负载，按配置进入破坏或停止出线，不能每次直接判“跑鱼”，也不能生成额外线。主动放弃须走显式动作和已配置损失规则，不能用换地图免费补齐装备。

持久化合同继承[装配/出手](FLOAT_RIG_ASSEMBLY_SPEC.md)和[库存交易](INVENTORY_TRANSACTION_SPEC.md)：`sessionId + terminalEventId` 只结算一次；鱼实例、鱼护、经验/记录、装备损失及回执原子确认。保存结果不确定时停止新业务写入、查询原回执；不得先退款再重复发鱼。首版中途重启按既定 `recovery-retrieve` 收束未完成已提交会话，保留已确认消耗、无鱼或奖励；本文不引入“完整物理续局”承诺。已确认终结回执优先，重启不能再用恢复收竿覆盖它。

## 待实现验收

| 场景 | 应取得的证据 |
| --- | --- |
| 同种子、配置、固定步输入，两种绘制频率 | 相同事件序列与容差内状态；渲染未抽随机数或推进模拟 |
| 先提竿，再不按左键 | 没有自动绞入；鱼仍可拉线，不能靠固定倒计时自动收鱼 |
| 固定外冲意图，松开左键 | 绞入停止；拉力由鱼/线/竿决定，不执行固定减张力 |
| 同负载分别改变泄力、速度、线强度 | 局部响应符合声明包络；强度影响破坏条件，不直接让鱼移动更快 |
| 鱼冲刺耗尽线杯、长时间松线、持续超载 | 长度守恒；失败原因与损失部件可复核，终结只有一次 |
| 抬竿与快速控竿 | 竿尖速度受限，线/鱼连续变化，动画不能注入额外能量 |
| 活跃收线时菜单/失焦/宿主暂停并停留 | 状态、体力、暴露时间均冻结；恢复无冲击、无自动收线、无离线奖励 |
| 鱼进入抄网区又离开；重复空格或迟到回调 | 资格失效不收鱼；有效终结至多一次，旧会话回调无效 |
| 鱼护最后一格被另一个已确认事务占用 | 当前收鱼原子拒绝；不越容、不重复奖励，保留可处理状态 |
| 满鱼护后重复放流当前鱼、尝试卖旧鱼/换容量，放流确认丢失并重启 | 容量拒绝与保存未知分开；旧鱼护不变，当前鱼一次收束，未确定放流先查原回执，全部会话结束后才管理旧鱼护再抛 |
| 结算写入后确认丢失、重启重试 | 查询同一回执，鱼/经验/损失不重复；未完成会话执行既定恢复收竿 |
| 配置缺失、非有限输入、求解失败 | 开始前拒绝或故障暂停；无凭空修复、鱼/物品奖励或伪装业务失败 |
| 调整场景尺寸与重建只读窗口 | 模拟会话不迁到视图，不改变鱼状态与随机序列；重新授权前无控制输入 |

这些是未来 P3/P4 的可执行验收要求，目前没有实现或测试这些玩法。后续依赖仍为 R1 钓组/库存规格与 P0 路线通过后进入 P1，再按计划恢复界面、单竿和遛鱼。咬钩表现、多竿、技能与制作仍需各自规格；本文件不把整套 R1 标为完成。
