发布范围更新：2026-10-19 15:15 用户授权公开本规格及研究日志。下文“本地”表示证据在本机取得；原始配置、解码数据和伪代码不随文档上传。

## 证据与适配决定

| 事项 | 依据 | 本项目处理 |
| --- | --- | --- |
| 鼠标左键为主要操作、右键为替代操作 | 用户的控制设置截图；已确认鼠标抛竿需求 | 左键按住蓄力、松开抛出；右键提竿；中鱼后按住左键收线、松开释放手动收线 |
| 地图/背包/鱼护/食品快捷入口 | 用户截图中的 M/I/C/T；B 为快速选择拟饵，R 为收线速度，中键为线杯开关 | 后续恢复开发时对齐常用入口。0.3.1 的 B 打开渔具店属于现存差异，本次没有修改 |
| 钓具状态不同，输入作用不同 | 静态类型中有不同 InputLayer、钓组与竿架；实际方法语义仍在研究 | 先明确上下文和优先级，输入只提交给当前上下文，避免一个按键同时触发多个动作 |
| 菜单买卖、只走钓点、横屏壁纸 | 用户明确需求 | 任意钓点都可从菜单进入买卖；不恢复跑商流程；竖屏仅提示和暂停 |

## 输入上下文和优先级

### 2026-10-19 本地静态核对补充

本轮取得以下关联，尚未据此实现玩法：

- 浮漂钓组基类关联鱼钩、浮漂、物理链、鱼线渲染器及专用输入控制器；经典浮漂类型还关联沉子和多个连接器。这能支持装配对象拆分，不能直接证明所有兼容条件。

### 默认动作绑定与回调核对（本地，2026-10-19）

已从本地元数据字符串区找到两份可解析的输入配置，其中一份被生成输入类的构造入口引用。以下是这份内置默认配置的结构摘要；尚未验证当前启用设备、玩家改键覆盖和新旧输入系统之间的选择，不能以它覆盖用户截图中的实际设置。

| 动作 | 默认绑定证据 | 实现前还需核对 |
| --- | --- | --- |
| 主要/替代/附加操作 | 左键 / 右键 / 中键 | 当前钓具与菜单如何消费同一输入 |
| 手动收线 | 左键，配置含按下及释放交互 | 遛鱼、未中鱼、自动收线下的状态切换 |
| 自动收线切换/重置 | 左键多次点击 / 左键持续按住 | 多次点击计数、时限与其他左键动作的冲突处理 |
| 泄力调整 | 鼠标滚轮；另有 Alt 与加减键组合 | 挡位、方向与当前渔轮类型 |
| 收线速度调整 | R 配合滚轮或加减键；R 另有模式动作 | 挡位和切换优先级 |
| 漂深调整 | 小键盘加减、主键盘等号/减号 | 漂深边界及长按步进，不能用作抛竿距离曲线 |
| 抄网 | 空格 | 手持物与收鱼状态条件 |
| 提竿相关 | 存在 Ctrl+右键的独立动作，普通右键另有替代动作 | 与用户当前设置和钓具上下文核对，暂不改写为“只能 Ctrl+右键提竿” |
| 线杯/钓组及其他组合 | 存在回车、Ctrl 与加减键等绑定 | 与用户截图有差异，先核对启用路径与自定义设置 |

原生事件分发层的字段分别保存“动作编号”和“事件类别”。由动作提示分支及字符串引用交叉核对，编号 8/9 对应浮漂下调/上调，19 对应收线速度，101 对应主要操作。五个浮漂闭包回调中，一个写入收线速度模式标志，两组回调分别处理上下调整及各自持续状态；这排除了把其时间累积直接当作抛竿蓄力的解读。

对这条 InputPair/InputUnit 旧输入路径，已沿静态委托初始化和内部调用字符串核对：事件类别 0 使用持续按住读取，2 使用按下瞬间读取，1 使用松开瞬间读取并保留先前按住的输入单元；3 基于持续按住执行计时，4 基于释放事件再检查点击间隔。后两者的完整计数和冲突行为仍需游戏状态核对。关闭/清理时将缓存及计时清零，并向回调提交未激活状态。这不等于已证明生成配置对应的新输入路径在当前机器上启用。

新增实现约束：输入层先将物理设备转换为动作，再由钓具/菜单上下文消费；动作按下、持续、释放与取消应分开记录。手动收线、自动收线和主要操作共享左键时，必须明确优先级；调漂、改泄力、调速不能误触抛竿。原配置和伪代码不导入本项目代码，规格用独立的数据和实现表达。

后续已取得就绪按下、蓄力、松开、抛出状态和动画提交接口的链路证据，见[抛竿链路与独立实现规格](CASTING_FLOW_SPEC.md)。原版完整取消、装备谓词、轨迹与扣除规则仍未恢复。

横屏提示/宿主暂停或隐藏 → 对话框/菜单 → 正在蓄力 → 当前手持钓具 → 钓点探索。高优先级已经处理的动作，不继续传给下层。

观赏模式只展示环境；页面失焦、隐藏、宿主暂停或变为竖向时，取消尚未释放的蓄力并清除按住状态。菜单暂停保留正在进行的一竿，回到场景后不能因为此前按住鼠标而自动收线。所有输入限定于游戏页面或宿主交互区，不注册系统全局按键。

## 第一套浮漂钓组状态合同

| 状态 | 可以做什么 | 离开状态的条件 | 存档与消耗 |
| --- | --- | --- | --- |
| 未就绪 | 看缺件/兼容性、打开背包、换装备 | 装备兼容且有鱼饵与体力 | 装备变化落盘，不扣鱼饵 |
| 就绪/瞄准 | 选落点、调整视角、开始蓄力、打开菜单 | 左键按下或进入其他上下文 | 不扣鱼饵 |
| 蓄力 | 调整落点、松开左键、右键/Esc 取消 | 有效水面释放才接受抛竿请求 | 取消、失焦、无效水面均不扣鱼饵 |
| 松开/准备出手 | 冻结力度和落点，等待出手事件，可在出手前取消 | 会话及装备再次验证后提交一次 | 此阶段尚不扣资源；取消后的迟到回调无效 |
| 飞行/落水 | 展示钓组轨迹与水花，按收竿/失败流程结束 | 钓组落点被确认 | 出手提交时原子扣一次鱼饵和体力；重入不重复扣；已提交会话不再套用出手前取消 |
| 等待/出漂相 | 看漂、调整允许的钓组设置、收竿、暂停 | 有效咬钩、主动收竿或失败 | 本地模拟随统一时钟推进；不在后台独自结算鱼 |
| 咬钩 | 右键提竿；错过则结束或返回等待，按该钓组规格 | 提竿成功或窗口过期 | 成功才创建一份搏斗会话，不重复抽鱼 |
| 遛鱼 | 收线、松开、调整泄力、控竿；见[独立遛鱼规格](FIGHTING_MODEL_SPEC.md) | 抄鱼条件成立或断线/脱钩 | 只有收鱼成功才授予鱼、经验和记录 |
| 入护/结果 | 保留、卖鱼、查看记录 | 结果确认 | 鱼有唯一 ID；入护、卖出与奖励均只结算一次 |

蓄力时长、距离映射、咬钩窗口、鱼力、泄力和抄网阈值暂不填作“俄钓数值”。先完成同一套鼠标动作下的行为核对，再写入本项目参数表。

## 钓组装配数据要求

2026-10-24 补充：首套带轮浮漂的实例归属、可编辑/可抛竿区别、槽位兼容、换件门槛和出手消耗合同见[装配与消耗规格](FLOAT_RIG_ASSEMBLY_SPEC.md)。它是待实现的原创规则，不表示 RF4 装备谓词或正式存档已经恢复。

每件装备有独立实例 ID；物品目录 ID 表示型号，不能用型号代替实例。竿、轮、主线、前导线、钩、漂/沉子/饵笼、鱼饵分别占槽，记录当前数量、容量、耐久与装配关系。第一阶段只开放经过验证的一套浮漂钓组，其余类型在对应钓法阶段接通后开放。

兼容性以明确规则表表达：竿对应钓法、是否需要渔轮、漂/沉子/饵笼槽允许类型、线和轮容量、钩与鱼饵装配条件。缺件和不兼容需要告诉玩家具体原因。价格、承重与容量先作为本项目参数，不直接导入原游戏数据库。

更换装配前结束活跃钓组会话；多竿阶段每根竿的会话、钓组和物品消耗分开保存，切换当前手持竿不能复制、删除或免费补充其他竿的装备。存档迁移优先保留 0.3.1 余额、库存、鱼护和记录，并保留迁移前备份。

## 后续实现前的验收场景

- 蓄力后取消、移出水面释放、切菜单、失焦、隐藏和旋转屏幕，都不产生重复抛竿或残留收线状态。
- 同一按键在菜单中只操作菜单；菜单关闭时不把关闭动作再次当作提竿/抛竿。
- 缺钩、缺线、鱼饵不足、体力不足、鱼护满与不兼容装配分别有原因，失败请求不扣资源。
- 刷新、保存失败重试、重复点击入护/出售，都不能复制鱼或奖励。
- 活跃垂钓、入护结果、切图和交易的保存先后关系明确；每一笔结算可从存档状态核对。
