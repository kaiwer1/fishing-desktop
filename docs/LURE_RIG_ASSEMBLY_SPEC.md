# R1：纺车轮路亚装配与主动收饵合同

2026-10-26。面向P6的待实现原创规格，依赖P1实例/保存、P3抛投、P4遛鱼及相应水域数据；不恢复暂停中的游戏/UI开发。沿用[输入](INPUT_RIG_SPEC.md)、[抛投](CASTING_FLOW_SPEC.md)、[装配归属](FLOAT_RIG_ASSEMBLY_SPEC.md)、[库存交易](INVENTORY_TRANSACTION_SPEC.md)、[遛鱼](FIGHTING_MODEL_SPEC.md)、[咬钩身份](BITE_PRESENTATION_SPEC.md)、[三竿/位置](MULTIROD_STAND_SPEC.md)和[损耗维修](SUPPLIES_CLOTHING_REPAIR_SPEC.md)合同，只补路亚专用装配、运动与消耗策略。

## 依据、旧行为与首版范围

[RF4模块调查](RF4_MODULE_RESEARCH.md)确认`RigLureComplex`、拟饵资源分类、收线输入和渔轮/线杯类型存在；[输入证据](INPUT_RIG_SPEC.md)包含左键手动收线、R组合调速及滚轮泄力。尚未恢复原版路亚连接规则、泳姿/深度曲线、攻饵、自刺鱼、强度与损耗公式；不能把类型名或默认配置当成完整当前玩家操作。

已核对[src/content.js](../src/content.js)、[src/game.js](../src/game.js)、[src/casting.js](../src/casting.js)和[src/ecosystem.js](../src/ecosystem.js)：0.3.1的`minnow`是每抛扣一份的活饵鱼，不是路亚；落水后按落点累计等待暴露，收线仅在中鱼后改变简化进度，没有可复用拟饵实例、收饵轨迹/水层、速度档或主动搜索。本规格不能用换图标沿用该等待流程实现。

首版只开放`lure_spin_basic`：一根路亚竿、一种纺车轮结构、一枚下沉亮片，使用匀收和停顿，手动右键完成有效提竿。水滴轮、软饵/铅头钩拆装、浮水/潜水硬饵、抽动、跳底、复杂竿操、拖钓与自动收线延后，不提供无实际效果的钓法标签。

## 装配、资产与可用性

| 对象/槽位 | 首版要求及不变量 |
| --- | --- |
| 竿、轮 | 各一件独立实例，目录明确支持本模式和纺车轮连接；抛投质量/线杯/绞入负载规则完整 |
| 主线 | 来自当前渔轮的同一`LineSegment`，线类别、线径和长度符合组合容量；不额外生成一卷或槽位副本 |
| 前导线 | 至多一件，安装时长度/连接/强度有效；省略只能用于目录显式允许直连的组合，不猜测某鱼种必须钢线 |
| 拟饵 | 恰好一件可复用实例，记录型号、版本、耐久、唯一槽位；首版一体钩属于该件内部定义，不另发可拆钩或鱼饵份数 |
| 拟饵目录 | 含钩总质量、连接类别、沉降/匀收运动表、工作速度/水层条件、攻饵与损失规则；未配置类型不可用 |
| 会话 | 同一`sessionId/rigRevision`、拟饵实例/版本、规则/技能/穿戴快照、出手身份、运行轨迹、搜索/遇鱼及终结身份 |
| 运行状态 | 拟饵位置/速度、水面/底面距离、出线/余量/松弛、线杯状态、速度档、控制代数/动作序号、固定步与随机流 |

型号与实例、归属、容量和版本沿用库存合同，拟饵装配不改变持有总数；同一实例不得同时给两根竿或作为背包可售副本。一体钩不接受独立换钩命令；未来可换钩结构须新增实例/迁移规则，不能凭内部定义再生成资产。

资产使用整数毫米、微米、毫克、数量和耐久刻度，货币沿用整数最小单位；运行时几何/速度/力使用P4米、米/秒、牛顿。线量转换保留余数，只有确认的损失/终结量化一次；拟饵速度档是有界整数索引，不把页面显示的百分比直接当绞入速度或强度。

`ValidateAssembly`可保存缺件装配，但拒绝已有连接冲突、重复归属与非法数值；`EvaluateCastReadiness`另检查完整且可用、技能资格、抛投质量范围、线量、体力及目标水域。路亚不要求浮漂/沉子/笼料，也不检查活饵堆叠；混入这些槽位不是自动转换成另一钓法。

每种开放组合必须具备容量、含钩质量、出手成本、收线/泄力包络、沉降/工作水层、遇鱼、收回与损失参数。缺参数返回`configuration-missing`，与已配置零鱼口、不兼容、坏件分开；不填零质量、无限线、免费维修或必中。所有初始表均标本项目原创调参值，不冒充RF4常数。

## 抛投与可复用拟饵

沿用左键蓄力→松开→准备出手→`CommitCastRelease`身份及双重校验。首版仅当前合法手持竿可抛；冻结装配、拟饵、规则和出手资源版本，确认前不飞行。尚未出手的取消零消耗，旧回调无效；已出手按收回/失败终结，不再套用出手前退款。

本模式的明确消耗策略是每次成功出手扣配置体力一次、锁定同一拟饵实例，不扣活饵份数，不移除或“重新发放”拟饵。它替代浮漂/底钓的一份钩饵成本，仅改变钓法资源表，不改变共同提交边界。体力、已出手状态、实例引用/版本与回执同一事务确认；同请求重试返回原结果，改ID不能重用同一会话/出手事件。

出手后受阻/落点失效保留已确认体力消耗，拟饵是否实际遗失只按已配置且发生的损失事件决定，不因为“这一抛失败”就自动删一枚。正常收回、错过攻饵或未中鱼均保留原实例；损坏影响下次可用性，不能每抛补成满耐久。活跃会话中换拟饵/线/竿、出售或维修被占实例拒绝，菜单管理仍可从任意钓点查看，不增加建筑距离条件。

## 收线输入与状态边界

| 阶段 | 允许动作与退出 |
| --- | --- |
| 飞行 | 使用已提交抛投及有限放线；不接受第二次蓄力或手动绞入，轨迹有效落水才进入水中状态 |
| `lure-in-water` | 落水后的拟饵按自身沉降与线约束推进；新左键按下开始收饵，松开停止主动绞入；不会直接转浮漂`waiting` |
| `retrieving / paused-retrieve` | 描述实际连续收饵/停顿，均可出现配置允许的追饵/攻饵；取决于真实轨迹，不由按钮标签授予效率 |
| `approaching / strikeable` | 遇鱼身份附着于同一活动收饵状态；保持当前轨迹，按攻饵条件打开有限有效窗口 |
| `hooked`以后 | 转P4同一搏斗链，清除旧收线意图；新有效输入才绞入，不重抽鱼 |
| `retrieve-pending` | 无鱼且满足合法收回区域/速度/线状态后提交一次空竿终结；确认后才重新就绪，不按住连抛 |

飞行持续的旧按住状态不能在落水后自动收线，必须新的左键动作。落水时线杯状态由本模式明确配置恢复为闭合待操作；飞行中不接受手动线杯切换。水中中键可在配置允许时开/关线杯：打开取消绞入，闭合本身不启动绞入，下一次新左键才开始；线杯开时新左键可显式闭合并开始收饵，不影响抛投力度。

滚轮默认调泄力，R按住时滚轮仅改当前速度档，单一输入不同时改两者；R释放/取消恢复泄力上下文。档位列表和每档绞入包络来自型号/规则，上下限不循环，不按真实时间长按加速。速度改变只影响后续固定步，不瞬移拟饵、不重置出线或搜索阈值；松开左键只停主动绞入，仍可沉降/摆动或受泄力出线。

右键在准备出手前按原规则取消，在有效攻饵窗口提交提竿，已中鱼按P4上下文处理；同一动作只被一个上下文消费。无有效鱼口的右键仅反馈空提并结束当前追饵（如有），随后继续合法收饵，不产生鱼、删除拟饵或模拟尚未接通的抽动技法。首版不从双击/长按猜自动收线。

## 有效轨迹、水层与收饵方式

owner按统一固定步推进拟饵，渲染仅插值。闭合线杯并收线时，按速度档、竿轮/负载包络减少已出线，并以有界运动表向合法竿尖路径移动拟饵；线松弛先被收尽，不允许一开始就无视线量拉近拟饵。停顿时按下沉特性、当前线长/张力约束继续运动，开线杯也只在剩余线量和放线包络内出线。

首版用可检查的沉降/收饵升降速度表和单线约束近似，声明最大速度/步进、求解顺序与容差，不承诺完整流体或绳链物理。必须维护位置、出线与线杯余量守恒；不能用“已经收了几秒”直接填写到岸距离或进度条。降低速度档的静态受控对照不得反而无解释地绞得更快。

水层取实际拟饵到水面的深度及河床净空，按轨迹经过的水域、鱼种层位、拟饵工作速度和可达区评估；不是只看最初落点或地图鱼种列表。速度/水层超出工作区可继续合法回收，但对应问饵效率必须按配置降低至规定值，不能保持全程同一鱼口率。

P6首版只开放已有底面、水深、岸边及障碍边界的平缓清水区；不支持穿岸直拉、绕障或跳底。触底后首版停止下穿，并进入明确的`retrieve-required`低效回收状态：不再搜索/攻饵，只允许已配置的脱离/回收路径；若无安全路径则故障暂停，不能瞬移回手或把未知挂底概率当作必丢。相应触底/回收规则不完整的区域禁止出手。

匀收资格由实际有效绞入、拟饵速度及连续活动步稳定范围计算；停顿资格由实际停止主动绞入及沉降状态计算，不靠界面选择“匀收/停顿”增加概率。停顿可攻饵的时间与前置有效运动量明确有界，超过窗口仍可沉降/回收但搜索率为零；原地无限等不能退化成浮漂钓。重新建立停顿资格须满足新的有效运动量，不因每次点击或重载白得一次窗口。

## 遇鱼、提竿与P4交接

复用咬钩合同的`searchEpoch`、独立随机流、累计危险量和唯一`encounterId`，但每步搜索率来自当前轨迹/水层/速度/停顿资格及本项目水域适配，不能直接调用落点固定等待率。参数缺失拒绝开放，明确零率/空池不生成保底目标；换速度、切菜单或页面重建不重抽阈值。

触发追饵时锁定鱼种、体型、条件及行为版本，使用本项目有界追随距离/持续步数近似接近移动拟饵，不声称存在RF4完整逐条游鱼。拟饵离开合法攻饵范围、触底或追随超时则明确结束该遇鱼，随后若仍可收饵才开始新的搜索epoch；不在原遇鱼中偷偷换体型或用“已抽到鱼”保证追上。

攻饵必须满足本模式连接与几何条件才进入`strikeable`，窗口使用owner活动步的`[openStep, closeStep)`，不信页面回填时间。竿尖/线/水花的反馈来自本竿确认事件，辅助提示只改变表现，不改变窗口或精确公开鱼种/重量；环境抖动不等于有效攻饵。重复/旧授权/旧控制/旧会话提竿拒绝，不把早按住缓存到窗口内。

有效右键一次提交中鱼并沿用当前拟饵位置/速度、线量、鱼身份与P4力学状态；不瞬移鱼到起始落点，不再抽目标或改成自动收线。原收饵按住意图在交接处清除，玩家须重新按下；后续泄力、部件破坏、抄鱼资格、鱼护满待处理与奖励均用P4合同。一次追饵失败不额外给成长或“尝试奖励”。

## 结束、损失、暂停与恢复

未中鱼的正常收回只终结原会话，保留同一拟饵/线实例；收回区域采用世界空间距离、可达路径、速度及线状态，不能因为画面靠近或动画结束就回包。结果确认后清除按住状态，避免收线左键变成下一次蓄力。首版活跃路亚不允许放架或换手持竿；已有其他底钓会话仍由同一owner继续，统一暂停规则不变。

磨损沿用已配置的使用/搏斗事件，在对应确认事务量化一次；断线/主动放弃的损失表明确断掉线长及拟饵/前导线是否实际遗失。遗失标记与移除槽位引用同一终结确认，不以“重新装备”找回，也不把整个竿轮删除。若未定义某失败损失，不开放该失败路径；挂底专门释放玩法延后。

菜单、失焦、观赏、竖屏或宿主暂停冻结轨迹、追饵/窗口、随机流与世界活动时间，清除绞入和组合键状态；恢复不补算后台漂移、鱼口/损耗或自动收线。命令包含`rigId/sessionId/controlEpoch/actionSeq`，只由唯一owner接受，视图/动画重建不产生另一份轨迹或拟饵。

保存继承共同原子/防重边界：出手、遇鱼交接和`sessionId + terminalEventId`均有可查身份，鱼/奖励/实际损失与终结回执一起确认。保存不确定停止新业务写入，查询原回执，不先补发拟饵、退款或换ID再抛。确认无提交则保持原资产，不把表现失败当业务损失。

首版重启不续跑拟饵轨迹：未提交准备作废，已提交未终结执行一次`recovery-retrieve`，保留确认体力消耗、耐久/实际损失，不授鱼/奖励；未确认损失不补记，未遗失拟饵保留原ID且不再新增一枚。已终结回执优先，迟到飞行/攻饵/收回回调无效。0.3.1没有拟饵权益，迁移不能把`minnow`或旧竿自动转成免费路亚套装。
