# R1：竿架、三竿并发与切竿合同

2026-10-26。待实现的原创规格，服务P5，不提前开放三竿。依赖P1实例/保存、P3单竿、P4遛鱼及相应底钓钓组规则；目前0.3.1只有单会话，P0独立宿主也尚未接入正式游戏。

[RF4模块调查](RF4_MODULE_RESEARCH.md)记录竿架、槽位、竿托、报警器、碰撞体及锚点关联；完整取放竿、多竿计时、同时中鱼优先级和原版报警公式未知。用户截图提供三根竿放置的视觉参考。本文位置归属、切换事务与并发规则均为本项目设计，不称作原版机制恢复。

## 归属与场景数据

| 对象 | 必要数据与不变量 |
| --- | --- |
| 钓组实例 | `rigId`、装配版本、竿轮线钩等实例引用、唯一位置；延续装配合同，不因切竿复制部件 |
| 位置 | 收纳、手持、某竿架槽位互斥；玩家至多持有一根可控竿，一个槽至多一根竿 |
| 竿架实例/放置 | `standId`、位置/朝向、放置版本、水域/钓点、容量、承载及可达条件；首版容量上限3，实际槽数来自配置 |
| 槽位 | `slotId`、父竿架、占用版本、竿根/竿尖/报警器锚点、取放可达区；逻辑编号固定，不因界面排序改变 |
| 垂钓会话 | 每根竿独立的`sessionId`、钩饵、落点、出线、遇鱼、固定步状态和终结回执；只有活动的合法钓组才推进 |
| 手持控制 | `heldRigId`、控制代数、动作序号与按住状态；切竿不把同一份收线意图传给下一根 |
| 取放意图 | `handoffId`、目标竿/槽位版本、预期位置、动作阶段；迟到回调不能改变已结束意图 |

竿架没有隐形背包作用。放置位置必须在本水域许可区域、地面支撑合法、尺寸/碰撞和可达条件满足；不能放进水里或挡住交互后仍视为可用。首版允许哪些竿型、钓法与报警器明确配表；没有完成底钓装配/放线规则的型号不得仅靠挂在架上变成可钓。

## 取放、切竿与输入

采用用户熟悉的X放到竿托、E取用、1/2/3快捷选择的项目绑定；这些组合的完整原版上下文尚未确认，以后按设置页统一展示。快捷数字指向稳定槽号，不是背包里排序后的型号。视角瞄准与可达条件仍有效，不能隔着地图拿竿；已有水域内可达的快速取用范围须明确配置。

取放先创建意图并锁定相关钓组/槽位，清除旧手持持续输入；在取放提交点再次验证版本、归属、可达和状态。提交前取消、失焦或动画失败，保持原位置，不产生另一根可控竿；提交成功后位置唯一变更一次，动画追随确认位置。迟到回调拒绝，提交后的视觉失败不能悄悄回滚成双占用。动作提交与恢复边界沿用[抛投合同](CASTING_FLOW_SPEC.md)的会话/回调防重原则，但不重复扣鱼饵。

手持A时选择槽B，先把A放入一个可用且合法槽位，再取B；两次位置提交可单独查询。没有可用位置则拒绝并提示，不能把已出线的A免费收进背包。若放A成功但取B失败，A保留已确认槽位、B保持原位，手中为空；不把整个过程伪装成原子完成后复制或回填旧物品。该次取用不能绕过版本重检。

蓄力/准备出手期间切竿先按出手前取消规则收束；飞行中拒绝取放，待落水或失败。遛鱼时是否允许放架由该竿/架承载和钓组规则决定，默认未配置则拒绝。成功放架后关闭手动/自动收线意图，鱼仍按架上物理推进；取回后必须新的有效输入才收线。一次数字键不同时触发切竿、提竿和收线。

菜单优先消费输入；关闭菜单、视图重建或宿主恢复不执行缓存的数字键/取竿动作。当前窗口需要有效交互授权，命令指定`rigId/sessionId/controlEpoch`，不能在异步回调中只读取“当前手持”并误操作另一根。

## 一个时钟、三份会话

所有活跃竿由同一owner按同一固定步推进，切手持竿不暂停另外两根。每根竿的等待、鱼口、钩饵、泄力/出线、鱼体力与失败独立；只有手持竿接收手动控竿/收线，架上竿使用其锚点、已配置泄力和架上约束，不能自动提竿或自动绞入替玩家处理鱼。

单步分为读取共同环境快照、各竿计算候选状态/事件、确定性提交和发布快照。共享压力/打窝等状态集中归并后进入下一步，不因数组遍历顺序让后一根竿多抽一次或读到半步世界。随机流以存档分支、会话和子系统分离，切换当前竿不改变其他竿的随机序列。这里是自研局部遇鱼，不宣称同一条RF4服务端鱼同时跨竿选择的原规则。

菜单、失焦、宿主暂停、显示不可用等按统一合同冻结所有会话与世界时钟，不能只冻结当前手持竿；报警计时也不积累墙钟时间。恢复不补算后台鱼口、不产生集中跑鱼/奖励。任何视图只是呈现一个原子快照，不启动自己的第三份或第四份模拟。

鱼护容量、鱼饵与体力等共享资源由唯一提交层检查。例如只剩一份饵的两个出手，最多一个成功；两条鱼争最后一格时按确定的模拟步/事件序号顺序提交，后一笔保持待处理，不越容或改成自动出售。所有竿对同一存档分支写入，不能各自保存整份钱包而互相覆盖。

## 报警、同时咬钩与故障

报警器消费本竿会话已确认的线/竿尖变化及配置阈值，不消费当前手持竿的全局变量。音频、灯和屏幕提示是同一事件的不同表现；页面重建可恢复当前持续状态，不重放所有历史铃声或增加咬钩次数。没有报警器的竿仍可看竿尖/线，不能显示一个已购装备才有的功能。

同时报警须可识别槽号并保留每根状态，界面不会自动抢走手持竿或切镜头。告警展示可合并/限频，但去重只影响表现，不能吞掉另一个会话的状态。暂停/观赏模式不触发后台通知轰炸；具体声音与视觉表现留P2/P5/P10验收。

竿架失效、地面/水域非法、部件失效与线断分开处理。受影响会话进入有明确原因的暂停/收束，不把整个竿架和所有竿任意销毁。物品损失沿用版本化装配与遛鱼规则。水域切换前必须收束所有活跃会话并处理场景放置，不只检查手持竿；禁止通过切图补饵、清空失败或将同一竿留在两个地图。

## 保存与恢复

取放、拆架与位置改变用请求ID/版本/回执原子确认。正在使用的竿架或占用槽位不能出售、拆除或搬走；先按规则取回并结束相关会话。重复取放返回原回执，不能重做一次对象创建。

首版重启对每份未完成已提交垂钓执行一次既定`recovery-retrieve`，保留确认消耗与损失，不授予鱼；已经确认终结的会话不再执行恢复收竿。场景中的竿架与竿先核对引用/版本与放置合法性，再显示；非法位置进入明确的待恢复记录，由恢复事务移动到唯一合法收纳位置，不能凭空丢弃或同时生成库存副本。未确定提交结果的取放先查原回执，不按动画所在画面猜归属。

本规格不承诺重启续跑三份物理状态；以后要支持须独立版本迁移。P0计数器结果不能替代正式多会话事务、断电或恢复测试。

## 待实现验收

| 场景 | 必须成立 |
| --- | --- |
| 同一根竿重复放入两个槽、同一槽并发取放 | 至多一个位置提交成功，部件/会话不复制 |
| 三根等待时连续切1/2/3 | 三份活动时间/种子不重置，只有一根受手动控制 |
| 按住左键后切竿、失焦或打开菜单 | 旧收线取消，新竿无继承收线/提竿；暂停时三竿同时冻结 |
| 放A成功、取B失败或中途失焦 | 已确认位置可核对，无双持、无空槽引用错乱，无隐形回收已出线竿 |
| 三竿同一步报警、一个鱼口过期 | 槽号提示独立；不自动切镜头/提竿，其他会话继续合法推进 |
| 架上中鱼且持续外冲 | 使用架上锚点、线量和泄力，不自动收线；破坏有独立原因与损失 |
| 最后一份饵/最后一格鱼护 | 共享资源只提交一次，后到者明确失败/待处理，数量不为负且奖励不重复 |
| 对占用竿架拆除、出售或切图 | 明确拒绝或先合法收束，不删除活跃引用、不补满资源 |
| 两个视图重载、只读窗口重建 | owner与三会话不随视图复制/丢失，旧文档动作无效 |
| 位置提交后确认丢失，重启再取放 | 查询原回执，同一实例只有一个归属，未完成会话逐个恢复收竿 |
| 固定种子输入，交换内部遍历顺序 | 共同环境结果与独立会话事件一致或按声明的稳定顺序提交，不出现遍历依赖的额外抽样 |
| 三竿持续负载与长时运行 | 独立记录CPU/GPU、内存/句柄、暂停及帧时间；单竿/占位景预算不能代替三竿实测 |

这些是P5及其前置数据层的未来验收，不是已实现功能。当前仍按R1/P0→P1→P2/P3/P4→P5推进，不改暂停中的游戏UI或单竿原型。
