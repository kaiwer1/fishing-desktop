# P0 可见桌面循环与资源记录

该测试延续[完整暂停路径](../diagnostics/dual-window/README.md)，只加载本项目的二维诊断画布。它不加载钓鱼游戏，也不能代替[三维场景基线](P0_RENDER_PERFORMANCE.md)或桌面输入验收。

## 可重复运行

先具备通过身份、几何与 DPI 核对的已有传统 WorkerW；没有符合条件的层时诊断明确失败，不自动更改 Explorer。实际运行会显示自有诊断壁纸及约50秒的自有全屏测试窗，应安排在空闲时段。

```powershell
./diagnostics/dual-window/test-webviews.ps1 -SdkDirectory <SDK目录> -OutputDirectory <已有仓库外目录> -SoakSeconds 900
```

时间范围120至7200秒；计时从前面的页面、桌面和原生全屏检查完成后开始。每30秒交替手动暂停/恢复，每180秒在允许活动时释放并重建只读视图。每约2秒记录一次 owner、提交序号、活动时钟、暂停原因、渲染器挂起/静帧状态、绘制计数和本进程资源。重建继续使用同一 owner、写锁与请求去重记录。

通知接入版成功报告共29项（下文08:53历史版本26项），最后正常关闭视图、撤回全部桌面 lease，核对自有浏览器/测试进程退出。过早退出、报告不一致或需要强制清理均不计通过。运行范围内的内存/句柄变化只作观察，不自动作泄漏判定。

资源采样器可以同时在另一个终端只读观察已运行的确切宿主：

```powershell
./diagnostics/lively-host/measure-gpu.ps1 -OwnerExecutable <本轮DualWindowHost.exe> -OutputDirectory <本轮构建目录> -Seconds 873 -IntervalSeconds 3 -Phase unlabelled
# 两个程序结束后再汇总；资源 summary.json 未生成时拒绝汇总。
node diagnostics/dual-window/summarize-soak.mjs <本轮构建目录>
```

采样器不会启动/暂停宿主。原有 `-LivelyExecutable` 参数仍可用；新参数只接受 `DualWindowHost.exe`。按完整路径找到唯一根进程，再用 PID、启动时间与已证明的父子关系确定范围。原始数据含本机进程身份和路径，留在仓库外；公开文档只摘录独立汇总。

## 汇总口径

- 输入目录及祖先不得为链接，记录文件为不超过64 MiB的直接文件。存在多个资源运行时拒绝猜选。资源最终报告必须匹配本轮可执行文件、样本数及每个样本的根 PID/启动时间。
- 活动阶段要求 owner 可运行、无暂停原因、渲染协调完成、WebView 未挂起且静帧未显示。暂停阶段要求唯一原因为手动暂停、协调完成、SDK 已挂起且静帧显示。其他情况单独排除。
- CPU 采用连续两个资源观察的差分区间；额外向两边各留1秒计数器刷新余量。两端须有距离不超过2.5秒的心跳覆盖，且期间阶段、策略 revision、视图重建代次一致。跨暂停/恢复、重建或证据不足的区间不进入阶段均值。这个相关方法仍依赖记录时钟和系统计数器刷新，并非同步硬件测量。
- CPU 仅在全部当前范围内进程都有前一次差分时计入均值。GPU 读取 `maxSingleEngineReportedPercent`，即已归属进程在最忙单一引擎上的报告值；它不是显卡总利用率。整数化、缓存和提供器刷新限制保留。
- 显存字段是可用实例的报告和，不是唯一物理显存；缺失为 null，真实0保留。DWM、准备桌面层的 Lively、采样器及测试脚本开销不在此进程范围。
- 窗口首/末60秒的中位数、GDI/USER/句柄计数只描述本次观察。RAF 绘制回调频率与系统呈现帧率分开，不能称为游戏 FPS。

原始心跳、进程报告、WebView profile、可执行文件及本机路径不公开。公开结果应同时保留场景类型、时长、阶段样本量、排除量和未验项目。
