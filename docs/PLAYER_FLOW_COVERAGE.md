# R1：玩家流程覆盖矩阵与剩余接口

2026-10-27。本文交叉整理现有合同，不是新版本功能清单、测试报告或R1完成证明。P0仍独立验证宿主，P1正式保存及暂停的游戏/UI尚未开始；0.3.1旧试玩不能作为下面实例、会话和事务规则已接通的证据。

“最初里程碑”指[开发计划](DEVELOPMENT_PLAN.md)的一钓位、一套带轮浮漂、完整保存与菜单交易；“阶段首版”指P5简单底钓/三竿、P6纺车轮路亚、P7单水域、P8补给维修或P9制作各自先开放的有限组合。它们不是同时上线的承诺，依赖仍按原计划推进。

无轮手竿目前**没有可执行合同**：首套浮漂明确需要渔轮/线杯，不可简单移除渔轮槽并沿用就绪检查。手竿线长、固定连接、抛投/提竿、无泄力的负载/损失及收鱼方式均待独立设计，当前不能标为支持，也不擅自指定上线阶段。

## 从进入到再次出手的覆盖矩阵

| 玩家步骤 | 最初/阶段首版的合同路径 | 失败、后续或阻塞 |
| --- | --- | --- |
| 进入/载入 | 唯一owner验证分支、格式/规则和最后确认状态；新页面只读快照，显式交互后才收命令 | P1入口、迁移激活及宿主资格接口未接通；损坏/结果不确定不能回默认钱包或新世界 |
| 首次选择钓法 | 最初仅完整带轮浮漂；其他阶段只列已实现组合及未就绪原因 | 手竿、复杂底钓、水滴轮、海钓均不可仅换图标启用；具体目录/解锁待配表 |
| 选择/拆装/绕线 | 具体实例/堆叠引用，编辑合法与可出手分开；替换按最终容量一次移动，线量守恒 | 缺件可保存，不兼容整笔拒绝；活跃引用不能拆、售、维修或重复装到另一竿 |
| 选钩饵/笼料/拟饵 | 浮漂/底钓选择库存饵；底钓另选整数笼料；路亚锁同一可复用拟饵 | 选择不消费；缺批次/体力/参数不就绪，路亚不要求一份活饵，也不每抛发新拟饵 |
| 探索/移动钓点 | 最初固定钓位；P7在无活跃会话时沿已配置岸线移动，交易始终菜单进入 | 出线后跨钓点/切图先收束全部竿；出线行走、穿水/绕障未支持，不重新引入跑建筑买卖 |
| 瞄准/蓄力 | 左键按下创建准备身份，按活动时间蓄力；松开冻结力度/目标 | 目标/归属/版本再次校验；取消后旧出手回调无效，数值曲线和动作还待接通 |
| 出手提交 | 当前手持竿一次提交资源与会话：浮漂一份钩饵/体力；底钓另扣料；路亚只扣配置体力 | 确认前不飞行；同会话改请求ID仍不重复扣；提交后受阻不按出手前取消退款 |
| 飞行/实际落水 | 使用同一几何/线量和会话，轨迹有效才进入工作状态 | 预计落点不代表已落水；阻挡/失效有原因收束，不瞬移钓组或授鱼 |
| 浮漂工作/等口 | 配重/漂深稳定后搜索，接近/试探/有效窗口按浮漂规则；失饵要求收竿 | 不能由类型名猜漂相或用固定等候时间保底；无口可主动收竿，未来不默认65秒自动结束 |
| 底钓工作/报警 | 实际触底稳定才工作，笼料有限释放；铃铛/报警消费本竿信号 | 未稳定/不支持底质不问饵；空笼不等于失钩饵，报警不自动提竿或生成一条鱼 |
| 路亚主动收饵 | 新左键收线、松开停绞；速度/深度/真实轨迹与有限停顿驱动搜索 | 不复用浮漂静态等待；抽动/跳底/自动收线后续，触底按明确回收规则处理 |
| 多竿放取/切手持 | P5共用时钟、每竿独立会话；X/E/1/2/3按稳定槽位和取放事务生效 | 取竿不等于提竿，数字键不缓存收线；无空槽不能隐形收纳已出线竿，取用失败不复制/回滚已确认位置 |
| 有效提竿 | 合法手持、新有效右键在owner窗口内提交一次中鱼，沿用原鱼种/体型/位置 | 早按/过期/旧竿命令无效；提竿不自动收线，空提与失口按该钓法处置，不能重抽必中 |
| 搏斗/泄力/收线 | P4左键持续收线，松开仅停止主动绞入；滚轮泄力、R组合调速 | 鱼外冲仍可有张力，不统一松开降张力；力/速度/强度参数、竿线/手部接口待实现 |
| 抄鱼/入护 | 同鱼进入可抄区域且状态/抄网可用，新空格确认；鱼/经验/记录/损失同终结提交 | 进度条满不自动入护；容量不足是明确拒绝，暂停全部模拟并保留同会话/遇鱼，只允许有当前授权的明确放流，不改旧鱼护或先发入护奖励 |
| 跑鱼/断线/主动收回 | 明确终结原因，保留已确认出手成本，仅记配置且实际发生的损失 | 不任意毁整根竿；未定义损失不能启用该失败方式，迟到鱼口/出手/动画不重开会话 |
| 鱼护与出售 | 查看真实鱼ID；单卖/多选/全部冻结确认清单，原子移鱼加余额，历史记录保留 | 报价失效重新确认，不把后来入护鱼并入旧“全部”；出售不再发入护经验，鲜度/计价仍待配表 |
| 采购/穿戴/食用 | 购买仅入库；食用消费一份与实际恢复同提交；穿戴唯一实例，价格/容量/资格再校验 | 购买即装备/吃掉是旧版差异；任一竿活跃时食用/换装拒绝，全零恢复不浪费食品，不隐式补默认装备 |
| 维修/配件 | P8先显式拆下可修实例/子件再报价，同步扣款/料和改耐久，保留原ID | 带线渔轮不隐式清空/补线；不可修、满耐久、缺规则等受理前拒绝，等待维修后续 |
| 技能/制作 | P9有效前置/点数与版本一次分配；同步批量制作完整成本/结果/品质及回执 | 活跃任一竿拒绝加点/重置；制作不可用会话占用物料/工具，其他制作可用性依配方条件，不笼统禁止全部制作 |
| 无钱/无饵的恢复路径 | P8菜单救济须有明确资格、一次事件及不可套利的物品政策 | 尚无完整配表/验收，不默认无限免费补给，也不让玩家只能删档继续 |
| 再出手/换图 | 已终结结果确认后重新校验；切图前所有竿收束、位置/竿架按合同处理 | 保留原水域压力/时钟/沉积，未配置地图拒绝；没有接通的场景加载/失败回退不能假报完成 |
| 退出/重启 | 停接旧输入；已确认满护pending保留、重新授权再放流，普通未完会话一次恢复收竿且无鱼/奖励 | owner对象层已实现显式启动/退出收束，实际关闭UI/应答超时仍待接线；页面关闭不等于退出或退款 |

菜单交易可从任何钓点进入，不等于任何钓鱼状态都能写资产。满鱼护首版采用本项目简化选择，并非RF4复现：不提供整理旧鱼再重试入护，不允许活跃中出售/放流旧鱼或换容量。结果暂停只停模拟，合法交互结果命令仍可确认，独立宿主/授权阻塞不被绕过。`ReleaseCurrentFish`只终结同一待处理鱼，校验当前交互授权、分支/会话/遇鱼和版本，不是普通库存交易；缺奖励配表可无奖励收束。之后先解决/收束全部会话，再管理旧鱼护、检查容量和重新出手，不自动收束别竿。保留/换鱼的原子交换仅为后续扩展。

容量不足已知拒绝与放流保存结果不确定分开：前者不写入护资产、不发入护奖励，后者维持暂停停新写入、先查原放流回执，不能再放流或先恢复收竿。已确认终结优先；2026-10-27调整为已确认满护pending跨重启保留，明确未提交放流则恢复同一待处理结果，普通未完成模拟才一次恢复收竿。页面重载不复制待处理鱼，全部暂停解除后仍需新的有效输入。

## 中断、恢复与输入intent复位

| 中断来源 | 模拟/写入边界 | 返回场景后的输入要求 |
| --- | --- | --- |
| 菜单/对话框 | 全部竿及世界活动时钟暂停；出手前取消，已出手保留会话；已受理原子业务不能取消一半 | 清蓄力、绞入、组合键及缓存提竿/取竿意图；菜单确认键不穿透为抛投 |
| 观赏模式 | 只展示环境，游戏命令只读；生态/鱼口/压力/沉积均冻结 | 显式回交互并取得当前授权，新的按下才生效，不因旧按住自动钓鱼 |
| 失焦/隐藏 | 准备阶段取消，活跃模拟冻结；不补后台经过时间或发放离线收益 | 清持续输入，旧动作代数拒绝；切回不自动收线/提竿 |
| 竖向窗口 | 只显示横屏提示，游戏输入和模拟/渲染暂停 | 恢复横屏后重新交互，不做竖屏钓鱼布局，也不补发松键事件 |
| 宿主/全屏/会话/电源暂停 | 业务统一门槛冻结，具体逐输出资格由P0持有；无有效共享活动资格不推进世界 | 旧输入授权撤销，恢复须新资格/授权；暂停位各自解除，不清其他阻塞 |
| 页面重建/断开/结果不确定 | view不拥有模拟；只查确认快照与原回执，未确定结果停止新写入 | 新文档不重放旧回调/交易确认；同请求重试保留业务身份，不能换ID重扣/重抽 |

优先级仍为横屏/宿主门槛→菜单→准备/蓄力→当前钓具→探索。一次物理动作只由一个上下文消费，按下/持续/释放/取消身份分开；提竿交P4、切手持、模式切换和结果返回均不得继承旧绞入intent。共享活动是否可推进与某视图是否可收输入是两个资格，不能只清一根竿或一张页面。

取消与业务回滚不同：未受理选择可零消费取消；出手或交易已确认则保留结果；确认丢失先查同一回执，不先退款/补物品再重做。恢复不得把按键物理状态当作新动作，也不能凭动画结束补做出手/入护。

## 仍缺的数据与动作接口

| 缺口 | 开工/验收前必须落实的内容 |
| --- | --- |
| P0→P1接线 | 唯一owner实际游戏状态、共享活动资格、只读/交互文档和撤权、正式存档提交/查询/备份接口；诊断计数器不能代替 |
| 玩家入口/退出 | 新建/载入/迁移选择、就绪/阻塞原因、正常关闭与保存不确定的可理解反馈；不能只写一条成功提示 |
| 动作桥接 | 当前手持/控制代数、蓄力与出手事件、取放提交点、竿尖/导环/鱼线、抄鱼区域、动画失败/迟到与取消的独立接口 |
| 内容/资产目录 | 中国内陆/海洋鱼准确身份及模型映射、竿轮线钩/漂/配重/拟饵、来源许可/真实尺寸/节点；海洋模型不是海钓规则 |
| 几何/场景 | 同源水面/河床/底质/障碍、站立/步行/架位、允许投回路径及失败回退；首版区域外不猜默认值 |
| 原创平衡表 | 出手/活动成本、沉降/速度/力学、鱼口/体型/压力/沉积、价格/鲜度、食品/维修、技能/配方等必需字段与版本/舍入 |
| 未覆盖钓法 | 手竿、复杂底钓/架上搏斗、水滴轮/抽动跳底、海钓/船钓各自装配、输入、损失/恢复合同；没有独立合同不开放 |
| 业务呈现 | 准确槽位/实例/批次、报价和待确认结果，空包/满护/不足/旧版本/保存不确定等原因；不靠异常字符串推断状态 |
| 满鱼护收束接口 | 实现已明确的容量拒绝状态、全部会话暂停及当前鱼放流命令/回执，不开放旧鱼护写入；未来保留/换鱼需独立原子交换合同 |

原RF4服务器算法、真实数值、玩家改键覆盖与完整原版时序继续列未知；本项目用已声明原创规则补齐时须保留差异，不能把填表称为反编译恢复。必需参数缺失应禁用受影响动作，不默认为免费/零强度/无限资源/必成。

## 后续验证必须形成的证据

以下仅列玩家链路验收入口，不表示已经执行或通过：

- 新进度与0.3.1迁移分别走到装配就绪，缺件/不兼容/不足可恢复，资产与历史事实不凭空增加。
- 一套带轮浮漂完成鼠标抛投、真实落水、空口/失口、提竿、P4搏斗及抄鱼；动作身份/消费/终结各一次。
- 底钓三竿同时有状态时取放/切换，正确槽号报警且取竿不提竿，共享资源竞争不越界。
- 路亚抛收、调速/停顿和不同真实水层确实改变轨迹/遇鱼，拟饵重复使用或实际遗失可对账。
- 鱼护满、批量卖鱼、采购/食用/维修/制作的容量/版本冲突与确认丢失，均无部分消费、重抽或重复奖励。
- 满鱼护时重复放流当前鱼、尝试卖旧鱼/换容量及放流确认丢失后重启：已知容量拒绝与保存未知分开，旧鱼护不变，当前鱼一次收束，不确定先查原回执，全部会话结束后再管理旧鱼护并出手。
- 各阶段按住输入时分别开菜单、观赏、失焦、竖屏、宿主暂停/重建，返回无自动抛投、提竿、取竿或收线。
- 切钓点/切图、退出中途重启和旧回调到达，所有竿/世界/物品归属可恢复，压力不重置、无离线收益。
- 原版操作差异、未知数值和每项后续范围可由玩家看懂；模型、动作、画面与性能另按[质量门槛](VISUAL_MOTION_TARGET.md)和P0证据验收。

本矩阵暴露了现有合同的交界与未覆盖项，不替代各合同的详细状态/交易规则。R1还需数据/动作接口、玩家覆盖与平衡确认；没有恢复P1、UI/玩法编码，也没有宣称整个RF4或本项目完整流程已经实现。
