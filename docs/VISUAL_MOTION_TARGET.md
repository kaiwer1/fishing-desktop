## 已核查的差距

检查现有 `src/main.js` 的竿模型、鱼线更新和绘制分支：

| 部分 | 当前实现 | 造成的问题 |
| --- | --- | --- |
| 竿轮与手部 | 单条固定半径管状网格代表鱼竿，圆柱体代表衣袖；没有完整手部、渔轮、导环与握把结构 | 外形、尺度关系、握持接触和近景细节不足 |
| 抛竿姿态 | 抛竿时仅给整条竿约 0.08 弧度（4.6°）的正弦转动；顶点位置已带场景坐标，旋转仍绕对象原点 | 没有握持处转轴和手臂联动，缺少后摆、前送及随挥的动作层次 |
| 竿尖与鱼线 | 鱼线起点取固定 `rodPoints[3]` 加钓位偏移，没有取旋转或变形后的竿尖世界位置 | 鱼线与竿尖不能保持一致 |
| 飞行表现 | 浮漂按一秒归一化进度插值，加正弦高度；没有与手部动作、竿身加载/回弹及出线事件完整同步 | 挥竿、出手与钓组飞行的因果关系弱 |
| 环境和鱼类 | 几何树木及简化鱼体，缺乏写实近岸细节与材质层次 | 整体仍显著呈现占位模型特征 |

以上是对本项目源码的检查。用户录屏元数据为约 606.9 秒、1920×1080、60 fps；已复核既有抽样画面，以守钓、菜单与行走为主。抽样未覆盖完整抛竿动作，不能据此填写 RF4 精确关节轨迹、出手帧或持续时间。原始录屏及含桌面/账号/聊天的抽帧继续留在仓库外。

## 按原开发顺序验证的独立样片

用户随后要求继续此前顺序，撤销把本样片提前的调整。以下质量门槛保留，按 P10 的原依赖推进；当前先做 P0 输入和宿主验证。

先固定一个钓位、一套具体竿轮组合及第一人称视角，制作可单独查看的模型与动作样片。它不接入交易、成长、咬钩或新的界面流程；当前界面和钓鱼流程的暂停要求继续有效。

- **模型与材质**：按同一真实尺寸基准制作竿节渐细、握把、轮座、导环、渔轮、线杯和摇臂；双手具有可调整的手指握持、腕部及前臂，袖口接触自然。保留可编辑源文件、骨架与 glTF 导出，登记原创/许可来源。
- **动作组织**：设计持竿就绪、蓄力预备、后摆加载、前送加速、出手、随挥、回弹与回到就绪。具体节奏先标为独立设计，取得完整动作参考后再对照调整，不宣称是原版参数。
- **握持和变形**：竿、轮、手指与腕部保持接触关系；弯曲沿竿身分布并带衰减回弹。用明确的握持节点和竿尖节点驱动附件，避免各部件独立漂移。
- **同步接口**：鱼线起点逐帧来自竿尖世界坐标，导环与线段对应；出手事件连接动作与钓组飞行。力度改变加载、速度和落点的关系需可解释。业务结算仍按[抛竿链路规格](CASTING_FLOW_SPEC.md)单独处理。
- **场景质量**：先补一个固定镜头里的近岸、植被、天空、水面及光照关系，提供和用户参考相近构图的对照。资产规模与表现须和目标硬件预算一起实测。

## 样片验收

1. 固定相机，分别展示待机、低/中/高力度完整动作；提供正常速度和慢放，包含正面实际视角与侧面检查视角。标明参考观察、自研设计与仍待核对之处。
2. 检查手掌是否滑离握把、手指/衣袖是否穿模、渔轮朝向是否稳定、竿尖是否连续运动，出手与钓组出现是否同步；鱼线起点与竿尖保持一致。
3. 在蓄力、前送、出手后分别暂停/恢复和取消，动作可收束，不发生姿态瞬跳、重复发射或残留按住状态。
4. 在不同帧率与横屏宽高比下检查轨迹和近景裁切；记录真实帧时间、GPU/显存及内存，不以宿主能加载替代画面/动作/性能通过。
5. 由用户实际观看样片判断外形、节奏和手感方向。该质量门槛通过前，不扩大地图和鱼种来替代模型与动作改善。
