# R1：水域、钓点与轻量生态合同

2026-10-27。面向P7的待实现原创规格，沿用[抛投](CASTING_FLOW_SPEC.md)、[咬钩](BITE_PRESENTATION_SPEC.md)、[底钓](BOTTOM_RIG_ASSEMBLY_SPEC.md)、[路亚](LURE_RIG_ASSEMBLY_SPEC.md)、[三竿](MULTIROD_STAND_SPEC.md)、[库存交易](INVENTORY_TRANSACTION_SPEC.md)及[成长](GROWTH_CRAFTING_SPEC.md)合同。P1正式保存和暂停的游戏/UI继续未开始，本文不把R1整体或P0标为完成。

## 依据、旧行为与首版边界

[RF4模块调查](RF4_MODULE_RESEARCH.md)只确认水域/地图、种群与咬钩转换等类型线索，未恢复服务器种群、迁移、共享竞争或真实概率。[鱼群研究](FISH_POPULATION_DESIGN.md)中的公开参考只支持位置、环境、压力等方向，不能据此反推固定周期/数量。以下均为独立设计，不使用原客户端素材、配置、解码数据或个人存档。

已核对[src/ecosystem.js](../src/ecosystem.js)、[src/content.js](../src/content.js)、[src/casting.js](../src/casting.js)及[src/game.js](../src/game.js)：0.3.1有三图各三钓位、矩形水面判定、公式深度、每鱼种一个移动聚集中心、6×5压力格和共同`elapsed`；全部地图压力随活动时间恢复，鱼种权重结合落点/鱼饵/环境，游戏另有首鱼辅助和最长等待。没有权威河床碰撞、底质/障碍、自由步行、饵笼沉积或三竿共享步。旧数值只是原创试玩参数，不能当作本规格已实现。

首版只开放一个静水水域、少量连通岸线钓点与已配置鱼种，采用局部相对丰度/活跃度近似，不逐条模拟整湖鱼、不设有限总鱼数或全服竞争。河流输运、季节迁移、洪水水位、游泳/船钓和复杂绕障延后；未配置水域不以换场景名开放。P3/P5/P6所需最小几何/查询子集随对应阶段提供，不要求先完成全部P7探索内容。

用户已明确鱼类总范围为中国内陆淡水鱼与海洋鱼类，见[建模交接](ASSET_MODEL_BRIEF.md)。首版静水内容是实施切片，不缩减总范围；海水/河口环境与海钓随对应阶段补齐。候选模型清单不自动变成合法水域鱼种池；准确物种、环境和钓法须配表验证，旧原型ID仍按明确迁移处理。

## 权威数据与单位

| 对象 | 必需数据及边界 |
| --- | --- |
| 水域定义 | 稳定`waterId`、几何/生态/天气规则版本、水面域、岸线、河床高度面/三角网、底质/坡度及障碍区域；采样边界/误差明确 |
| 钓点定义 | 稳定`spotId`、所属水域、可达步行区、合法站立/竿架区域、允许钓法/抛投与回收域；不是一份可重抽鱼群的副本 |
| 世界状态 | 存档分支、世界种子、活动`worldStep`、各子系统随机流、环境阶段、共同版本/检查点；唯一owner持有 |
| 局部生态 | 鱼种/栖息区及聚集状态、相对丰度/活跃度、压力格/区域、最后处理步、规则版本；权重不是可出售/钓取的库存条数 |
| 局部沉积 | 来源会话/释放事件、位置/范围、配方/批次属性、确认释放量、剩余/衰减量、活动到期步及规则版本 |
| 遇鱼输入/输出 | 当前钓组/模式、钩饵或拟饵真实位置/轨迹、工作状态、快照步/版本 → 可用性、候选种权重、危险率及原因，不直接返回鱼或奖励 |

运行几何以世界坐标米/米每秒计算，深度向下为正；持久化位置/长度、资产质量沿用整数毫米/毫克，线径微米、份数整数。活动时间用整数步及声明步长，压力/活跃度使用有界整数刻度或明确量化方式，余数保留到检查点；显示百分比不反写状态。所有算术校验范围/溢出与非有限值。

必要参数缺失、无法采样和几何不一致返回明确不可用，不能补零深度、默认泥底、无限鱼量或保底鱼。目录须区别“明确零权重/零危险率”与`configuration-missing`；不开放的数据不能因种类名称熟悉而采用猜测RF4数值。

## 水面、河床、障碍与移动

权威采样接口`SampleWater(position, geometryVersion)`返回水面高度、河床高度/底质/法向、合法水域与障碍标签；深度由同一垂向采样求得。首版可用平面水面和自制简化河床，但渲染水线/河床必须由同源数据生成或在声明误差内对齐，不能画着深槽却查询成岸地。动画水波不改变权威深度或凭空改变鱼口。

目标有效性分层检查：站立/竿根合法、瞄准射线命中可钓水面、实际飞行路径无阻挡、落水点在本钓法工作域、线量足够且有受支持回收路径。开始与出手前重检，提交后以真实落水为准；“屏幕上蓝色”或落点矩形内不足以证明有效。移动相机/改分辨率不得改变同一世界目标。

底钓使用河床接触/稳定及前导线工作高度；路亚使用逐步轨迹到水面深度和河床净空；浮漂使用已配置漂深与钩饵工作位置。生态查询统一接受它们各自确认的位置，不拿玩家站位或整张地图名代替落点，也不强制三种钓法共用一个深度。P4鱼/线合法域从同一几何源取得。

首版排除无安全回收路径、复杂绕障、不可处理埋陷/挂底的区域，目录/目标预览给出原因。未预见的几何失效按既有钓法故障暂停/收束，不瞬移鱼、补线或把未知碰撞当一次随机断线；环境变更不能暗中删除竿架与物品。

步行只用于探索钓点。首版在无活跃垂钓会话时沿明确可达岸线移动/切换钓点，不能穿水/穿障或传送越过不可达区；蓄力先确认取消，已有出线则先按原流程收束再跨钓点移动。竿架放置和归属沿用三竿合同，不跟着镜头隐形复制。未来允许出线行走时须补动态竿根/可达约束，不能默认已支持。

商店、鱼市、食品、服装及维修始终由任意钓点菜单进入，位置/到建筑距离不是交易资格。搜索/地图/环境线索不更改资产；菜单打开按统一暂停合同冻结世界与全部会话，不能一边暂停界面一边推进鱼口或压力。

## 鱼种池、体型与危险率接口

先取本水域配置的候选鱼种及其合法栖息域，再按当前钩饵/拟饵、钓法、真实水层、底质可见性、活动时段/天气、相对丰度、压力与沉积适配生成权重。每项因子范围、组合/截断顺序必须版本化，所有结果有限且非负；饵不适配或工作状态无效可以明确为零，不用“鱼很多”绕过硬性资格。

相对丰度与愿意问饵分开。首版可用少量有界移动聚集区及配置背景分布表达附近存在量，活跃度/适配表达接触后的倾向；聚集区按世界活动步连续演化，不在每抛、每次开图或切钓点重排。背景丰度必须明确配置，可以为零，不继承旧版隐式下限。没有目标不强行生成一条“新手鱼”。

`EvaluateEncounter`在共同环境快照下返回版本/步号、各候选权重及单位为每模拟秒的危险率`lambda`；因子可以为零，具体概率/上限由自研配表另定。调用为只读，不抽随机数、不推进世界；页面不能自行调用它发鱼。参数完整但鱼池为空/总权重为零时返回合法无目标，危险率为零，不能把配置错误混作暂时无鱼。

搜索沿用咬钩合同：每轮只抽一次开区间随机阈值`-ln(1-u)`，固定步累计`lambda × stepSeconds`，触发后在当前合法权重中选择一次遇鱼。环境变化只改变后续增量，不重新抽当前阈值；阈值触发时目标池已空则不创建鱼，保留/开启新搜索epoch的分支须明确，不能重抽直到有鱼。首版采用结束该轮并记录无目标原因、下一合法搜索步开启新epoch。

浮漂/底钓只有处于各自合法工作阶段才搜索；路亚危险率由实际运动/水层及有限停顿资格驱动，不退回静态落点等待。有效提竿窗口、空提、失饵、追饵失效仍由各钓法处理；生态不因达到阈值直接中鱼、入护或授经验。

鱼种选定后按该种及当前条件配置的体型分布一次生成整数质量，记录上下限、分布/舍入规则、遇鱼ID与条件来源。体型与等待时长不是同一变量，不把等得久自动变成大鱼；缺体型配置不可生成目标。提竿/重载/切竿不重抽，后续环境变化只能按原遇鱼中断规则处理，不偷换鱼种或质量。

生态候选不是有全局ID的逐条鱼，因此两个合法会话可以产生同种同体型但不同`encounterId`的独立目标；不能声称“一条世界鱼被两竿钓走”。真正鱼实例及图鉴/成长只来自原终结事务，鱼护容量和奖励防重沿用库存/成长合同；探索、看热点、压力恢复和迁移不发鱼/经验。

## 活动时钟、天气昼夜与压力

世界只有一个固定活动步时钟，步长、最大追赶子步和丢弃超预算时间策略沿用P4；绘制、声音与只读页不推进。无出线时合法探索/停留仍可推进世界，菜单、观赏、失焦、竖屏及宿主暂停冻结全部环境/鱼口/恢复；离线/休眠和系统时间前拨回拨不计入活动时间，不补算鱼群、体力或收益。

昼夜由活动步映射到版本化游戏日历，不读取电脑时钟改变鱼口；天气采用首版有限状态/有界过渡，声明温度、风、云量与持续步数/转移条件。天气随机流独立且每个计划决策步只取一次，不在每竿/每视图查询时抽取。视觉雾雨/亮度是其表现，关闭特效或调画质不修改生态。

压力首版按局部区域记录有界影响，不代表鱼已被钓光。抛投入水、跑鱼/终结和成功钓获等可施压来源逐项配表，事件ID+通道一次确认；出手前取消/无效旧回调不施压。成功出手造成何时/何处压力按确认落水事件处理，不能在预计落点先扣一次再在实际落点扣一次。空间扩散范围及恢复规则独立于聚集区迁移。

恢复仅使用活动步差按明确规则衰减，不因关闭地图、换钓点、切图或载入把压力置零。首版只有一个水域；以后扩展多水域仍共享`worldStep`，非当前水域可按`lastProcessedStep`延迟推进相同活动步区间，效果须等价于逐步推进，不使用墙钟，也不把切回当新水域。无法确定的延迟演化不得用零压力替代。

普通菜单不提供世界重置/刷天气/重抽热点。改变规则、导入或回退备份不是游戏内恢复鱼口手段，必须使用独立存档分支和明确迁移记录，不能把旧余额与新鱼群收益合并。模拟停留后压力下降是已声明活动时间的效果，不额外发任何奖励。

## 局部沉积与三竿共同一步

首版只接底钓饵笼的有限质量释放，不新增手抛窝料/配方制作界面。沿用饵笼库存一次消费与`loaded = remaining + released + lost`；生态只接收owner确认的释放来源/质量，不再扣料，不把同源沉积各给三根竿一份。沉积剩余量+累计衰减/移除量与确认释放量守恒，回收有余料按底钓规则弃置，不退为未消费库存。

沉积按来源位置、配方/批次适配、有限范围与活动寿命影响已有候选权重/危险率；叠加顺序/上限、零适配和衰减明确配表。不生成新鱼种、不绕过钩饵/拟饵工作资格、不保证鱼口；过量是否抑制未定义前不能猜测。首版不模拟水流输运，未知扩散公式不是无穷范围。

每个固定步先确定共同环境快照，再分别计算各竿运动/搜索/候选事件，按稳定事件次序确认共享业务，归并压力/释放增量后形成下一步世界；当步其他竿不能读到某竿一半更新的沉积。生态随机流与每会话搜索/体型/搏斗随机流分开，稳定键含存档分支、水域/会话、子系统与规则版本；切手持或交换内部数组顺序不额外抽样。

共享鱼护/体力/鱼饵仍由唯一提交层竞争，生态不会先向三竿承诺同一库存或容量。一个视图或一根竿只读取同一步版本；重复事件、旧授权/旧会话/旧世界版本事件不能再次施压或释放。定期检查点必须同时保存源料已释放量、沉积、压力、活动步/余数与相关随机状态，不能分别恢复一半造成物质复制。

## 切图、保存恢复与版本变化

切钓点/水域先检查所有竿，不只检查手持：未出手准备先确认取消，已提交会话先合法收竿/终结并处理待结果，竿架放置按位置合同收束。首版只有一个可进入水域，未配置目标明确拒绝；以后切图也只改变当前位置/场景引用，不重建原水域种子、压力或天气。目标加载失败保留可核对原位置/状态，不悄悄退款、发鱼或丢弃装备。

世界/会话检查点、已确认事件和终结回执同属正式P1恢复边界，结果不确定停止新写入、查询原身份；原回执优先，不先重建“全新世界”再继续钓。重启仅恢复同一已确认环境步，未完成已出手会话仍一次`recovery-retrieve`，保留确认消耗/损失、不发鱼/奖励；不重播落水、整笼释放或未确认压力，也不补记离线衰减。

几何与生态规则版本固定于活动世界；不在半步或活跃会话中热换表。升级须先收束/恢复会话，备份并生成新分支候选，显式映射旧水域/钓点/压力格、环境时间、种子与沉积。规则不兼容或缺映射时保留原数据/阻止激活，不能重置压力/天气、把失效位置传到任意新点或删除超出范围的沉积来掩盖差异。

0.3.1`world/map/spot/journal`按库存迁移合同保留来源及对账；旧公式深度/矩形地图与新几何没有天然一一对应。新增底质、障碍和生态字段必须有明确原创迁移政策，不凭旧记录造完整河床、已发现鱼群或额外渔获。旧鱼售价/图鉴/经验不因新分布重算，个人备份不公开；未实施迁移不能宣称无损恢复已经通过。

## 待实现验收

| 场景 | 必须成立 |
| --- | --- |
| 同目标不同缩放/视角，水岸/障碍边界与无河床数据 | 世界采样/投回路径一致；缺几何明确拒绝，不靠蓝色像素或默认深度放行 |
| 浮漂、底钓、路亚经过不同深度/底质 | 分别按真实工作位置查询，同图不同落点/轨迹有可解释条件，非共用静态等待 |
| 岸线探索、任意钓点交易、任一竿出线时跨点/切图 | 路径与会话门槛正确，无跑商条件、穿水/复制支架或免费收竿 |
| 零率/空池、缺因子/体型表、错误量纲/非有限值 | 合法无鱼与配置错误分开，不保底、不重抽到成功、不生成非法质量 |
| 同种子固定输入与30/60绘制，多视图/交换竿遍历 | 同环境步及事件结果可复查，视图/数组顺序不增加抽样或共享影响 |
| 阈值临界时环境改变、遇鱼后提竿/切手持 | 后续危险量只按新条件累加，目标一旦确定不重抽，不直接发鱼/奖励 |
| 抛投入水/失败/钓获重复事件与休息后返回钓点 | 各来源压力一次，恢复只按活动步，无刷新/切图重置 |
| 三笼重叠、同源重播、衰减/收回与检查点恢复 | 质量守恒、下步共同生效，无三份复制、重复整笼或库存退款 |
| 菜单/观赏/宿主暂停、离线与系统时间回拨 | 时钟/天气/压力/沉积/鱼口冻结，无追赶离线收益或集中失口 |
| 切图失败、旧版本迁移/回退、丢确认后重启 | 原事件可查、全部会话一次恢复收竿，世界来源不清零，不合并分支或补造资产 |

以上为P7及前置几何/数据层的未来验收，未执行测试或改动玩法。首次鱼口辅助、所有参数平衡、玩家操作覆盖与更完整水域规则仍需独立配表/验证；不能据本合同宣称复刻RF4生态或R1整体完成。
